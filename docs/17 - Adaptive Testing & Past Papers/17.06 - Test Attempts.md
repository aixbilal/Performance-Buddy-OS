# Test Attempts

## Purpose

Preserve what the user actually attempted, under which conditions, before feedback or later corrections can alter the evidence.

## Record contract

Stable attempt ID, immutable test version, start/end and active intervals, response per item, response revisions before submission, skipped status, confidence rating if used, assistance/hint events, AI-off status, source visibility, submission time, environment note, and recovery checkpoints.

## Lifecycle

`Draft → Active → Submitted → Scored/Needs Review → Reviewed`, with recoverable `Interrupted` and `Failed to Save` states. Submission freezes the answer snapshot. Later annotations never replace it.

## Rules

Hints and solutions follow test-mode timing. Retakes create new attempts. Unknown or corrupted responses remain explicit. Timer expiry follows configured submission policy and cannot fabricate unanswered responses. Stable IDs make retries idempotent.

## Acceptance criteria

Crashes preserve recoverable work, answers cannot change after submission without an audited correction path, assistance is visible, and every score points to the exact response snapshot.
