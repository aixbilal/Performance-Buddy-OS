# Knowledge Feedback Loop

## Purpose

Publish validated practice evidence and corrections to Knowledge OS, then consume updated confidence and coverage for later testing without circular self-confirmation.

## Flow

Submitted attempt → scored item evidence → reviewed mistakes/corrections → deduplicated learning-evidence events → Knowledge OS confidence recalculation → Phase 14 study-demand update → candidate retest or revision action.

## Rules

Phase 17 emits facts about attempts and reviewed classifications; Knowledge OS owns confidence. Phase 14 owns allocation. A generated question is not learning evidence until attempted. The same response cannot be counted through both score and mistake records as independent demonstrations. Corrections and rescoring invalidate dependent projections by stable provenance.

## Loop control

Rule/model versions, input hashes, and event IDs prevent duplicate feedback. Adaptation uses prior evidence but preserves exploration so a narrow detected weakness does not permanently suppress other topics.

## Acceptance criteria

Every confidence change traces back to attempt evidence, repeated processing is idempotent, corrected records propagate, and no phase writes directly into another owner’s state.
