# Architecture Practice

## Purpose

Build skill in translating requirements and constraints into explainable system boundaries and trade-offs before implementation.

## Practice outputs

Context and requirements, quality attributes, constraints, domain boundaries, data ownership, interfaces, failure modes, security/privacy, deployment assumptions, alternatives, decision rationale, validation plan, and diagrams where useful.

## Rules

Architecture is not the number of technologies used. Start with the simplest design that meets evidence-backed needs. Separate learning experiments from product decisions. Performance Buddy OS framework/database/cloud decisions belong to Phase 44 and approved ADRs, not this practice record. AI-generated designs are proposals requiring critique.

## Exercises

Design a bounded feature, compare two approaches, identify coupling, model failure/recovery, conduct a threat or privacy review, or refactor an existing architecture based on evidence.

## Acceptance criteria

Every design traces requirements to decisions, names rejected alternatives and consequences, respects owner boundaries, and includes a way to validate assumptions.
