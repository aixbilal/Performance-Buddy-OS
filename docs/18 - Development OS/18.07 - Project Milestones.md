# Project Milestones

## Purpose

Define evidence-bearing checkpoints that connect project delivery to specific engineering capabilities.

## Milestone contract

Stable ID, project, desired behavior, linked skills/modules, prerequisites, acceptance criteria, evidence requirements, verification plan, target window, state, definition version, and dependencies. Phase 11 provides generic milestone mechanics.

## Evidence

Useful evidence includes working behavior, tests, code review, accessible UI, security checks, deployment proof, performance measurements, migration/recovery results, documentation, and a user explanation of design trade-offs.

## Rules

A commit, code volume, or screenshot alone does not prove acceptance. Generated code must pass the same criteria. Milestones distinguish implemented, verified, accepted, partial, blocked, and deferred states. Scope changes preserve old acceptance criteria and rationale.

## Acceptance criteria

Dependencies are valid, each milestone can be independently reviewed, project progress is reproducible from evidence, and completing delivery does not automatically claim every linked skill.
