# Skill Evidence

## Purpose

Represent observations that support or challenge claims of software-engineering capability.

## Evidence ladder

Exposure and tutorial completion are weak activity evidence. Guided exercise, independent exercise, implemented feature, verified tests, debugging, explanation, refactoring, code review, architecture trade-off, security/accessibility work, and transfer to a new context provide progressively richer evidence when quality is validated.

## Record contract

Skill/topic, artifact or attempt, observed behavior, correctness/quality, independence/assistance mode, difficulty/context, reviewer or test source, date, freshness, privacy, and provenance.

## Rules

AI-created output is not evidence of user skill by itself. A working feature may still conceal gaps in understanding or testing. Repository activity and time are context, not capability. Conflicting evidence remains visible. Knowledge OS owns confidence calculation.

## Acceptance criteria

Every claim traces to inspectable evidence, independence is explicit, duplicates are controlled, corrections propagate, and skill summaries avoid false precision or ability judgments.
