# Learning Path Model

## Purpose

Specialize the Phase 11 learning-path contract for software engineering and AI-application development.

## Path fields

Target capability, practical outcome, current evidence, modules, prerequisite graph, core/optional classification, learn/practice/build activities, projects, assessments, AI-off checkpoints, review cadence, maintenance mode, workload state, and effective version.

## Module states

`Not Ready`, `Ready`, `Learning`, `Practicing`, `Building`, `Demonstrated`, `Maintaining`, `Paused`, and `Unknown` may be used. State derives from evidence and explicit decisions; it is not advanced by elapsed time.

## Rules

Stable module IDs survive renaming. Semantic changes create versions. Parallel modules are limited by capacity and dependency readiness. A path may enter maintenance during exams without erasing progress. Technology substitutions require mapping of preserved and missing evidence.

## AI boundary

`V1` may draft paths or exercises, but assumptions and sources are reviewed. `V2` may propose adaptation from evidence. AI cannot mark a module demonstrated.

## Acceptance criteria

Paths work offline, expose prerequisites and evidence, support branch/pause/maintenance, and avoid locking project architecture choices before Phase 44 approval.
