# AI-Assisted Coding Policy

## Purpose

Use AI to accelerate learning and engineering while preserving understanding, security, licensing awareness, verification, and human ownership of consequential decisions.

## Permitted uses

Explanation, Socratic guidance, examples, scaffolding, test ideas, code review, debugging hypotheses, documentation drafts, refactoring proposals, and bounded code generation are allowed within permission and learning-mode constraints.

## Required controls

Review generated code; understand consequential paths; run relevant tests; inspect security, privacy, data migration, accessibility, and failure behavior; verify dependencies and APIs from authoritative sources; record material assistance where it affects evidence; and preserve source/license context.

## Prohibited behavior

Do not send secrets or unauthorized private code, accept destructive commands blindly, bypass review because tests pass, claim generated work as independent evidence, or let AI make product architecture decisions outside Phase 44 authority.

## Capability boundary

AI help is `V1` or later and optional. Tool/provider failure leaves work unchanged and manual `CORE` workflows available.

## Acceptance criteria

Assisted changes are attributable, reviewable, tested proportionately, privacy-safe, and compatible with later independent explanation or modification.
