# Development OS Overview

## Purpose

Development OS coordinates technical learning and project delivery while ensuring produced code translates into retained, explainable engineering capability.

## Core model

`Capability Goal → Learning Path → Module → Learn/Practice/Build Activities → Project Milestones → Skill Evidence → Review`

Paths may cover full-stack foundations, frontend, backend, databases, testing, security, deployment, AI/LLM integration, and related engineering topics without locking a specific stack prematurely.

## Interactions

Phase 11 supplies generic path structures; Phase 09 records sessions; Phase 15 links knowledge and evidence; Goals and Analytics observe progress; Phase 08 schedules feasible work; Phase 44 decides project technology through research and ADRs.

## Capability

Manual paths, prerequisite validation, sessions, evidence, and reviews are `CORE`. `V1` may explain, scaffold, review, or diagnose. `V2` may identify patterns. AI availability never controls access to records or independent practice.

## Acceptance criteria

Every active path has outcomes and evidence, project work links to learning objectives, assistance is traceable, and users can continue learning offline without AI.
