# Chained Learning Philosophy

## Purpose

Build technical capability through explicit prerequisite chains and repeated transfer rather than disconnected tutorials or premature tool hopping.

## Philosophy

Each module states what prior concepts it depends on, what new capability it develops, how it will be practiced, where it will be applied, and what evidence allows progression. Chains may branch and converge; they are not required to be one rigid sequence.

## Rules

- A prerequisite is satisfied by evidence, not content-viewing history.
- Earlier concepts recur in later projects and debugging.
- Skipping is allowed when prior evidence already demonstrates capability.
- Unknown readiness triggers a diagnostic exercise, not automatic demotion.
- Framework-specific knowledge should connect to underlying language, web, data, security, and system concepts.
- Path revisions preserve completed evidence and mapping history.

## Anti-patterns

Avoid endless tutorial consumption, copying projects without explanation, learning many frameworks simultaneously without purpose, and treating generated code as acquired skill.

## Acceptance criteria

Every module traces prerequisites and successors, users can challenge or bypass with evidence, and projects require integration of earlier learning rather than isolated repetition.
