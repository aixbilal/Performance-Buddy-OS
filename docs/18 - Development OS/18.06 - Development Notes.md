# Development Notes

## Purpose

Capture technical understanding, decisions, debugging discoveries, commands, patterns, questions, and project context without creating an ungoverned duplicate source of truth.

## Note types

Concept note, implementation note, debugging log, architecture exploration, decision rationale, code-review note, security finding, experiment result, and retrospective may be linked to modules, projects, sessions, and Knowledge entities.

## Rules

Raw session notes require explicit promotion to durable Knowledge references. Architecture decisions for Performance Buddy OS must move to the appropriate Phase 44/ADR owner. Secrets, tokens, private keys, personal data, and unsafe raw logs are prohibited. Code snippets record language, source, license where relevant, and context.

## AI assistance

AI summaries and extracted tasks are labeled derived drafts, preserve backlinks, and require approval. They do not overwrite raw notes or prove understanding.

## Acceptance criteria

Notes remain searchable and source-linked, decisions reach their correct owner, sensitive data is excluded, and broken external references remain visible rather than silently replaced.
