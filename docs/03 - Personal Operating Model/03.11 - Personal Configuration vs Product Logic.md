# Personal Configuration vs Product Logic

## Purpose

Separate changeable user preferences and records from reusable deterministic rules, official policy, and product invariants.

## Categories

| Category | Examples | Authority |
|---|---|---|
| Product invariant | Human approval for meaningful AI writes; offline CORE | Approved product/Phase 00–02 |
| Domain rule | Completion semantics, plan validation | Owning domain/rules phase |
| Official external rule | Curriculum, grading policy, prerequisites | Applicable official source |
| Personal configuration | Sleep window, priority weights, language, routine schedule | `USER_CONFIRMED` |
| Personal record | Marks, sessions, completion, reflections | `IMPORTED_RECORD` or user entry |
| Derived result | CGPA, trend, risk signal | Versioned rule plus inputs |
| AI interpretation | Suggested priority or pattern | Non-authoritative proposal |

## Design rules

Personal values must not be hard-coded as universal defaults. Defaults are editable, labeled, and never overwrite existing configuration silently. Official rules are versioned by program/date and cannot be changed through ordinary preferences. Product invariants require an approved decision to revise.

## Configuration lifecycle

Record source, effective date, prior value where consequential, validation, and user approval. Temporary modes—examinations, recovery, travel, maintenance—override scheduling behavior without rewriting long-term goals.

## AI boundary

AI may infer a possible preference only as a proposal. It cannot convert observed behavior into a personal value, expose private configuration without permission, or change protected boundaries silently.

## Portability

Configuration and records should be exportable independently of implementation technology. Later multi-user support must not be anticipated by turning one user’s values into tenant-wide rules.

## Acceptance criteria

Every behavior can identify whether it came from invariant, official rule, personal setting, record, derivation, or inference; conflicts are visible; and changing configuration does not corrupt historical interpretation.
