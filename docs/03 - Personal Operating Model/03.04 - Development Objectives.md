# Development Objectives

## Purpose

Define software-development and AI-engineering growth direction while preserving independent understanding.

## User-confirmed direction

The user aims to become capable in full-stack software engineering and modern AI application engineering, including LLM integration, while remaining able to reason, debug, design, and implement without blind dependence on AI-generated code.

## Operating objectives

- Follow chained learning paths with prerequisites and visible milestones.
- Use a learn → practice → build → explain → review cycle.
- Produce projects that demonstrate real architecture and engineering judgment.
- Practice debugging, testing, data design, security, accessibility, and performance.
- Maintain development notes and evidence of skill, not course completion alone.
- Schedule deliberate AI-off exercises and human learning checkpoints.
- Balance development with university risk and protected recovery.

## Evidence

Useful evidence includes working features, tests, code review, debugging records, architecture explanations, refactoring, independent exercises, and the ability to modify prior work. Code volume, tutorial hours, or AI-produced output alone are weak evidence.

## AI-assisted boundary

AI may research, explain, scaffold, review, and help diagnose. The user should understand consequential code paths and decisions. When an AI suggestion is accepted, normal testing, security, and architecture rules still apply.

## Scope and ownership

Phase 18 owns the Development OS. Phase 44 owns technology research and ADRs. This document defines personal direction, not a locked framework or programming stack; all such selections remain `RESEARCH REQUIRED` until approved.
