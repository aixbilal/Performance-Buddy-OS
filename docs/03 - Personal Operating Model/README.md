# Phase 03 — Personal Operating Model

## Purpose

Define how the founding user intends to balance major life domains and translate personal direction into configurable product behavior.

## Phase responsibility

Phase 03 is the authoritative bridge between the general product foundation and the founding user’s operating preferences. It records philosophy, priorities, objectives, safety boundaries, and the distinction between configuration and universal logic. Detailed domain behavior remains with its later owning phase.

## Personal direction

The operating model supports sustained improvement across academics, software development and AI engineering, independent study, fitness and endurance, sleep and recovery, spiritual/personal routines, practical language learning, and secondary skills. These directions are `USER_CONFIRMED`; exact targets and schedules remain configurable unless explicitly approved elsewhere.

## Governing loop

```text
GOAL → SYSTEM → ACTION → RESULT → EVIDENCE → REVIEW → ADJUSTMENT
```

Plans are living allocations, not moral commitments. Evidence changes the next plan. Protected constraints and fixed commitments are validated before optional work is scheduled.

## Documents

- `03.01–03.02`: philosophy and contextual priority model.
- `03.03–03.08`: domain objectives and secondary-skill strategy.
- `03.09–03.10`: consistency and independent study.
- `03.11`: configuration-versus-product boundary.

## Capability boundary

CORE stores preferences, constraints, objectives, evidence, and deterministic priority inputs. Later AI may explain or propose adjustments, but may not invent personal values, override protected constraints, or commit meaningful changes without approval.

## Acceptance criteria

The model is usable offline, personal without becoming hard-coded, flexible under examination/recovery pressure, and explicit about which statements are personal configuration rather than universal advice.
