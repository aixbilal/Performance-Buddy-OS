# Desktop Performance Budgets

## Budget areas

Desktop budgets cover process launch, first usable local screen, database readiness, route transition, input response, command palette/search opening, quick capture save, session controls, large tables/charts, window restore, notification/tray action, background refresh, memory steady state, and shutdown/checkpoint.

## Measurement

Separate cold and warm start, fresh and migrated stores, AI/cloud enabled and disabled, minimum and representative hardware, display scale, reduced motion, large text, typical and large datasets, and optional worker concurrency. Measure p50/p95/p99 or an approved equivalent plus failure and cancellation rates.

The first usable screen means local state is trustworthy and required migrations/keys are resolved—not merely that a window is painted. UI animation cannot mask blocked input. Background indexing, sync, backup, or local AI yields to interactive CORE work.

Framework and package evaluations use the same scenarios to avoid incomparable claims.

`RESEARCH REQUIRED`: approve numeric desktop budgets after Phase 35 framework prototypes.

## Acceptance criteria

- Budget tests run on every supported desktop platform and architecture.
- Long sessions and repeated navigation show no unbounded growth.
- Optional worker pressure cannot violate CORE response or data-integrity gates.
