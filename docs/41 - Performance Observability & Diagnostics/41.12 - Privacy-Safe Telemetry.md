# Privacy-Safe Telemetry

## Default and consent

Remote telemetry is off by default unless a later approved policy establishes a narrower lawful default. Enabling it explains purpose, fields/categories, destination/provider, region where known, retention, aggregation, access, deletion, and local alternative. Consent is revocable.

## Data minimization

Use allowlisted event schemas with coarse device/app versions, feature/error codes, durations and resource buckets, and randomized or rotating identifiers where correlation is necessary. Do not send user content, credentials, raw paths/queries/prompts, marks, money/routine details, source filenames, persistent cross-purpose identifiers, or local-only/never-AI derivatives.

Telemetry is not required for CORE, cannot block UI, and queues only approved minimized payloads with expiry and revalidated consent. Sampling, aggregation, retention, access, deletion, and schema changes are versioned and auditable. Unknown fields are rejected.

Local preview shows what will be sent. Provider contracts cannot expand product permission.

## Acceptance criteria

- Network tests match the disclosed allowlist exactly.
- Revocation stops queued/new telemetry and triggers eligible deletion.
- Product quality remains diagnosable locally when telemetry is disabled.
