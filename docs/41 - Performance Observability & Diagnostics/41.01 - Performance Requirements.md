# Performance Requirements

## Requirement form

Every performance requirement states user journey or operation, start/end markers, cold/warm state, dataset tier, concurrency, network state, supported hardware/OS, accessibility settings, percentile, maximum or target, measurement tool, and failure disposition.

## Coverage

Measure startup and readiness, input and navigation, durable command commits, Today and dashboards, database queries/migrations, search/indexing, import/export, backup/restore, timers/jobs, sync, local and cloud AI, memory/CPU/GPU/disk/network/battery, and package/update cost.

Record distributions and tail latency rather than averages alone. Empty, typical, large, pathological, degraded, and long-running states are distinct. A visually fast action that has not committed durably is not successful performance.

CORE interaction remains responsive during optional work. Work may degrade with an honest scoped state, but protected correctness, integrity, security, and accessibility requirements remain unchanged.

`RESEARCH REQUIRED`: approve minimum/representative hardware, dataset tiers, supported platforms, and numeric budgets.

## Acceptance criteria

- Each approved budget maps to reproducible Phase 40 tests.
- Measurements identify artifact, environment, data, and configuration versions.
- Breaches are visible and cannot be averaged away.
