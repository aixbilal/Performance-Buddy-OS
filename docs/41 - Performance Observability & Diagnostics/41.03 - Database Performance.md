# Database Performance

## Scope

Measure open/unlock, integrity checks, migrations, transactional commands, common queries, analytics scans, pagination, joins/graphs, import, backup snapshot, restore validation, compaction, and concurrent-reader/safe-writer behavior.

## Method

Use schema-versioned realistic datasets with empty, typical, large, and pathological distributions. Record query plans, index usage, rows examined/returned, lock wait, transaction duration, cache state, disk I/O, database size, and tail latency without logging row content.

Performance work cannot weaken constraints, foreign keys, revision/audit atomicity, encryption, provenance, or deterministic ordering. Avoid N+1 access, unbounded reads, UI-thread database work, and indexes that leak restricted projections. Migrations expose progress and have storage/time preflight.

Slow-query diagnostics use query/template IDs and safe cardinalities rather than SQL parameters. Changes to schema, query, ORM/driver, encryption, or engine rerun baselines.

## Acceptance criteria

- Critical command and query budgets pass on minimum hardware.
- Load, lock, disk-full, encryption, and migration tests preserve integrity.
- Query-plan regressions and unbounded result paths are release-visible.
