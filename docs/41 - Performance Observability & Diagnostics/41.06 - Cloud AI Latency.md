# Cloud AI Latency

## Measurement stages

Cloud AI latency separates queue wait, authorization/consent, context build, retrieval, upload, provider connection, time to first token/output, inference, tool loops, retries, download, structure validation, deterministic validation, approval wait, and commit. Human approval time is reported separately.

## Dimensions

Record provider/model/adapter/region, request class, minimized payload size bucket, context/output units, tools, streaming, rate-limit state, network profile, attempt count, finish reason, and cost. Do not record raw prompts, responses, tool payloads, credentials, or sensitive identifiers.

Timeout, cancellation, retry, rate limits, partial streams, provider outage, and fallback are tested. Remote failure never fabricates completion or silently switches provider/location. A local/manual path remains where the feature contract permits.

Latency targets are application- and consequence-specific; tutoring, command interpretation, scheduled analysis, and deep reasoning need different budgets. Quality and safety gates precede speed optimization.

`RESEARCH REQUIRED`: approve provider-specific targets after selection and representative network testing.

## Acceptance criteria

- Traces attribute latency without exposing content.
- Bounded retries cannot duplicate tools, proposals, or commits.
- Provider/model switching triggers consent, quality, cost, and latency reevaluation.
