# Search Performance

## Scope

Measure global and knowledge search query latency, first result, complete result set, ranking, highlighting, permission filtering, initial index build, incremental update, compaction, rebuild, and memory/storage use.

## Dataset dimensions

Use permitted corpora across small/typical/large vaults, long files, many headings/tags/links, Unicode and German/Italian text, common/rare terms, filters, renamed/deleted files, cold/warm caches, corrupt index recovery, and concurrent file change.

Performance is evaluated with retrieval quality and permission safety. A faster result that omits required matches, leaks restricted snippets, uses stale deleted data, or cannot cite source location fails. Lexical CORE works offline; embeddings are measured separately by model/index generation.

Instrumentation records query class, index generation, corpus size buckets, candidate/result counts, stages, and durations—not raw query or snippets by default. User query logging is local, minimized, optional, and retention-scoped.

## Acceptance criteria

- Search budgets pass with authorization filters enabled.
- Incremental update and rebuild never modify source files.
- Index loss or corruption recovers without blocking canonical knowledge data.
