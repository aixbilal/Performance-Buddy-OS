# Performance Regression Policy

## Baselines

Maintain versioned baselines by operation, artifact, platform, hardware tier, dataset tier, configuration, network state, and measurement tool. Compare distributions and approved percentiles with statistical and practical significance; do not rely on a single noisy run.

## Gate

Regression checks run for relevant pull requests/builds, release candidates, dependency/framework/database/model changes, schema migrations, and supported platform updates. Correctness and privacy failures take precedence over apparent speed gains.

A breach records metric, baseline/current evidence, reproduction environment, affected users/capabilities, suspected cause, owner, severity, remediation, and rollback. It blocks release when an approved budget or resource ceiling is exceeded. Exceptions require rationale, scope, compensating action, expiry, and approval; they cannot roll forward automatically.

Flaky benchmarks are fixed or excluded from gating with visible status; they never count as passes. Intentional budget changes require requirement review and cannot be achieved by weakening dataset, percentile, validation, encryption, or accessibility.

## Acceptance criteria

- Baselines are reproducible and tied to immutable artifacts.
- Reports separate improvement, neutral, regression, noise, and invalid run.
- Escaped regressions create tests and update budgets or architecture evidence.
