# Local Logging

## Purpose

Local logs explain operations and failures with minimum data. They are not a history of personal activity and are not uploaded automatically.

## Schema

Prefer event type/version, occurred time, severity, component, build, correlation ID, opaque entity/operation reference, action/result, duration, bounded reason code, retry count, and redacted environment buckets.

Never log credentials, secrets, keys, full prompts/responses, notes/reflections, marks, money detail, raw paths, search queries/snippets, media, provider payloads, database rows, or sensitive notification text. Normalize nested errors instead of serializing them wholesale.

Logs are structured, size-bounded, rotated, access-restricted, retention-scoped, and integrity-protected where needed. Debug mode is time-limited and does not broaden fields or enable upload silently. Disk-full behavior drops optional diagnostics safely rather than domain data.

Support bundles provide an exact redacted preview and require consent.

## Acceptance criteria

- Seeded secrets and sensitive values produce zero prohibited log exposure.
- Rotation, malformed input, crash, and low-disk tests pass.
- Disabling or deleting logs does not affect canonical records.
