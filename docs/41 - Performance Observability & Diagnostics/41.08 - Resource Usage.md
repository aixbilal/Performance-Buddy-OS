# Resource Usage

## Resources

Observe memory, CPU, GPU/accelerator, disk space and I/O, file handles, threads/processes, network, battery, thermal state, database/index/model/cache sizes, queue depth, and background wake frequency.

## Policy

Define soft and hard limits by component and supported hardware tier. CORE retains reserve capacity. Optional AI, indexing, sync, backup, animation, and analytics throttle, pause, spill safely, unload, or cancel according to priority and user settings.

Use lifecycle ownership for every process, task, subscription, watcher, cache, model, and handle. Restart, sleep/resume, cancellation, crash, provider failure, and repeated navigation must release or reacquire resources safely. Disk preflight protects migrations, imports, models, backups, and updates.

Device details and usage metrics remain local unless the user enables minimized diagnostic sharing. Resource pressure cannot cause privacy downgrades, partial commits, skipped validation, or destructive cache cleanup of canonical data.

## Acceptance criteria

- Stress/soak tests detect leaks and unbounded queues/caches/wakes.
- Low-resource handling preserves canonical integrity and usable recovery.
- Users can inspect and control material optional resource consumers.
