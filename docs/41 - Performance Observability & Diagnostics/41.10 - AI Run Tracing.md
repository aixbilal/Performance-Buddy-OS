# AI Run Tracing

## Trace model

Trace the Phase 24 lifecycle using run/correlation ID, application/capability, state transitions, guards, provider/model/adapter versions, prompt/schema/tool/policy/retrieval versions, context category/size manifest, tool names and result states, validation outcomes, approval status, timing stages, usage/cost, finish reason, and cleanup.

## Privacy boundary

Traces store references, categories, counts, hashes, and reason codes—not raw prompts, responses, retrieved snippets, tool payloads, filenames, secrets, marks, money details, or private routines. Data zones and retention apply to trace metadata and its correlations.

Tracing proves sequence, not factual truth. It links to separately authorized provenance and audit records. Retries and specialists share causation while retaining distinct run IDs. Cancellation prevents later commit; changed permissions/source revisions are visible as revalidation.

Local traces are default. Remote observability requires explicit disclosure, minimization, provider permission, and redaction at the earliest boundary.

## Acceptance criteria

- Every transition has actor, guard, time, and allowed successor.
- A trace explains latency and failure without reconstructing private content.
- Retry, tool, approval, and commit lineage detects duplicate or skipped stages.
