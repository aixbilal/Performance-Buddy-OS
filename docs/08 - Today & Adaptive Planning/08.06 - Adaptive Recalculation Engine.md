# Adaptive Recalculation Engine

## Purpose

Define deterministic triggers, constraints, outputs, and safety rules for recalculating a day.

## Engine role

The CORE engine evaluates the confirmed plan against changed inputs and produces validation findings plus candidate adjustments. It is deterministic for a given data/rule version. It does not autonomously commit a new plan.

## Triggers

New/changed commitment, deadline, completion evidence, session duration, constraint, mode, availability, prerequisite state, user priority, or manual “recalculate” request. Background detection may mark a plan stale but should not repeatedly interrupt.

## Pipeline

1. Snapshot current plan and authoritative inputs.
2. Validate fixed/protected constraints.
3. Recompute remaining windows and demand.
4. Preserve completed/active/pinned items.
5. Rank eligible changes under mode/priority rules.
6. Produce conflict list and candidate plans.
7. Explain differences and require confirmation as appropriate.

## Outputs

No-change valid, conflict requiring user decision, suggested minimal repair, or infeasible day. Each output includes reason codes, affected items, trade-offs, and rule version.

## Safety

The engine cannot invent duration, policy, or recovery facts. Missing critical input blocks or lowers confidence. It cannot move fixed commitments, violate protected sleep, or turn maintenance into full completion.

## AI relationship

AI may generate alternatives or narrative explanation; CORE engine validates every candidate. AI is not the recalculation engine.

## Acceptance criteria

Rule tests are reproducible, candidate changes are minimal and explainable, and no recalculation mutates the plan without the correct user-control path.
