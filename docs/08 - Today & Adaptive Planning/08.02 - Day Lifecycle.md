# Day Lifecycle

## Purpose

Define stable day states, transitions, and recovery behavior.

## States

| State | Meaning |
|---|---|
| Unplanned | Date exists but no confirmed plan |
| Draft planning | Candidate plan is being assembled |
| Planned | Validated plan confirmed |
| Active | Day execution/capture has started |
| Reconciling | New evidence or changes require review |
| Closing | Outcomes and carry-forward decisions are reviewed |
| Closed | Day record finalized for normal editing |
| Reopened | Explicit correction after closure |

State describes workflow, not personal success.

## Transition rules

A plan can be confirmed only after constraint validation. Execution may begin without a complete plan; unplanned actions are legitimate records. Reconciliation can occur repeatedly. Closure never converts unfinished items automatically. Reopening records who/why and preserves the prior closure snapshot.

## Date and time

The day uses configured local time zone and day boundary. Travel/time-zone changes preserve recorded instants and original local context. Midnight does not silently terminate active sessions or discard drafts.

## Recovery

Interrupted planning/closure restores a local draft. Duplicate retries are idempotent. If the application detects an active prior-day session or unclosed day, it offers explicit resolution.

## Acceptance criteria

All transitions are testable, invalid transitions explain the required action, historical snapshots remain traceable, and crash/restart does not produce false completion.
