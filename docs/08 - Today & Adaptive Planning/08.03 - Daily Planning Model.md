# Daily Planning Model

## Purpose

Define the inputs, outputs, validation, and confirmation contract for a daily plan.

## Inputs

Date/time context, selected mode, fixed commitments, protected constraints, available windows, due/overdue actions, goal/system relationships, domain demand, user priorities, recent evidence, estimated duration/load, and carry-forward candidates.

## Output

A plan contains versioned plan items, order or time window, estimate, flexibility, source/goal references, validation state, reason codes, and current lifecycle. The plan is a feasible intention, not a guarantee.

## Planning stages

1. Load authoritative commitments and configuration.
2. Reserve protected/fixed windows.
3. Build eligible candidate actions.
4. Apply mode, priority, dependency, and feasibility rules.
5. Detect conflicts, overload, missing estimates, and unsafe combinations.
6. Present a draft with reasons and alternatives.
7. User edits/confirms; CORE revalidates.

## User control

Manual planning remains available. The user can pin, move, reduce, defer, split, or add work subject to validation. Overrides record reason and do not silently weaken future rules.

## Boundaries

Planning references domain requirements but does not recalculate grades, diagnose recovery, or redefine learning paths. Exact scoring formulas remain open until Phase 23/14 rules are approved.

## Acceptance criteria

Plans are reproducible from recorded inputs/rule versions, feasible under constraints, editable, explainable, and useful without AI or cloud.
