# Schedule Constraints

## Purpose

Define temporal, capacity, dependency, and safety constraints used to validate daily plans.

## Constraint classes

- Protected: configured sleep/recovery and safety boundaries.
- Fixed-time: classes, examinations, appointments, prayer windows where configured, deadlines/events.
- Availability: start/end, travel/transition, device/location needs.
- Capacity: maximum planned load, buffers, breaks, recovery needs.
- Dependency: prerequisite action/evidence/material before work can start.
- Mutual exclusion: overlapping sessions or incompatible activities.
- Preference: preferred time/location, soft rather than mandatory.

## Strength

Constraints are hard, soft, or informational. Hard violations block confirmation unless an explicit approved exception policy exists. Soft violations warn and offer alternatives. Informational constraints explain context without blocking.

## Provenance

Each constraint records owner, source class, effective dates, recurrence, time zone, priority/strength, and exception behavior. Official commitments and user preferences remain distinct.

## Conflict handling

The validator identifies conflicting items, affected window, source/strength, and repair options. It never silently moves fixed commitments. If no feasible schedule exists, the plan remains explicitly infeasible until the user changes scope or constraint.

## Acceptance criteria

Boundary, recurrence, daylight/time-zone, overlap, buffer, dependency, and exception cases are tested; conflicts are understandable and recoverable.
