# Plan vs Reality Reconciliation

## Purpose

Define how actual events update understanding without falsifying the original plan.

## Inputs

Plan versions, sessions, tracker states, university exposure, marks/deadlines, unplanned actions, interruptions, cancellations, recovery/context changes, and user corrections.

## Reconciliation outcomes

| Reality | Possible outcome |
|---|---|
| Completed as planned | Link evidence and close item |
| Partial | Record achieved scope and remaining work |
| Completed elsewhere | Link external/domain evidence; avoid duplicate work |
| Not started | Defer, skip, excuse, or retain |
| Took longer/shorter | Update remaining capacity, not history |
| Unplanned work | Record and assess impact |
| Commitment changed | Revise windows and conflicts |

## Rules

Reconciliation never backfills evidence automatically or calls missing records failure. It distinguishes changed plan from changed result. Domain evidence determines whether a requirement is satisfied; time alone may be insufficient.

## Workflow

Detect candidate discrepancy, show source/evidence, ask only needed questions, determine remaining demand, recalculate feasibility, present minimal changes, and confirm consequential revision.

## Acceptance criteria

Original intention, actual outcome, evidence, and resulting adjustment are separately inspectable; repeated reconciliation is idempotent and cannot double-count work.
