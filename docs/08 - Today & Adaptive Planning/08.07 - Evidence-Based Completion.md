# Evidence-Based Completion

## Purpose

Define completion as a domain-aware claim supported by an explicit state and proportionate evidence.

## Principle

Completion means the defined requirement was satisfied, not merely that time passed or a timer ended. Evidence requirements vary by action type and consequence.

## Evidence levels

- User attestation for simple routine or low-risk action.
- Session outcome/notes for focused work.
- Artifact reference for assignment, code, reading notes, or project output.
- Assessment/test result for knowledge evidence.
- Domain record for marks, workout, prayer check, expense, or language practice.
- External-source reference where completion occurred outside the application.

## States

Complete, partial, deferred, skipped, excused, rest, maintenance, not applicable, and unknown. Owner domains determine which states apply.

## Rules

Automatic completion is allowed only when an authoritative deterministic event proves it. A timer cannot automatically prove learning. Multiple evidence items must not double-count one requirement. Corrections preserve prior state and reason.

## AI boundary

AI may summarize evidence or propose a state, but user/domain validation confirms it. AI-generated content is not evidence that the user performed the work.

## Privacy

Evidence should be proportionate; do not require sensitive content when a reference or attestation suffices.

## Acceptance criteria

Each completed plan item exposes state, evidence source/type, timestamp, actor, and domain rule; missing evidence is not silently fabricated.
