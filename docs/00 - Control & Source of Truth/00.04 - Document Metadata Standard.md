# Document Metadata Standard

## Purpose

Specify consistent machine-readable and human-readable metadata for document identity, lifecycle, ownership, and traceability.
## Required frontmatter

```yaml
---
title: "Exact document title"
document_id: "00.04"
phase: "00 - Control & Source of Truth"
status: "DRAFT"
baseline: "v1.0"
capability: "CORE"
owner: "Named role or owner document"
last_updated: "YYYY-MM-DD"
---
```

`README.md` files use a stable phase identifier such as `P00-README`. Multiple capability labels are written as a YAML list when necessary. Optional fields include `source_class`, `decision_ids`, `supersedes`, `superseded_by`, and `review_due`.

## Controlled status values

`DRAFT`, `IN REVIEW`, `APPROVED`, `APPROVED BASELINE`, `FROZEN`, `SUPERSEDED`, and `ARCHIVED`. `OPEN`, `PROVISIONAL`, and `RESEARCH REQUIRED` describe decisions or claims, not the whole document unless explicitly appropriate.

## Rules

- `title` must match the H1.
- `document_id` must match the locked filename number.
- `baseline` identifies the documentation baseline, not a product capability.
- `capability` uses labels from `00.05`. Phase 00 governance documents use `CORE` because their controls apply to the deterministic baseline; a separate non-canonical capability label must not be invented.
- `last_updated` changes on material content changes.
- Status changes require the lifecycle in `00.16`.
- Metadata must not claim approval that has not occurred.

## Validation

Automated checks should verify parseable YAML, required keys, controlled values, title/ID/path agreement, ISO dates, and valid referenced decision IDs.
