# AI Coding Agent Reading Order

## Purpose

Give AI coding agents a mandatory context sequence and operating contract that prevents unauthorized architecture or source-of-truth changes.
## Required reading order

1. Root `PERFORMANCE-BUDDY-OS-BLUEPRINT.md`.
2. Phase 00 README and `00.02`, `00.05`, `00.06`, `00.07`, `00.08`, `00.09`, `00.14`, `00.16`, `00.17`, and `00.18`.
3. The requested phase README and every authoritative document for the task.
4. Relevant data, security, offline-first, testing, roadmap, and agent-guidance documents when they exist.
5. Controlled references from Phase 46, preserving provenance.

## Operating contract

Agents must work only within requested scope, preserve user changes, and never silently modify locked paths or decisions. They must distinguish approved, provisional, and researched information; prefer the simplest sufficient architecture; and keep CORE independent of cloud and LLM availability.

AI output is a proposal. Deterministic rules validate calculations and constraints. Humans approve meaningful writes. Agents must not invent academic policies, expose restricted data, replace Obsidian, create premature multi-user/SaaS architecture, add agent swarms for appearance, or claim FUTURE/V3 capability is complete.

## Before implementation

State affected owners and capability levels; identify open decisions; inspect existing work; and define validation. If a required choice is unresolved, document or escalate it rather than selecting a stack silently.

## Completion report

Report files changed, checks run, problems corrected, and unresolved blockers. Do not advance to another phase automatically. A task is complete only when its artifacts match the blueprint and relevant acceptance criteria.
