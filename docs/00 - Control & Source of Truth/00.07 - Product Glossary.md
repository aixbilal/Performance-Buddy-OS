# Product Glossary

## Purpose

Provide canonical meanings for core product terms so different phases and contributors use the same conceptual language.
## Canonical terms

| Term | Meaning |
|---|---|
| Performance Buddy OS | Private, personal-first, desktop-first, offline-first performance operating system |
| Goal | Desired outcome that supplies direction |
| System | Repeatable method designed to advance a goal |
| Action | Concrete executable unit within a system or plan |
| Plan | Current intended allocation of actions under constraints |
| Living plan | A plan that can be reconciled with evidence and changed conditions |
| Evidence | Traceable observation supporting completion, progress, confidence, or analysis |
| Session | Bounded period of execution with type, timing, outcome, and optional evidence |
| Tracker | Configurable mechanism for recording a state, count, duration, number, milestone, or reflection |
| Protected constraint | Boundary that recommendations must not casually violate, such as essential sleep or fixed commitments |
| Recommendation | Explainable proposal; not an automatic command |
| Approval | Explicit human authorization for a meaningful proposed write or decision |
| Deterministic rule | Predictable, testable logic whose output follows defined inputs and rules |
| Knowledge confidence | Evidence-based estimate of understanding, not time spent alone |
| Maintenance mode | Reduced viable practice during temporary pressure, not failure |
| Obsidian | External knowledge-storage layer integrated by permission; not replaced by this product |
| Source provenance | Record of where information came from and how it was transformed |

## Usage rules

Use these exact concepts unless a later approved owner adds a more specific subtype. Do not use “AI decision” for a recommendation that still needs validation and approval. Do not equate activity, completion, evidence, learning, and performance. Avoid “streak failure” language for excused, rest, or maintenance states.
