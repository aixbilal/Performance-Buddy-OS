# Assumptions Register

## Purpose

Track temporary premises that allow work to continue without disguising uncertainty as approved fact.
## Register rules

Each assumption has an ID, statement, source, confidence, impact, owner, validation action, review trigger/date, status, and affected documents. Status is `ACTIVE`, `VALIDATED`, `INVALIDATED`, or `SUPERSEDED`.

## Active assumptions

| ID | Assumption | Confidence | Validation trigger |
|---|---|---:|---|
| ASM-001 | The initial deployment serves one primary user on a desktop device | High | Product scope revision |
| ASM-002 | Core planning, tracking, sessions, and academic calculations must remain useful without internet | High | CORE acceptance review |
| ASM-003 | Mobile is initially a later capture companion | High | MOBILE phase approval |
| ASM-004 | Cloud synchronization is optional and deferred | High | CLOUD scope approval |
| ASM-005 | German or Italian will be configured as a primary language before language features are implemented | Medium | Personal configuration |
| ASM-006 | Official academic sources will be obtained before policy-specific calculations are finalized | High | Phase 12/13 implementation readiness |

## Not assumptions

Locked principles and approved decisions belong in the Decision Log. Unknown technology selections belong in the Open Questions Register or Phase 44 research, not here.

## Safety rule

If invalidating an assumption could corrupt data, misstate grades, weaken privacy, or materially change scope, block the dependent release until resolved. Low-impact assumptions may remain visible and provisional.
