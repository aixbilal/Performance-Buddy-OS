# Documentation Map

## Purpose

Provide the canonical navigation model for the complete documentation tree and identify where each type of decision belongs.
## Authority

The root `PERFORMANCE-BUDDY-OS-BLUEPRINT.md` is authoritative for the frozen tree. This map explains ownership but cannot rename or relocate anything in that blueprint.

## Navigation rules

Start with the root blueprint, then this phase. Read the owner document for a rule before consuming documents that merely use it. Domain behavior belongs to its domain phase; shared mechanisms belong to the relevant engine or platform phase. Cross-references must point to planned or existing locked paths and must not copy an authoritative rule into a second owner.

## Important ownership examples

- Capability definitions: `00.05`, detailed registry in Phase 02.
- Academic formulas: Phase 13, with deterministic enforcement in Phase 23.
- Language routine: `20.09`, using learning paths from Phase 11.
- Obsidian: external storage contract in Phase 16; it is not replaced by the application.
- Architecture choices: researched and recorded through Phase 44 and the decision process in `00.09`.

## Maintenance

Update this map only after an approved baseline revision. A mismatch with the blueprint is a defect; the blueprint wins until formally revised.
