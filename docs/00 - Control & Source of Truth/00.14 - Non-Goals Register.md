# Non-Goals Register

## Purpose

Protect the project from scope drift by recording capabilities deliberately excluded from the current product or initial release.
## Product non-goals

| ID | Non-goal | Boundary |
|---|---|---|
| NG-001 | Generic public SaaS at initial build | Personal-first single-user product |
| NG-002 | Mandatory account or cloud connection for CORE | Offline-first remains usable locally |
| NG-003 | Full accounting, banking, investment, or financial-advice platform | Money tracking stays lightweight |
| NG-004 | One composite score judging the user's life or finances | Domain evidence remains contextual |
| NG-005 | Autonomous AI control of plans or sensitive records | Human approves meaningful writes |
| NG-006 | LLM-calculated official SGPA/CGPA or policy | Deterministic engines use authoritative rules |
| NG-007 | Replacing Obsidian as the note repository | Integration and control layer only |
| NG-008 | Medical diagnosis or unsafe exercise prescription | Fitness features retain health/safety boundaries |
| NG-009 | Premature microservices, agent swarms, or enterprise infrastructure | Prefer simplest sufficient local architecture |
| NG-010 | Simultaneous delivery of V3, cloud, and mobile in CORE | Capability levels remain staged |

## Interpretation

A non-goal is not necessarily “never.” Items may belong to `FUTURE`, but moving one into committed scope requires an approved decision, roadmap impact analysis, and possibly a baseline revision. Non-goals must not be used to omit required accessibility, security, backup, or data portability.
