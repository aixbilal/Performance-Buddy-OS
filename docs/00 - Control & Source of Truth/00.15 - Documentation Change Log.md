# Documentation Change Log

## Purpose

Record material documentation changes and preserve a reviewable history of baseline and approved-content evolution.
## Entry format

Each entry records date, change ID, baseline/document version, affected paths, type, summary, reason, approver, and related decision. Types are `BASELINE`, `CONTENT`, `CORRECTION`, `CLARIFICATION`, and `SUPERSESSION`.

## Logging rules

Log material semantic changes, status changes, ownership changes, and path/baseline revisions. Pure whitespace or spelling corrections need not receive individual entries unless they alter meaning. Never rewrite old entries; add a corrective entry. A baseline change must link its approval and migration impact.

## Relationship to version control

Repository history records file-level edits; this log records human meaning. Neither replaces the other. If version control is not yet initialized, this log remains required.
