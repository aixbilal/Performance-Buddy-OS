# 30.02 — AI Suggests, Rules Validate, Human Decides

## Responsibility split

AI may interpret, summarize, compare, tutor, draft, detect uncertain patterns, and produce candidate recommendations. CORE/domain rules authenticate, authorize, resolve entities, calculate, verify sources, enforce constraints, classify consequence, and validate feasibility. The user accepts, edits, rejects, defers, or chooses a manual path.

## Action flow

`model proposal → strict schema → source/entity checks → CORE recomputation → Phase 23 validation → before/after preview → fresh approval → owner command → outcome confirmation`

No model or specialist can validate itself, approve an override, or claim a write completed before the command result exists. Validation means feasible under known rules; it does not mean optimal, medically safe, financially advisable, or guaranteed.

## Failure behavior

Invalid, stale, unauthorized, unsupported, ambiguous, or blocked proposals cause no mutation. The system shows the reason and safe alternatives. Editing creates a new proposal version and reruns validation.

## Acceptance criteria

- Architecture tests prove the model has no direct source-of-truth write credential.
- Every committed AI-originated action links to validation and approval records.
- Bypass attempts through chat, tools, APIs, background runs, retry, or specialists fail closed.
