# 30.05 — Per-Domain AI Permissions

## Permission dimensions

Permissions are configured per domain and finer category, AI application/purpose, operation (`read`, `retrieve`, `derive`, `remember`, `propose`), execution location (`LOCAL`/approved `CLOUD`), provider, retention, and expiry.

## Domain defaults

| Domain | Default posture |
|---|---|
| Plans/goals/sessions | Off until feature permission; proposals only for writes |
| Academic records | Task-specific; official facts and marks require source/validation |
| Knowledge/vault | Selected collections/files only; vault boundaries apply |
| Development | Task/path-specific; private repositories excluded unless selected |
| Fitness/recovery | Conservative, health-adjacent, non-diagnostic |
| Routine/spiritual | Private by default; category- and task-specific consent |
| Money | Explicit task permission; no transactions or composite scoring |
| Analytics/cross-domain | Every contributing domain separately authorized |

## Rules

One domain's permission never implies another's. Aggregates and metadata inherit the strictest contributing category. Cross-domain permission is the intersection, not union, of source permissions. Users can inspect, change, revoke, and export settings.

## Acceptance criteria

- Tests prevent direct, aggregate, metadata, inference, memory, and citation leakage.
- Permission changes identify affected features and purge prohibited derivatives.
- Missing permission yields a clear narrower/manual path, not fabricated context.
