# 30.04 — AI Write Permission Levels

## Levels

| Level | AI authority | Examples | Control |
|---|---|---|---|
| `W0_NONE` | No mutation path | Answer, explanation, analysis | Read permission only |
| `W1_DRAFT` | Create isolated untrusted draft | Test/question draft, note draft | No source-of-truth effect |
| `W2_PROPOSE` | Prepare typed change proposal | Move block, edit tracker | CORE validation plus approval |
| `W3_COMMIT_APPROVED` | Owner service commits approved proposal | Approved plan change | Fresh approval, idempotency, audit |
| `W4_EXTERNAL` | Affect external system/person | Send/publish/submit | Explicit high-risk confirmation; only if separately in scope |

## Rules

Models possess at most draft/proposal capabilities; `W3` and `W4` are executed by owner command handlers, never by the model. Each application and tool declares a maximum level. Runtime permission is the intersection of application, user, domain, data-zone, provider, and action policies.

Destructive, bulk, official-record, money, private, permission, and external actions cannot use standing AI approval. Baseline excludes financial transactions.

## Acceptance criteria

- Unauthorized level escalation is impossible even with prompt injection.
- Every tool is correctly classified and contract-tested.
- Downgrading permissions immediately blocks higher-level pending actions.
