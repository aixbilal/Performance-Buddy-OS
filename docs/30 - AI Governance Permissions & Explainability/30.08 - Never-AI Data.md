# 30.08 — Never-AI Data

## Definition

Never-AI data is excluded from all model context, prompts, retrieval results, embeddings, fine-tuning/training flows, AI memory, model-visible tool output, and AI telemetry—local or cloud.

## Mandatory categories

Authentication secrets, passwords, passphrases, API keys/tokens, private encryption/signing keys, recovery codes, session secrets, raw credential stores, and security material that would grant authority are always never-AI. Users may designate any record, field, folder, attachment, or category never-AI. Legal/security review may add mandatory classes.

## Handling

Prevent ingestion at source adapters and indexing. Use opaque references or redacted facts only when a deterministic system operation requires them; models never receive secret values. Derived artifacts that reveal prohibited content inherit never-AI. Detection/quarantine supports accidental secret appearance without logging the secret.

Never-AI does not mean delete the owner record; it restricts AI processing. Classification changes require authorization and cannot weaken mandatory categories.

## Acceptance criteria

- Secret-seeded tests show zero model, embedding, memory, log, checkpoint, or provider exposure.
- Prompt injection and tool output cannot retrieve never-AI values.
- Purge procedures identify and remove accidental derived exposure with incident handling.
