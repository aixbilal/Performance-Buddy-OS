# 30.06 — Local-Only Data

## Definition

Local-only data may be processed by an approved `LOCAL` application on the user's device but must not be sent to a remote model, embedding service, telemetry payload, support log, or cloud-derived cache.

## Classification

Users may mark any eligible domain/category/source local-only. Privacy-sensitive defaults may include selected vaults, detailed routines, language recordings, recovery notes, personal reflections, or financial details, subject to stricter `ASK_EVERY_TIME` or `NEVER_AI` policy.

## Enforcement

Apply classification before context selection and model routing. Derived summaries, embeddings, prompts, citations, filenames, and metadata inherit local-only unless an explicit declassification workflow is approved. Hybrid processing is `CLOUD` if any selected content or derivative leaves the device.

Local execution still requires purpose permission, minimization, secure logs/caches, runtime/model supply-chain review, and cleanup. “Local” is not synonymous with safe or authoritative.

## Acceptance criteria

- Network-denial and egress tests prove local-only content cannot leave device boundaries.
- Remote fallback is blocked rather than automatic.
- Revocation removes local derived artifacts according to retention/recovery policy without harming source records.
