# Future Distribution Options

## Candidate options

Possible future forms include:

1. A private portfolio demonstration using synthetic data.
2. A source-available learning project with documented setup and no hosted service.
3. A packaged local desktop application for individual users.
4. A bring-your-own-provider edition retaining local authority.
5. Optional encrypted sync for one user's devices.
6. A hosted single-user service.
7. A multi-user consumer or institutional product.

Listing an option does not approve, rank, promise, or schedule it. Each step introduces different licensing, privacy, security, update, support, accessibility, compliance, cost, and operational obligations.

## Evaluation method

For a candidate, define the target user and problem; demand evidence that the personal version is useful; compare the smallest distribution form; identify data and permission changes; estimate packaging, signing, update, support, abuse, incident, migration, deletion, and exit costs; and test whether local-only use remains viable.

Phase 44 research and ADRs decide packaging, hosting, identity, licensing, and delivery technologies. Provider prices, platform policies, laws, and store requirements are `RESEARCH REQUIRED` at decision time because they change.

## Promotion gate

An option advances only through Phase 02 promotion and Phase 43 Definition of Ready. A demo, repository publication, waitlist, or positive comment is not sufficient evidence for hosted or multi-user scope.

## Acceptance criteria

- Options remain separately costed and risk-assessed.
- The chosen path is the smallest one supported by evidence.
- Distribution does not imply productization or remote data authority.
- Rejected and deferred options retain rationale and review triggers.
