# Personal-First Boundary

## Definition

Personal-first means Performance Buddy OS is designed and validated for one real owner before serving an abstract market. It prioritizes daily usefulness, local ownership, private data, understandable engineering, and direct evidence over growth assumptions.

## Current invariants

- One user owns the local data and decisions.
- CORE works without an account, subscription, organization, or network.
- Personal configuration does not become universal product logic.
- Reusable domain concepts may be modeled cleanly, but dormant tenancy abstractions are not added “just in case.”
- Distribution pressure cannot weaken protected constraints, deterministic validation, approvals, offline behavior, or data portability.

Personal-first does not justify hard-coded identity, inaccessible UI, undocumented assumptions, or unportable storage. Clean boundaries and stable identifiers are valuable where current requirements need them; speculative enterprise infrastructure is not.

## Boundary-crossing test

A proposal crosses into productization when it introduces other independent users, remote identity, shared resources, cross-user authorization, hosted authority, centralized operations, billing, public support obligations, or market claims. That proposal becomes `FUTURE` and requires an explicit problem, evidence, risk analysis, ownership, Definition of Ready, promotion approval, and likely ADRs.

## Acceptance criteria

- Current engineering decisions can be justified without hypothetical customers.
- Single-user assumptions are explicit rather than hidden.
- Generalization occurs only where it improves current correctness or an approved migration.
- Productization cannot enter CORE through implementation convenience.
