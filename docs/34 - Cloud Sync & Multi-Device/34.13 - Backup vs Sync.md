# Backup vs Sync

## Distinction

Synchronization keeps current state available across devices. Backup preserves recoverable historical state against deletion, corruption, account loss, ransomware, software defects, and operator error. Sync can quickly propagate the very damage a backup must recover from.

| Concern | Sync | Backup |
|---|---|---|
| Primary purpose | Multi-device convergence | Point-in-time recovery |
| Typical direction | Bidirectional | Source to protected snapshot |
| Deletion behavior | Propagates tombstones | Retains according to policy |
| History | Operational revisions | Independent recovery points |
| Availability | Active working service | Isolated recovery path |
| Proof | Convergence tests | Restore drills and integrity checks |

## Backup requirements

Backups require defined scope, encryption, independent credentials where practical, immutable or protected retention, multiple recovery points, integrity verification, documented restore procedures, and scheduled restore drills. Retention and deletion must honor law, policy, and user commitments.

Sync metadata may help rebuild state but does not constitute a backup promise. A provider's replication or availability claim also does not prove user-level recoverability.

## Acceptance criteria

- Product language never calls sync a backup.
- Restore tests recover a known snapshot without depending on live synchronized state.
- Backup retention and cloud-deletion behavior are disclosed separately.
