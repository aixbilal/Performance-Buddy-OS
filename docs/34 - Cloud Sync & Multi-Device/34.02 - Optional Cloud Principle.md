# Optional Cloud Principle

## Contract

Cloud use is informed, explicit, reversible opt-in. A user may begin and continue with local-only operation without creating a cloud account.

## Consent lifecycle

Before enabling sync, the product explains the data categories, destinations, purposes, security model, retention behavior, and consequences of disabling it. Consent is recorded with policy and configuration versions. Material scope expansion requires renewed approval.

The user can pause synchronization, inspect pending work, revoke a device, export synchronized data, disable cloud use, and request cloud deletion. Disabling sync does not silently erase valid local records. Deletion confirmation and provider retention limitations must be disclosed.

## Degraded operation

Expired credentials, provider outages, quotas, or a disabled subscription move cloud work into a visible blocked or retryable state. They do not lock the local application or mislabel unsent changes as synchronized.

## Boundaries

Data classified as local-only, never-cloud, or outside current consent must never enter a sync payload, diagnostic event, or remote backup.

## Acceptance criteria

- Core workflows remain available with cloud disabled.
- Opt-in, pause, resume, export, revocation, and deletion states are explainable.
- Consent checks occur before enqueue and again before transmission.
