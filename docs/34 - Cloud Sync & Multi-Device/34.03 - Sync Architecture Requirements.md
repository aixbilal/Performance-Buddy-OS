# Sync Architecture Requirements

## Required capabilities

The sync architecture must provide:

- immediate durable local commits;
- an idempotent operation or change log with stable identifiers;
- incremental push and pull using durable cursors or checkpoints;
- per-record revisions, causal or logical ordering metadata, and tombstones;
- authentication, scoped authorization, consent enforcement, and device revocation;
- encryption in transit and at rest, with explicit key ownership;
- conflict detection, preservation, resolution, and audit history;
- schema and protocol version negotiation;
- bounded retry, backoff, quota handling, integrity verification, and observability;
- resumable transfer without duplicate domain effects;
- provider abstraction, export, deletion, and migration support.

## Processing boundary

The server may authenticate, authorize, validate envelopes, deduplicate operations, retain ordered changes, and coordinate cursors. Domain invariants remain governed by canonical schemas and deterministic rules, not provider behavior.

## Research gate

`RESEARCH REQUIRED`: select the operation-log protocol, causal ordering mechanism, merge algorithm, hosted components, and performance limits through an approved architecture decision record and failure testing.

## Acceptance criteria

- Every acknowledged operation is durable and replay-safe.
- Interrupted transfers resume without loss or duplicated effects.
- Unsupported schema or protocol versions fail visibly and safely.
