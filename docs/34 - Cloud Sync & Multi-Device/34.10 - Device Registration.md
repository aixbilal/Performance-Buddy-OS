# Device Registration

## Device identity

Each installation receives opaque installation and device identifiers plus cryptographic credentials appropriate to the approved security design. A user-visible device name is descriptive metadata, never proof of identity or authorization.

Registration records include account binding, platform and supported protocol range, enrollment method, key reference, created and last-seen times, status, and capability flags. Collect only the device metadata needed for security and interoperability.

## Lifecycle

Supported states include pending, active, suspended, revoked, and retired. Enrollment requires authenticated approval and is protected against replay. Credential rotation does not change domain identity.

Revocation blocks future synchronization and key use as soon as practical. It does not silently delete valid local data on the revoked device. Remote wipe is not assumed and must never be promised without a separately verified mechanism.

Lost-device guidance includes revocation, credential rotation, session invalidation, risk disclosure, and review of recent synchronization activity.

## Research gate

`RESEARCH REQUIRED`: approve device-key storage, enrollment ceremony, recovery method, attestation needs, and revocation propagation after threat modeling.

## Acceptance criteria

- Device names cannot authorize access.
- Revoked credentials fail closed and create auditable events.
- Users can inspect and revoke registered devices.
