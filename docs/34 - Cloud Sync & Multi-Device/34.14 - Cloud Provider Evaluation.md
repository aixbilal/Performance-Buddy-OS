# Cloud Provider Evaluation

## Evaluation dimensions

Candidate providers are compared using documented evidence for:

- security certifications, breach history, encryption, key controls, and tenant isolation;
- privacy terms, data use, subprocessors, residency, retention, deletion, and export;
- identity, device, authorization, audit, and abuse protections;
- database and object-storage consistency, transactions, change feeds, and conflict support;
- offline SDK behavior, protocol portability, quotas, rate limits, and payload limits;
- availability, durability, incident communication, observability, and support;
- pricing under normal, growth, retry-storm, storage, egress, and backup scenarios;
- schema migration, testing, local development, data portability, and exit cost;
- end-to-end encryption compatibility and server-side feature tradeoffs.

## Decision process

Use a weighted scorecard, proof-of-concept, threat model, failure tests, cost model, privacy review, and exit rehearsal. Marketing claims require primary evidence and contractual confirmation where consequential.

`RESEARCH REQUIRED`: no provider is approved by this baseline. Selection requires an architecture decision record describing assumptions, rejected alternatives, risks, mitigations, and review date.

## Acceptance criteria

- Evaluation includes an explicit no-cloud and self-hosted comparison where feasible.
- A provider outage or replacement does not invalidate canonical domain data.
- The exit plan demonstrates export in a documented, verifiable format.
