# Cloud Philosophy

## Principle

Cloud capability exists to make a local-first product safer to use across devices, not to convert it into a cloud-dependent product. The user must retain useful local operation, data portability, and meaningful control over what leaves a device.

## Design position

- Prefer local execution and immediate local durability.
- Use cloud services for synchronization, continuity, controlled sharing, and optional remote capability.
- Keep business rules and canonical validation consistent across local and cloud paths.
- Minimize uploaded data and preserve its classification, provenance, and permission constraints.
- Avoid provider-specific assumptions in canonical domain models.

Convenience never overrides protected constraints, privacy settings, source authority, or human approval. Cloud availability must not determine whether a local session, tracker update, mark entry, or plan edit succeeds.

## Trust boundary

Remote infrastructure is a separate trust boundary. Authentication, authorization, transport security, storage security, observability, retention, deletion, and incident response must therefore be designed explicitly.

## Acceptance criteria

- Network loss cannot block a supported `CORE` write.
- Cloud state is never treated as inherently more truthful than an authenticated local revision.
- Provider replacement does not require redesigning domain entities.
