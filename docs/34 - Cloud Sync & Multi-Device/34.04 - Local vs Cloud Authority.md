# Local vs Cloud Authority

## Authority model

For a local command, the canonical local store is the immediate authority once deterministic validation and durable commit succeed. The cloud service is authoritative only for its own account, device, access, cursor, and delivery records. It does not automatically outrank local business data.

Official curriculum, institutional policy, and user-entered evidence retain the source authority assigned by Phase 00. Synchronization changes location and availability, not classification or truth status.

## Concurrent authority

When two devices produce valid concurrent revisions, neither is discarded merely because it arrived later. The system detects the divergence, applies only approved deterministic merge rules, or records a conflict for resolution.

Wall-clock last-write-wins is prohibited for meaningful user data because clocks drift and arrival order does not establish intent. Server timestamps may support diagnostics but cannot substitute for causal metadata.

## Validation

Remote changes are revalidated against compatible schemas, permissions, consent, integrity hashes, and protected constraints before local application.

## Acceptance criteria

- Local success never depends on remote acknowledgement.
- Sync transport never upgrades a source's authority.
- Concurrent valid revisions remain recoverable until explicitly resolved.
