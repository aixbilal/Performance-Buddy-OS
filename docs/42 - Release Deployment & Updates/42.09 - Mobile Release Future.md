# Mobile Release Future

## Status

Mobile release is `FUTURE` until Phase 36 framework, secure storage, offline database, sync, notification, support matrix, and threat decisions are approved. This document creates no app-store or delivery commitment.

## Required release design

A promoted mobile pipeline must define platform/OS/device support, signing identities, reproducible builds and provenance, dependency/SBOM scanning, test tracks, staged rollout, store review, privacy declarations, permissions, deep links, background behavior, crash/diagnostic privacy, schema/sync compatibility, local-data backup/export, update support, and emergency withdrawal.

Mobile and desktop versions may advance independently, so protocol/schema capability negotiation and compatibility windows are mandatory. Store delay cannot force cloud or desktop CORE to accept unsafe clients. Revoked releases fail safely without erasing valid local capture.

App uninstall, device migration, account sign-out, lost device, and store-region availability require explicit data behavior and recovery guidance.

`RESEARCH REQUIRED`: framework, stores, signing, CI/CD, rollout, crash service, minimum OS, support cadence, and migration approach.

## Acceptance criteria

- Risk-focused release prototypes pass on every proposed supported platform.
- Store metadata and privacy disclosures match observed network behavior.
- Mobile release cannot become a second semantic source of truth.
