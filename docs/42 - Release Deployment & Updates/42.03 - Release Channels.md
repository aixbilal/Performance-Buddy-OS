# Release Channels

## Channels

The initial channel model is:

| Channel | Purpose | Stability |
|---|---|---|
| `development` | Internal engineering and destructive-test data only | Unstable |
| `preview` | Opt-in validation with known limitations | Pre-release |
| `stable` | General supported release | Release-gated |
| `emergency` | Narrow critical security/data fix | Expedited but signed |

Exact names and availability are `RESEARCH REQUIRED`; channel semantics cannot be repurposed silently.

## Promotion

Artifacts are built once and promoted by immutable digest where practical, rather than rebuilt per channel. Promotion requires channel-specific test, migration, security, performance, and support evidence. Rollout supports pause, staged percentage/cohort, and kill switch without deleting local capability.

Users see current channel, version, support status, risks, and data compatibility. Moving to a less stable channel is explicit; returning does not imply safe downgrade. Preview data must remain portable to a supported path.

## Acceptance criteria

- Channel changes cannot bypass signature or compatibility checks.
- Stable users never receive preview artifacts accidentally.
- Promotion and withdrawal are auditable by artifact digest.
