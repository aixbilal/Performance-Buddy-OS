# Data Compatibility

## Dimensions

Compatibility covers reading/writing prior schemas, record revisions, definitions/rules, events, imports/exports, backups, APIs, sync protocols, AI records, and optional mobile/cloud metadata.

## Rules

Confirmed local records remain readable and attributable. Unknown fields are preserved or ignored only according to a documented contract; unknown required semantics block writes. Older clients cannot overwrite newer fields, resurrect tombstones, or reinterpret rules. Capability negotiation exposes unsupported states without corrupting CORE data.

Published academic policies and calculation rules remain versioned and immutable. Historical results are not silently recalculated. AI recommendation records retain prompt/model/tool/policy provenance sufficient for interpretation even when a provider disappears.

Feature removal requires deprecation notice, inventory, export/migration path, support window, compatibility impact, and approved deletion/retention behavior. Round-trip export tests protect provider/framework exit.

## Acceptance criteria

- Supported old data opens and reproduces meaning after upgrade.
- Mixed-version sync/API tests fail safely or interoperate as declared.
- Compatibility fixtures remain until the documented support boundary ends.
