# Desktop Packaging

## Artifact requirements

Desktop packages target an explicit supported OS/architecture matrix and include application binaries, approved runtimes/sidecars, licenses, migration compatibility, and release notes. Installers do not fetch undeclared executables.

Builds use locked dependencies, isolated reproducible environments, SBOM and provenance generation, vulnerability and malware scanning, checksums, platform signing/notarization where applicable, and protected signing keys. The application and updater verify trusted signatures and channel metadata.

Install, upgrade, repair, uninstall, per-user/per-machine behavior, path handling, shortcuts, deep links, permissions, firewall prompts, and multiple-instance behavior are tested. Uninstall distinguishes application removal from user-data deletion and requires explicit consent for the latter.

Offline installers and local export remain available according to support policy. Packages cannot silently enable cloud, telemetry, or AI, reset privacy settings, or weaken sandboxing.

`RESEARCH REQUIRED`: framework, package formats, signing/notarization services, updater, and support matrix.

## Acceptance criteria

- Tampered, unsigned, wrong-channel, and incompatible packages fail closed.
- Clean install/upgrade/repair/uninstall pass on every supported target.
- Published artifacts match recorded checksums, provenance, and SBOM.
