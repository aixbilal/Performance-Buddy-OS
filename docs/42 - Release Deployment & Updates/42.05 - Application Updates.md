# Application Updates

## Update flow

The updater checks signed metadata over an authenticated channel, validates current channel and compatibility, downloads to isolated storage, verifies size/hash/signature/provenance, performs disk/key/database preflight, displays material changes, and schedules installation at a safe user-controlled point.

Updates are resumable and bandwidth-aware but cannot execute partially verified content. Mandatory security intervention requires explicit policy and still preserves local-data access/recovery where safe. Offline update from a signed package is supported when compatible.

Before installation, active sessions/jobs are checkpointed, a qualifying verified backup is created, and migrations are prepared. Interrupted download or install returns to the known-good application or a clear recovery mode. Update success includes application launch, schema/integrity verification, and health checks—not merely installer exit.

Updates do not alter AI/cloud/telemetry consent, permissions, data zones, or provider choices silently.

`RESEARCH REQUIRED`: update service, metadata format, rollout controls, cadence, and support windows.

## Acceptance criteria

- Tamper, interruption, low disk, revoked signature, and offline tests pass.
- Failed update cannot strand valid local data behind an unusable shell.
- Users can inspect version, channel, progress, and recovery action.
