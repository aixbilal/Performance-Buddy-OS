# Reason Codes

## Purpose

Provide stable machine-readable explanations that UI, logs, tests, analytics, and AI narratives can use without relying on fragile prose.

## Code contract

Stable uppercase identifier, owner, severity, outcome, message key, parameters, affected entities, rule/version, remediation options, privacy classification, and deprecation mapping. Example families include `PERMISSION_*`, `SLEEP_*`, `FIXED_*`, `SCHEDULE_*`, `ACADEMIC_*`, `BUDGET_*`, `EVIDENCE_*`, `RULE_CONFLICT_*`, and `APPROVAL_*`.

## Rules

Codes identify conditions, not blame. Sensitive values are parameters protected from logs and notification previews. Prose localization cannot change semantics. Multiple codes are ordered by consequence and consolidated. Deprecated codes map to successors for history.

## Acceptance criteria

Every block/warning/approval requirement has at least one code, tests assert codes rather than prose, users receive understandable actions, and logs contain no unnecessary private data.
