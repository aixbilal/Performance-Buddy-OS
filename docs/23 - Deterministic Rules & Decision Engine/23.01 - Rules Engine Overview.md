# Rules Engine Overview

## Purpose

Provide one deterministic runtime for applying registered domain rules, validating candidate actions, and returning explainable outcomes.

## Core concepts

Rule definition, rule set, fact snapshot, candidate action, constraint, evaluation context, finding, decision, reason code, override policy, and evaluation trace. Rules reference stable owner-domain concepts rather than duplicating their semantics.

## Evaluation flow

Resolve rule set/version; collect permissioned authoritative facts; validate input schema and freshness; apply protected and hard constraints; apply domain invariants/calculations; evaluate soft rules and ranking; detect conflicts; produce `ALLOW`, `ALLOW_WITH_WARNING`, `REQUIRE_APPROVAL`, `BLOCK`, or `UNRESOLVED`; persist the trace without committing the action.

## Architecture

The engine is local, offline, side-effect-free during evaluation, and separate from repositories that commit approved writes. External time, randomness, locale, and configuration are explicit inputs.

## Acceptance criteria

Rules are independently testable, evaluation is idempotent, failures are contained, traces reproduce outcomes, and optional AI/cloud components are never required.
