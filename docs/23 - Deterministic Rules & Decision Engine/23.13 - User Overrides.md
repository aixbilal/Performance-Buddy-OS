# User Overrides

## Purpose

Allow informed human control where policy permits without turning overrides into invisible rule deletion or unsafe authority escalation.

## Override classes

Soft preference/priority override, temporary schedule exception, evidence/state correction, configuration change, and acknowledged warning. Protected security/permission invariants, official facts, deterministic arithmetic, and non-overridable health/safety boundaries cannot be “overridden” into falsehood.

## Contract

Record actor, target rule/finding, replacement choice, reason (optional unless high consequence), scope, effective/expiry time, impact preview, warnings, previous value, approval time, and reversion path.

## Rules

AI cannot approve an override. An override grants no new data permission unless the permission workflow separately does so. Repeated overrides may generate a review signal but never shame or silently rewrite configuration.

## Acceptance criteria

Override eligibility is rule-defined, expired overrides revert predictably, history remains auditable, and protected constraints reject unauthorized bypass attempts.
