# Rule Priority

## Purpose

Define a stable precedence order for resolving compatible rules and exposing true conflicts without arbitrary “last rule wins” behavior.

## Precedence

1. Security, permission, data-integrity, and urgent safety invariants.
2. Protected sleep/recovery and owner-domain safety boundaries.
3. Applicable official policy and verified hard constraints.
4. Fixed commitments and hard deadlines.
5. Domain lifecycle and calculation invariants.
6. User-approved hard configuration.
7. Soft constraints, priority rules, preferences, and optimization.
8. AI/model proposals and presentation preferences.

## Specificity and authority

Within a level, applicable higher-authority and more-specific owner rules govern; newer versions apply only within their effective scope. Equal-priority contradictory rules produce `CONFLICT/UNRESOLVED`, not silent selection.

## Acceptance criteria

Precedence tests cover security, sleep, official policy, fixed commitments, user configuration, and AI suggestions; every displaced rule appears in the trace with reason.
