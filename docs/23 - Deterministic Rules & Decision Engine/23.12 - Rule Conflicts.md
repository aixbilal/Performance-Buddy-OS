# Rule Conflicts

## Purpose

Detect and resolve contradictory rules or constraints without hiding ambiguity behind precedence or implementation order.

## Conflict classes

Protected/protected, official-source conflict, hard/hard schedule conflict, version/applicability conflict, domain ownership conflict, user configuration conflict, and soft preference competition.

## Resolution

Apply authority and priority only when scopes are comparable and precedence is unambiguous. Otherwise return `CONFLICT/UNRESOLVED` with rule IDs, sources, affected outcome, severity, temporary safe behavior, options, and required decision owner. Preserve both rules until resolution.

## Safe defaults

Block consequential academic calculations on policy conflict; deny access on permission conflict; preserve sleep/safety; avoid money transaction advice; and keep confirmed data unchanged. Soft conflicts may offer ranked alternatives.

## Acceptance criteria

No conflict uses last-write/last-loaded wins, equal-priority ambiguity is visible, resolution creates an auditable decision/version, and safe degraded behavior is tested.
