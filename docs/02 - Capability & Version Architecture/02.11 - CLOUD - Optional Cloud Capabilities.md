# CLOUD — Optional Cloud Capabilities

## Purpose

Define optional remote services while protecting local authority, offline operation, privacy, portability, and graceful degradation.

## Scope

CLOUD may provide encrypted synchronization, remote backup, provider-hosted AI, heavier computation, and future multi-device support. Each service is independently opt-in; enabling one does not imply consent for another.

## Boundaries

CORE works without an account or network. Cloud state does not silently become authoritative. Sync conflicts are explicit and recoverable. Provider processing receives minimized, permission-scoped data. Export and local restore remain available.

## Required contracts

- Authentication/device identity only when needed.
- Encryption and secrets management.
- Data category permissions and revocation.
- Sync/change/conflict semantics.
- Outage, rate-limit, quota, latency, and cost behavior.
- Provider replacement and data deletion/portability.
- Clear separation of backup, sync, and AI processing.

## Status

Provider, hosting, identity, synchronization, and encryption implementations are `RESEARCH REQUIRED`. No named vendor is approved by this phase.

## Failure behavior

Loss of connectivity queues only safe operations, never loses confirmed local work, and exposes pending/conflicted states. Provider failure cannot corrupt CORE records or force AI-generated substitutes.

## Acceptance criteria

Offline tests remain green; opt-in and revocation are understandable; security/recovery tests pass; costs and exposure are visible; and disabling CLOUD preserves local usability and exportability.
