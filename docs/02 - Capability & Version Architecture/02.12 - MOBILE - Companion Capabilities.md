# MOBILE — Companion Capabilities

## Purpose

Define the future mobile companion as a low-friction capture and review surface rather than a replacement for the desktop command center.

## Role

MOBILE supports fast university and daily capture: quick study sessions, lecture logs, marks, assignments/deadlines, routine checks, expenses, tests, notifications, and lightweight review. Desktop remains the primary configuration, analysis, and command-center surface unless a future approved revision changes that strategy.

## Capability relationship

Mobile uses shared domain contracts and may expose selected CORE behavior. `MOBILE` is a surface label, so a feature may be `CORE + MOBILE` or `V1 + MOBILE`. Mobile presentation cannot redefine domain rules or AI authority.

## Offline behavior

Capture must work under intermittent connectivity. Local mobile state records stable IDs, timestamps, provenance, and sync status. Conflicts are not silently overwritten. Sensitive cached data follows device-security and retention rules.

## Scope constraints

The initial mobile direction excludes full desktop parity, complex architecture administration, and mandatory mobile ownership. Framework and sync implementation remain `RESEARCH REQUIRED`.

## Promotion prerequisites

Stable CORE schemas, device identity, conflict rules, encrypted sync or an approved transfer method, mobile threat model, accessible interaction, and recovery tests.

## Acceptance criteria

Capture is quick and reliable offline; synchronization is explainable; permissions are preserved; desktop workflows remain available without mobile; and the companion does not create a second source of truth.
