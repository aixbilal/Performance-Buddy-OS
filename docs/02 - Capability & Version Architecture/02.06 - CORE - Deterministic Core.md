# CORE — Deterministic Core

## Purpose

Define the mandatory offline deterministic foundation and the authority that later capability levels must use rather than replace.

## Definition

CORE is the reliable local product: structured data, explicit rules, predictable workflows, and testable calculations that remain usable without internet, cloud, or any AI model.

## Responsibilities

- Goals, systems, actions, plans, constraints, sessions, trackers, and reviews.
- Academic records, prerequisites, assessment weights, SGPA/CGPA, and projections using authoritative inputs.
- Domain records for knowledge links, development, fitness/recovery, routines, language, and lightweight money.
- Local validation, reason codes, approvals, undo/recovery, backup/export, and provenance.
- Deterministic analytics and plan-versus-reality reconciliation.

## Authority

CORE owns calculations, invariants, permission enforcement, protected constraints, and final validation. AI may explain or propose inputs but cannot substitute for these rules. Unknown academic policy remains blocked/provisional rather than guessed.

## Non-goals

CORE does not include natural-language intelligence merely because a local model might be available. It does not require accounts, remote services, multi-user tenancy, or autonomous replanning.

## Failure requirements

Invalid input produces actionable validation. Crashes or interrupted writes preserve recoverability. Optional integrations fail independently. Local state exposes provenance and migration version.

## Acceptance criteria

Committed workflows pass offline tests; calculations are reproducible; protected constraints cannot be bypassed by recommendations; all meaningful changes are attributable; and the product delivers the Phase 01 loop without AI.
