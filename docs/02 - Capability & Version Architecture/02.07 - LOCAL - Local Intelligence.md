# LOCAL — Local Intelligence

## Purpose

Define privacy-preserving on-device intelligence and its boundary from deterministic CORE and provider-backed assistant features.

## Scope

LOCAL may support command parsing, classification, extraction, lightweight transformation, local knowledge retrieval, and other bounded tasks that can meet reliability and hardware constraints on device.

## Preconditions

- Stable CORE schemas and tool contracts.
- Explicit hardware and latency budgets.
- A tested local runtime/model selection; currently `RESEARCH REQUIRED`.
- Structured-output validation and deterministic fallback.
- Permission-aware access to local data and Obsidian.

## Authority boundary

LOCAL output is model output, not deterministic truth. Extracted dates, marks, tasks, or categories must be reviewed or validated according to consequence. LOCAL never owns SGPA/CGPA math, policy, constraints, or silent meaningful writes.

## Privacy

Local execution reduces remote exposure but does not erase privacy risk. Context should still be minimized, sensitive logs protected, and vault/file permissions honored. Model files and runtimes require supply-chain review.

## Failure and fallback

If confidence, latency, memory, or schema validation is unacceptable, provide manual CORE workflows. Do not make CORE startup depend on loading a model.

## Acceptance criteria

Benchmarks demonstrate acceptable structured reliability on target hardware; outputs are labeled and traceable; failures are contained; and disabling LOCAL leaves all CORE records usable.
