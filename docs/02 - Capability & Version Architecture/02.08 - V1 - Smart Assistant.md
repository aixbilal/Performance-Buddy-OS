# V1 — Smart Assistant

## Purpose

Define reactive AI assistance initiated by the user, with constrained tools, explainable proposals, and approval-gated writes.

## Interaction model

The user asks; V1 assists. Supported directions include natural-language commands, explanations and tutoring, source-grounded search, test generation, and proposals to modify habits, plans, schedules, or records.

## Contract

V1 receives only task-relevant permitted context, invokes registered read/tools, returns structured output where action is possible, and distinguishes answer from proposed write. A proposed write includes target, before/after effect, reason, evidence, validation result, and approval choices.

## Boundaries

- No meaningful write without explicit approval.
- No invented academic policy or deterministic calculation.
- No access to private categories without permission.
- No claim that suggestions are optimal or guaranteed.
- No hidden dependency for CORE workflows.

## Examples

“Explain this topic from my permitted notes” is a read/answer. “Move tonight’s study block” is a proposal validated against fixed commitments and sleep. “Calculate CGPA” invokes CORE tools and explains their output; the LLM does not calculate it itself.

## Failure behavior

Tool or provider failure leaves the user’s data unchanged. Invalid structured output is rejected. Ambiguity affecting consequential changes prompts clarification or offers bounded options.

## Acceptance criteria

Intent and tool tests pass; sources and uncertainty are visible; approval cannot be bypassed; rejected proposals produce no write; and provider unavailability degrades cleanly to CORE.
