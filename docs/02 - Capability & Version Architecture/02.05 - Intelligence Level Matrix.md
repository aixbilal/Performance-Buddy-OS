# Intelligence Level Matrix

## Purpose

Compare intelligence levels by trigger, context, outputs, authority, evaluation, and failure behavior.

## Matrix

| Level | Trigger | Context | Output | Write authority |
|---|---|---|---|---|
| `CORE` | User action or deterministic schedule | Structured local state | Calculations, validation, plans, records | Rule-governed user action |
| `LOCAL` | User/system invocation | Permission-scoped local context | Classification, extraction, retrieval | No independent meaningful writes |
| `V1` | User request | Task-relevant context | Answer, tutoring, generated test, proposal | Approval required |
| `V2` | User/scheduled analysis | Historical evidence windows | Patterns, risks, adaptive proposal | Approval required |
| `V3` | User/approved deep analysis | Cross-domain, long-horizon context | Highest-value-next-action recommendation | Approval required |

## Invariants

Higher intelligence does not gain policy authority. Deterministic calculations and constraints remain CORE. Each output records provenance, capability level, relevant evidence, uncertainty, model/provider/version when applicable, validation result, and approval outcome.

## Degradation

If a model is unavailable or an output fails schema/safety validation, the feature provides a clear unavailable or reduced state. It does not fabricate a deterministic result or silently downgrade a consequential recommendation.

## Evaluation progression

LOCAL emphasizes structured-output reliability and privacy. V1 adds task correctness and approval safety. V2 requires historical usefulness and false-signal analysis. V3 requires cross-domain safety, longitudinal benefit, and protection against overconfident optimization.

## Anti-complexity rule

One well-scoped model call or native sequential workflow is preferred until evidence demonstrates a need for specialist or multi-agent orchestration.
