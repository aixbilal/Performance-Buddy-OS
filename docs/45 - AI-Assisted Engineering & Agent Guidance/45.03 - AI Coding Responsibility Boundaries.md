# AI Coding Responsibility Boundaries

## Permitted assistance

Within granted scope, AI may inspect allowed files, explain code, research authoritative sources, propose designs, implement bounded changes, generate tests, run approved checks, review diffs, and draft documentation. It must label assumptions and separate observations, inferences, proposals, and completed actions.

## Human responsibility

The human owns product scope, source-of-truth approval, architecture decisions, risk acceptance, credential and permission grants, destructive operations, releases, and claims of personal learning. AI never becomes the accountable owner merely because it produced most of a change.

## Hard boundaries

An agent must not:

- invent requirements, academic policy, evidence, test results, citations, or completed actions;
- expose secrets, private data, proprietary material, or restricted files to an unauthorized provider;
- bypass approval, deterministic validation, repository rules, or protected constraints;
- overwrite user work, perform destructive actions, or expand external side effects without authority;
- add dependencies, change schemas, or decide architecture silently;
- weaken tests to make a change pass or conceal warnings and failures;
- present generated work as independent human evidence.

When ambiguity materially changes behavior or risk, the agent performs safe read-only investigation and then escalates the decision. Provider failure leaves the workspace unchanged or recoverable.

## Acceptance criteria

- Every AI-assisted change has bounded authorization and a human-reviewable diff.
- High-impact actions have explicit approval and recovery evidence.
- The handoff identifies assumptions, unverified facts, and incomplete checks.
- Manual CORE work remains possible when AI is unavailable.
