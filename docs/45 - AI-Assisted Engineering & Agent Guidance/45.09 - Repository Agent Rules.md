# Repository Agent Rules

## Instruction discovery

Before work, locate repository-level and directory-scoped agent instruction files. Apply the most specific applicable rule within its scope. Explicit user instructions and higher-authority Performance Buddy OS documents remain controlling; conflicts are reported rather than silently resolved.

## Workspace rules

- Confirm repository root, requested targets, allowed write areas, and current branch/worktree state.
- Inspect existing changes and assume unrecognized changes belong to the user.
- Do not rename, move, delete, or restructure locked documentation or code without explicit approval.
- Never edit read-only references, generated/vendor files, secrets, or external directories unless the task and repository rules expressly authorize it.
- Reuse existing scripts, conventions, components, and contracts when suitable.
- Keep edits focused. Do not mix cleanup, formatting, dependency upgrades, or adjacent features into the requested change.
- Avoid destructive commands. Resolve exact targets and recovery before an authorized destructive operation.

## Validation and reporting

Use project-provided checks first, then focused supplementary checks. Validate filenames, formatting, build/type status, tests, migrations, security/privacy, and documentation as applicable. Inspect the final diff and verify no unintended files changed.

The final report names files changed, commands/checks and outcomes, defects found and fixed, assumptions, and blockers. A partial run, skipped test, warning, or inaccessible target is not reported as a pass.

## Acceptance criteria

- Every change complies with applicable instruction scope and path authority.
- Existing user work and unrelated files remain intact.
- The final diff contains only authorized changes.
- Validation and handoff evidence can be reproduced.
