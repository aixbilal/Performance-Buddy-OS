# Global Search Architecture

## Purpose

Define permission-aware search across domains, external knowledge references, commands, and derived content.

## Search scope

Global search may index permitted goals, actions, plans, sessions, courses, assessments, topics, notes metadata/content where authorized, development paths/projects, fitness activities, routines/languages, money categories/records, reviews, and settings/help.

## Result model

Each result identifies type, title, owning domain, contextual subtitle, provenance/source, match reason, freshness/index status, and canonical route. Grouping and ranking must remain understandable; sensitive snippets may be redacted.

## CORE behavior

Local lexical/filter search works offline. Indexes are rebuildable projections and never the source of truth. Updates are incremental where possible; stale or incomplete index status is visible. Exact implementation technology remains `RESEARCH REQUIRED`.

## Intelligence enhancements

LOCAL may add classification, synonyms, or on-device semantic retrieval. Provider-backed semantic search is optional and permission-scoped. AI-generated answers must cite source results and remain distinguishable from them.

## Privacy and security

Search respects the same data permission zones as direct navigation. Private reflections, spiritual data, financial detail, and restricted vault folders are excluded or protected by explicit rules. Query logs are minimized and local by default.

## Ranking principles

Favor exact/strong matches, current context, user-recency, and task relevance without creating opaque behavioral manipulation. Users can filter by domain, type, date, status, and source.

## Acceptance criteria

Results open canonical entities, permission tests prevent leakage, unavailable indexes degrade gracefully, and disabling AI/cloud preserves useful local search.
