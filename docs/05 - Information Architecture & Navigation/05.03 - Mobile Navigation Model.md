# Mobile Navigation Model

## Purpose

Define a future companion hierarchy optimized for rapid capture and review without claiming desktop parity.

## Status and role

This is `MOBILE` direction, not initial CORE delivery. Mobile is a companion for quick study sessions, lecture logs, marks, assignments, routine checks, expenses, tests, notifications, and lightweight review. Desktop remains the command center.

## Proposed hierarchy

```text
Today
Capture
Review
Search
More
```

Exact tab count and labels remain subject to Phase 36 research and mobile usability testing. The model prioritizes reachable high-frequency tasks rather than reproducing every desktop destination.

## Navigation rules

- Quick capture is available within minimal steps and works offline.
- Deep links preserve domain/entity identity and source context.
- Complex configuration and architecture administration defer to desktop unless proven necessary.
- Sync state, conflicts, and pending uploads are visible and never silently overwritten.
- Sensitive preview content can be hidden on lock screens and notifications.
- Back behavior follows platform expectations while preserving unsaved work.

## Capability relationship

A mobile surface can expose `CORE + MOBILE` workflows or later `V1 + MOBILE` assistance. It cannot redefine formulas, statuses, permissions, or AI approval rules. Unavailable cloud/sync does not prevent local capture where that workflow is committed.

## Acceptance criteria

Frequent capture is fast and accessible, offline records are recoverable, permission boundaries match desktop, and mobile never becomes a second semantic source of truth.
