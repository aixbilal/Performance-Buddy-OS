# Desktop Navigation Model

## Purpose

Define the desktop command-center navigation model for efficient keyboard and large-screen use.

## Model

The desktop shell uses four conceptual layers:

1. **Primary navigation:** stable destinations such as Today, Goals, and domains.
2. **Context header:** current entity, breadcrumbs, capability/source state, and key actions.
3. **Workspace:** task or entity content, with optional supporting panels.
4. **Global utilities:** search, command palette, quick capture, notifications, help, and settings.

The final arrangement—sidebar, top bar, panels, or responsive combinations—belongs to UX/design phases. The conceptual hierarchy is fixed.

## Behavior rules

- Current location is always apparent.
- Back/forward navigation restores context, filters, and safe unsaved-state handling.
- Keyboard users can reach primary destinations, global search, commands, and main content.
- Multiple windows or split views remain `RESEARCH REQUIRED`; no dependency is assumed.
- Entity routes deep-link consistently from Today, search, analytics, and recommendations.
- Destructive or consequential actions are not hidden behind ambiguous icons.

## Large-screen principle

Use available width for useful context, not maximal density. Supporting panels may show plan, evidence, or relationships but must not duplicate the authoritative editor.

## State handling

Offline, sync, background, and AI availability are visible at the relevant scope. Global outage banners are reserved for truly global impact. Local unsaved edits and approval proposals remain explicit.

## Acceptance criteria

Core workflows are reachable without pointer-only interaction, navigation history behaves predictably, and the desktop remains understandable with all AI/cloud features disabled.
