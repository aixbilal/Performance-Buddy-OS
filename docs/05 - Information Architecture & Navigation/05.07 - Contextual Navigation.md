# Contextual Navigation

## Purpose

Preserve task and entity context while users move among related domain records, evidence, analytics, and recommendations.

## Context model

Context includes current route/entity, parent hierarchy, originating workflow, selected time range, filters, mode, and safe return location. It does not silently include permissioned private data in every downstream view.

## Relationship links

Examples include course → topics → notes → test attempts; goal → system → actions → sessions; development path → module → project evidence; workout → load → recovery; routine → entries → review; recommendation → evidence → proposed change.

## Navigation patterns

- Breadcrumbs represent structural parentage, not arbitrary browsing history.
- Back returns to the prior state; “up” returns to the parent concept.
- Related links show relationship type and owner domain.
- Drawers/panels may provide quick inspection, but canonical editing opens the owner route.
- After create/edit, return behavior is predictable and preserves the originating workflow.

## Cross-domain rules

Links do not transfer ownership. Academic metrics open the academic record/formula source; analytics cards open the derived view plus input explanation; AI recommendations open evidence and approval state. Sensitive relationship existence can itself be private and must be permission-filtered.

## Failure states

Deleted/moved external notes, missing entities, stale analytics, and unavailable optional services show repair or alternate routes without fabricating context.

## Acceptance criteria

Users can answer “where am I, how did I get here, what is related, and how do I return?” while permissions and canonical ownership remain intact.
