# Command Center Structure

## Purpose

Define the Today command center as an operational view of the current day rather than a competing owner of domain data.

## Purpose of the surface

The command center helps the user orient, choose, act, capture, reconcile, and close. It assembles permissioned references and projections from domain owners; it does not copy or redefine their records.

## Information zones

- **Current context:** date, mode, fixed commitments, protected constraints, relevant status.
- **Next action:** validated candidate with reason and alternatives where appropriate.
- **Living plan:** ordered or time-aware plan items with actual state.
- **Capture/start:** focused entry to session, task, mark, routine, or expense workflows.
- **Signals:** limited deadlines, conflicts, recovery needs, and evidence-backed risks.
- **Reconciliation:** changes since planning and unresolved items.
- **Closure:** day summary, carry-forward choices, and reflection entry.

## Prioritization rules

No domain receives permanent visual dominance. Urgency, consequence, trajectory, recovery, fixed commitments, and user priorities shape prominence. Protected sleep and safety cannot be hidden below optional work.

## AI states

CORE offers deterministic next-action context. V1–V3 recommendations are visibly labeled, cite reasons/evidence, and open an approval flow before changing plans. A suggestion card is not a plan item until approved.

## Density rules

Show the minimum needed for the next decision. Details, evidence, and history open contextually. Avoid a wall of metrics, streaks, or every domain status.

## Acceptance criteria

The user can understand today within a short scan, start common actions quickly, see why the plan changed, and operate fully offline without AI.
