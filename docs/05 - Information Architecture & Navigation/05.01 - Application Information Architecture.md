# Application Information Architecture

## Purpose

Define the canonical content hierarchy and relationship between global navigation, domains, workflows, entities, and system areas.

## Hierarchy

| Level | Purpose | Examples |
|---|---|---|
| Global | Cross-domain orientation and access | Today, search, command palette, notifications |
| Domain | Stable conceptual areas | Academics, Development, Fitness, Routines |
| Collection | Filtered sets of entities | Courses, learning paths, sessions, expenses |
| Entity | Durable record and its relationships | Course, goal, topic, workout, language path |
| Workflow | Task-focused sequence | Plan day, enter marks, close session, review week |
| System | Configuration and stewardship | Permissions, data, backup, integrations, diagnostics |

## Global structure

Today is the default operational entry, not the owner of all domain data. Goals & Paths exposes Goal → System → Action relationships. Domain areas own specialist workflows. Analytics presents derived views. Settings/Data areas govern configuration and platform concerns.

## Organization rules

- Organize by user concepts and tasks, not database tables or services.
- Give every entity one canonical detail route; alternative entry points deep-link to it.
- Keep creation/editing with the owning domain contract.
- Show capability, provenance, sync, and recommendation states where relevant.
- Preserve history and current state as distinct views.
- Avoid placing the same authority in Today, dashboard, and domain forms.

## Routing identity

Routes use stable entity IDs rather than display names. Filters, tabs, and selected subviews may be encoded for restorable navigation, but sensitive values must not leak into URLs, logs, or window titles.

## Offline and failure behavior

All CORE destinations resolve locally. Unavailable optional services show scoped status without blocking unrelated navigation. Missing/deleted entities produce a recoverable not-found state with provenance-aware repair options.
