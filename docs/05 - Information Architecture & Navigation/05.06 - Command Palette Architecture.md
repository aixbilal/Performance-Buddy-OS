# Command Palette Architecture

## Purpose

Define a keyboard-first registry for navigation and safe actions with deterministic validation and approval boundaries.

## Scope

The command palette exposes registered navigation, creation, capture, filtering, view, and workflow commands. It is not a shell and does not grant broader authority than the normal UI.

## Command contract

Each command has stable ID, label, aliases, owner domain, capability, required context, parameters, permissions, validation, preview/confirmation policy, availability reason, undo behavior, and result route.

## Command classes

- Navigation: open Today, course, path, review, settings.
- Creation/capture: new action, session, mark, expense, routine entry.
- Contextual: complete plan item, open evidence, start test.
- View: change filter, date, or mode.
- System: backup, export, reindex, diagnostics—clearly separated.

## Natural-language enhancement

CORE supports deterministic matching and parameter forms. LOCAL/V1 may interpret natural language, but interpretation produces a structured command proposal. Consequential parameters are previewed; meaningful writes require the same approval/confirmation rules as other surfaces.

## Safety

Unavailable commands explain why. Destructive actions cannot rely on fuzzy matching alone. AI cannot invent command IDs or bypass permissions. Sensitive arguments are not retained in command history without consent.

## Acceptance criteria

Commands are discoverable, keyboard accessible, owner-validated, auditable, and consistent with direct workflows; AI/provider failure leaves deterministic commands available.
