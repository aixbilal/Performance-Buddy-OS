# 26.05 — Read Operations

## Scope

V1 may answer questions using registered read tools, CORE compute tools, and permission-filtered retrieval. Reads include current plans, schedules, tracker state, academic records and calculations, knowledge sources, development progress, fitness records, routine data, money summaries, and analytics where the user is authorized.

## Rules

Apply permissions before retrieval and tool execution. Minimize context to the question. Distinguish authoritative records, user-entered evidence, derived analytics, and model explanation. Cite source entity, date/revision, and retrieval location when claims depend on documents. Recompute numerical results through CORE rather than accepting model arithmetic.

A read operation has no write side effect, including hidden “last viewed,” memory, or correction records beyond separately governed operational telemetry. Tool output remains untrusted context. Missing, stale, conflicting, or inaccessible evidence produces a qualified answer or abstention.

## Presentation

Show the direct answer first, then relevant evidence, assumptions, freshness, and a route to the owned detail surface. Never imply a record exists or is complete when it does not.

## Acceptance criteria

- Permission tests prevent direct and inferred leakage across data categories.
- Citations resolve to the claimed source revision.
- Read failures and provider unavailability do not change state and offer search/CORE alternatives.
