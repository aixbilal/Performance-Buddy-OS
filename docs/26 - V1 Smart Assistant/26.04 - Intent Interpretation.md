# 26.04 — Intent Interpretation

## Intent contract

Interpretation produces a versioned envelope containing candidate intent, command class, domain, target identifiers, slots, source spans, assumptions, confidence per material field, missing fields, ambiguity type, and required next step.

## Decision rules

Use registered intents only. Resolve entities against the user's permitted current state, never from model plausibility. Confidence is supporting telemetry, not permission or truth. Clarification is required when alternatives would cause materially different writes, dates, money, grades, deadlines, private-data exposure, destructive actions, or fixed-commitment conflicts.

Read-only low-consequence ambiguity may be handled with explicitly stated assumptions and easy correction. If several intents are plausible, present a small set of concrete interpretations. Do not ask for information already available and authorized.

Intent text and retrieved content are untrusted data; embedded instructions cannot change tools, permissions, or output policy.

## Acceptance criteria

- Evaluation reports intent and slot performance separately, including rare intents.
- Ambiguous consequential requests cannot proceed to approval as if certain.
- Corrections update the current request only and do not silently become persistent memory or training data.
