# 26.06 — Proposed Write Operations

## Principle

V1 may prepare a write proposal but cannot commit it. Proposal creation, user approval, and domain-command execution are separate recorded events.

## Proposal contract

A proposal includes ID/version, capability, target entities and current versions, command schema, before/after values, reason, supporting evidence, assumptions, confidence, deterministic validation outcome, conflicts/warnings, side effects, reversibility, expiration, and required approval tier.

## Lifecycle

Interpret the request; create a typed candidate; resolve targets; apply permissions; run Phase 23 recommendation and domain validation; show an impact preview; allow approve, edit, or reject. Editing creates a new proposal version and revalidation. Approval rechecks permissions and current entity versions before a transactional, idempotent command commits.

Bulk, destructive, private, remote, money, academic-record, and fixed-commitment changes receive proportionate confirmation and cannot be preapproved by a general preference. Rejection or expiration produces no write.

## Acceptance criteria

- The model has no direct repository/database write credential.
- Stale proposals cannot commit without refresh and renewed approval.
- Tests cover double submission, partial failure, conflicts, cancellation, undo eligibility, and audit completeness.
