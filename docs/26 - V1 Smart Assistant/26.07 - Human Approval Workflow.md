# 26.07 — Human Approval Workflow

## Purpose

Approval lets the user authorize a specific AI proposal with informed control. It is not blanket automation permission and does not prove the proposal is optimal.

## Workflow

1. Present action, target, before/after effect, reason, evidence, assumptions, validation, warnings, and recovery limits.
2. Offer unambiguous `Approve`, `Edit`, and `Reject` choices; dangerous actions are never default-focused.
3. On edit, create and validate a new proposal version.
4. On approve, record actor, time, proposal version, displayed impact, and scope.
5. Recheck authorization, freshness, constraints, and idempotency immediately before commit.
6. Show completed, partially completed, conflicted, or failed result accurately.

Approval expires with the proposal and applies only to its displayed scope. A keyboard shortcut, chat phrase, API retry, background run, or remembered preference cannot bypass high-consequence confirmation. The user may cancel before commit when technically possible.

## Acceptance criteria

- Approval cannot be replayed for a changed proposal or different targets.
- Rejection, timeout, revocation, and navigation away cause no write.
- Accessibility tests cover keyboard, screen reader, focus order, destructive labels, and status announcements.
