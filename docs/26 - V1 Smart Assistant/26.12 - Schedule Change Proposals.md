# 26.12 — Schedule Change Proposals

## Scope

In response to a user request, V1 may propose creating, moving, resizing, splitting, replacing, or cancelling flexible schedule blocks. Phase 08 owns daily planning and modes; Phase 23 owns fixed commitments, sleep protection, scheduling rules, and validation.

## Required proposal data

Identify affected blocks and versions, requested objective, resolved dates/timezone, before/after timeline, fixed versus flexible status, dependencies, capacity, protected constraints, displaced work, alternative options, reason codes, warnings, and expiration.

## Rules

V1 can explain tradeoffs and offer bounded alternatives but cannot silently move work, override a fixed commitment, shorten protected sleep, or claim the proposal is optimal. A request to “make it fit” does not authorize deletion. Editing or selecting an alternative triggers fresh deterministic validation. Changed calendar/plan state makes the proposal stale.

Exam, recovery, weekend, and university modes are read as current CORE configuration; V1 does not activate a mode without an approved proposal.

## Acceptance criteria

- Overlap, travel buffer, dependency, midnight, timezone, sleep, and stale-state tests pass.
- Every displaced or dropped commitment is visible before approval.
- Failed, rejected, or expired proposals cause no schedule mutation.
