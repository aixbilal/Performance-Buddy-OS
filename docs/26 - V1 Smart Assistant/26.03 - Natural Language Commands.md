# 26.03 — Natural Language Commands

## Purpose

Allow users to express supported application commands conversationally while preserving the typed domain-command contracts used by CORE.

## Command classes

- **Navigate/search:** open a surface or find permitted entities.
- **Read:** retrieve current facts or summaries.
- **Compute:** invoke a deterministic calculator or validator.
- **Draft:** prepare content or an uncommitted candidate.
- **Proposed write:** describe a state change for later approval.

## Pipeline

Normalize language and locale; identify candidate intent; extract entities, dates, quantities, units, and constraints; resolve identifiers through domain services; validate against an allowlisted command schema; clarify consequential ambiguity; then execute a read/compute or create a proposal. Parsing never grants execution authority.

Commands support paraphrases and corrections but remain bounded. Multiple consequential intents are split into separately reviewable proposals unless a clearly scoped batch policy exists. Relative dates display the resolved absolute date and timezone. The original request remains visible through review.

## Acceptance criteria

- Tests cover negation, typos, pronouns, multiple entities, locale, dates, units, and unsupported commands.
- V1 never invents a command, entity, value, or successful execution.
- Form, search, and manual-entry fallbacks preserve the user's input when interpretation fails.
