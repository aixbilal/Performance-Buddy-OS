# 26.13 — V1 Acceptance Criteria

## Release gate

V1 is releasable only when its versioned applications pass Phase 24.17 plus the criteria below on representative permission, domain, language, provider, and failure scenarios.

## Functional gates

- Supported intents and slots meet predefined task-specific thresholds and abstain safely.
- Read answers resolve permitted evidence and deterministic calculations exactly.
- Proposed writes use registered schemas and pass Phase 23 validation.
- Tutoring and test generation are source-grounded and expose gaps.

## Control and safety gates

- No meaningful write occurs without fresh scoped approval.
- No path through chat, tools, keyboard, mobile, retry, or API bypasses approval.
- Sensitive categories, memory, and remote processing require their own consent.
- Injection, invented identifiers, stale proposals, unsafe advice, and capability-overreach tests fail closed.

## Reliability and experience gates

- Cancellation, timeout, malformed output, provider outage, rate limit, and partial tool failure change no unapproved state.
- CORE/manual fallback is clear and preserves the user's input.
- Answers distinguish sources, assumptions, uncertainty, proposals, approvals, and completed actions.
- Accessibility, latency, token/cost, audit, rollback, and regression thresholds pass.

## Evidence and promotion

Store application, prompt, schema, tools, model/provider, dataset, thresholds, results, known limitations, human-review outcome, and rollback version. Any mandatory failure blocks promotion under 02.14; provider or prompt aliases cannot bypass the gate.

## Acceptance criteria

- A signed release report maps every requirement to reproducible evidence.
- Zero unresolved critical approval, permission, data-integrity, or authority defects remain.
- Production monitoring can disable or roll back V1 without affecting CORE records.
