# Filesystem Access

## Purpose

Define least-privilege, race-resistant filesystem behavior for reading a selected vault.

## Rules

All paths are resolved against the canonical approved root. Relative traversal, alternate streams where applicable, symlink/junction escapes, and unexpected device paths are rejected. Allowlisted file types and size limits apply before reading. The scanner does not execute files, macros, scripts, or embedded commands.

## Read behavior

Open files with safe sharing where possible, record modification marker and size, stream large content, verify consistency after reading, and retry bounded transient failures. Encoding detection preserves the original; decode errors create diagnostics rather than destructive conversion.

## Write boundary

Indexing never writes to vault files. A future approved write uses compare-before-write, atomic replacement in the same directory where supported, backup/recovery, exact diff preview, and conflict detection.

## Privacy and logging

Logs use redacted paths or stable IDs and exclude note content. Temporary parsed content is minimized and cleaned according to platform policy.

## Acceptance criteria

Security tests cover traversal and link escape, unreadable files are isolated, concurrent edits are not overwritten, and access remains bounded to explicit scope.
