# File Change Detection

## Purpose

Detect relevant vault changes with low overhead while acknowledging that filesystem watcher events can be incomplete, duplicated, or reordered.

## Strategy

Use a local watcher where supported, backed by periodic or startup reconciliation of permitted paths. Events are hints until canonical path, current metadata, checksum, and permission are revalidated.

## Event handling

Create, modify, rename/move, delete, permission change, and vault availability changes enter a debounced queue. Temporary files and editor save patterns are coalesced. Rapid edits wait for a stable-read window.

## Rules

Watcher failure must not imply the index is current. Overflow, sleep/resume, clock anomalies, network drive interruption, or long downtime marks coverage stale and triggers reconciliation. Moves outside scope become deletion plus an inaccessible reference unless the user broadens permission.

## Acceptance criteria

Tests cover atomic saves, rename pairs, duplicate events, missed events, offline vaults, and permission changes; stale state is visible; and reconciliation restores correctness without scanning outside scope.
