# Markdown Indexing

## Purpose

Parse permitted Markdown into rebuildable local projections for search, linking, and source-grounded retrieval.

## Parsed elements

File identity, path, title, headings and anchors, paragraphs or bounded chunks, tags, frontmatter, Markdown links, wiki links, embeds, block IDs, code fences, task syntax, and attachment references may be extracted while retaining source offsets.

## Rules

- Raw Markdown remains authoritative.
- Parser version and file checksum accompany every projection.
- Code, comments, generated folders, templates, and private paths follow configured inclusion rules.
- Unsupported syntax is retained as text or flagged; it is not silently discarded.
- Chunk boundaries preserve heading context and citation location.
- Parse failure quarantines only the affected file and leaves the prior index visibly stale.

## Capability

Local deterministic parsing is `CORE`. AI-based structure extraction is optional, labeled, and reviewable.

## Acceptance criteria

Representative Obsidian syntax has fixtures, offsets open the correct location, index rebuild is deterministic for a parser version, and malformed files cannot corrupt the wider index.
