# Vault Permission Boundaries

## Purpose

Enforce explicit folder, file-type, content-use, and provider boundaries consistently across scanning, indexing, search, retrieval, background work, and AI.

## Permission dimensions

Vault and subfolder inclusion/exclusion, file overrides, metadata-only versus content access, attachment types, snippet display, local indexing, local model use, remote model use, retention, and export are independently configurable where needed.

## Rules

Deny overrides allow. Canonical-path evaluation occurs before every read. Permission is checked both at ingestion and query. Symlinks/junctions cannot expand scope. A note link or embed does not grant permission to its target. Cloud sync consent does not grant AI-processing consent.

## Revocation

Revocation stops new access, cancels queued work where possible, purges prohibited content from indexes/caches/embeddings, and records completion. Minimal reference metadata is retained only when permitted.

## Acceptance criteria

Adversarial path and indirect-link tests prevent leakage, background jobs honor changes promptly, provider exposure is auditable, and the user can understand and revoke each access category.
