# Obsidian Integration Overview

## Purpose

Provide governed discovery, linking, indexing, and retrieval of permitted Markdown notes and attachments from an Obsidian vault without making the application the vault’s owner.

## Baseline flow

Select a vault; establish permission scope; scan permitted files; parse Markdown and approved metadata; create stable references; build local lexical projections; monitor changes; and expose source-grounded search/retrieval.

## Access posture

`CORE` is local and read-only by default. Explicit write features, if later approved, must preview the exact file change, preserve encoding and unrelated content, use atomic writes and backup, and support undo. Plugin installation inside Obsidian is not required.

## Authority

The file is authoritative for its text. Parsed metadata and indexes are projections. Knowledge links are governed references. AI summaries or classifications remain derived artifacts and cannot overwrite the source.

## Capability

Filesystem access, parsing, lexical indexing, references, and recovery are `CORE`. Semantic indexing is optional `LOCAL`; remote embeddings are optional `CLOUD` with separate consent.

## Acceptance criteria

Integration works offline, disabling it leaves the vault unchanged, permission revocation stops access promptly, and every search result opens or identifies its source file and location.
