# Vault Selection

## Purpose

Let the user deliberately choose which Obsidian vault and subfolders Performance Buddy OS may access.

## Selection workflow

The user chooses a directory; `CORE` resolves its canonical absolute path; verifies it is a readable directory; identifies `.obsidian` only as supporting evidence, not a strict requirement; displays scope and detected file counts; checks overlaps with existing selections; and requests confirmation.

## Rules

- Never auto-discover and index every vault without approval.
- Store a stable vault ID plus canonical path; do not rely on display name alone.
- Detect nested or duplicate vault selections to prevent double indexing.
- Resolve symlinks/junctions and reject paths escaping approved scope.
- Network/removable locations show availability and durability warnings.
- Switching vaults preserves the old configuration in disabled state until the user removes it.

## Missing vault

If unavailable, mark it `OFFLINE/MISSING`, pause scanning, retain permitted reference metadata, and offer locate, reconnect, or disable. Do not create a replacement folder automatically.

## Acceptance criteria

Selection is explicit, canonical, non-duplicative, reversible, and unable to broaden access through path tricks.
