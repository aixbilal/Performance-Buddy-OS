# Embedding Index Strategy

## Purpose

Define optional semantic indexing without weakening lexical search, privacy, explainability, or offline authority.

## Capability status

Embeddings are not `CORE`. On-device generation belongs to `LOCAL` after runtime, quality, latency, and hardware evaluation. Provider-generated embeddings are `CLOUD` and require explicit source-scoped consent. Exact model, vector store, dimensions, and chunking are `RESEARCH REQUIRED`.

## Record contract

Store source chunk ID/checksum, model/provider/version, dimensions, normalization, generation time, permission partition, and index version. Model changes require a new index generation; vectors from incompatible models are never mixed.

## Privacy

Restricted files can be excluded entirely. Remote transfer minimizes content, records exposure, respects revocation, and never follows permission merely because sync was enabled.

## Retrieval

Semantic matches show source and reason, combine with lexical results through an explainable strategy, and remain fallible candidates. Disabling embeddings deletes or deactivates projections without harming references.

## Acceptance criteria

Lexical fallback remains complete, stale vectors are invalidated by source changes, permission leakage tests pass, and semantic quality is evaluated before promotion.
