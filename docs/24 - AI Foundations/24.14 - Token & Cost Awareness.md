# 24.14 — Token and Cost Awareness

## Principle

Quality, privacy, and correctness are protected constraints; cost optimization may not weaken them silently. Every application defines input, output, tool-step, time, and monetary budgets suitable for its capability tier.

## Controls

Estimate before execution where pricing metadata exists. Minimize context through permission-safe retrieval, deduplication, compact schemas, and bounded history. Cache only non-sensitive, version-keyed artifacts with explicit invalidation. Stop or request consent before exceeding a user-visible budget. Record actual usage and estimated cost with provider pricing version and currency.

Budgets may exist per run, day, month, feature, and provider. Background workloads use stricter limits and yield to interactive work. A cheaper model is selected only if it satisfies the application’s declared capability and evaluation gates. Local inference can reduce remote cost but still consumes device resources and remains subject to privacy rules.

## Acceptance criteria

- No unbounded context, output, tool loop, or background spend is possible.
- Users can inspect and configure meaningful cost controls.
- Cost records distinguish estimates from settled provider usage.
