# 24.08 — Prompt Versioning

## Version unit

A prompt release includes the instruction template, component versions, context mapping, output schema, tool contracts, model requirements, and evaluation baseline. Changing any behaviorally significant element creates a new release.

## Version policy

Use immutable semantic versions: major for incompatible contract or behavioral changes, minor for compatible capability improvements, and patch for wording or defect corrections with unchanged contracts. Every AI run stores the application, prompt, schema, tool, provider adapter, model identifier, and policy versions.

## Lifecycle

Draft versions run only in controlled evaluation. Approved versions may be gradually enabled behind a capability gate. Rollback selects a prior immutable bundle; it never rewrites historical records. Migration notes identify changed inputs, outputs, safety behavior, cost, and expected quality.

Prompt changes require regression evaluation, including permission leakage and injection resistance—not only subjective answer review. Emergency disablement is possible without deleting evidence.

## Acceptance criteria

- A historical result can be traced to the exact prompt bundle.
- Production aliases resolve to an immutable version in the run record.
- Promotion and rollback decisions are recorded with evaluation evidence.
