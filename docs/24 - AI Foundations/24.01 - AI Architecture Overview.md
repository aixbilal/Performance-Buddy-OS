# 24.01 — AI Architecture Overview

## Decision

Performance Buddy OS uses a layered AI architecture around—not inside—the deterministic CORE. Domain services supply authorized facts; retrieval supplies traceable evidence; orchestration assembles a bounded request; a provider produces a proposal; validators and Phase 23 decide whether it is safe and structurally usable.

## Layers

1. **Experience layer:** user request, disclosure, approval, cancellation, and explanation.
2. **Orchestration layer:** capability selection, context budget, prompt version, tool loop, and run state.
3. **Evidence layer:** permission-filtered domain data, retrieval results, provenance, and governed memory.
4. **Model layer:** provider-neutral inference through a capability adapter.
5. **Control layer:** schema checks, policy checks, Phase 23 rules, approval gates, and transactional writes.
6. **Observability layer:** redacted traces, outcome metrics, costs, failures, and evaluation results.

## Invariants

- Models never become a source of record.
- Domain ownership from Phase 04 is preserved.
- Deterministic calculations are recomputed by CORE, never accepted from prose.
- Untrusted content is data, not executable instruction.
- Every run is bounded by purpose, permissions, time, tokens, tools, and retries.
- A write is committed separately from inference and is auditable and recoverable.

## Capability placement

`LOCAL` may summarize or classify on-device. `V1` is reactive and user-directed. `V2` may detect patterns and propose adaptations from reliable history. `V3` may reason across domains, but remains constrained. `CLOUD` identifies optional remote execution, not a quality tier.

## Acceptance criteria

- Every AI feature maps to one layer, owner, capability label, and failure path.
- No dependency makes AI necessary for CORE operation.
- All action paths terminate in deterministic validation and applicable approval.
