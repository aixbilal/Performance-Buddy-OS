# 24.20 - Agent Memory & Continuity
## Purpose

Preserve useful companion continuity through application-managed, permission-scoped memory while keeping deterministic records authoritative.

## Memory classes and writes

Memory includes stable persona configuration, user-approved preferences, task/session context, summaries with provenance, recommendation outcomes, and explicit corrections. It excludes credentials, private chain-of-thought, unapproved inference presented as fact, and data classified never-AI. Deterministic trackers and domain records are referenced, not silently copied or rewritten.

Candidate memories pass schema validation, sensitivity classification, provenance capture, retention rules, contradiction checks, and the required approval level. Memory updates are versioned and reversible. Retrieval is purpose-bound, least-privilege, freshness-aware, and logged. A specialist receives only the minimum slice necessary for its assigned task.

## Continuity and provider changes

Identity and memory live in the application, not provider chat history. Provider/model/key replacement cannot erase or redefine a companion. Conversation can improve future recommendations because the application stores and retrieves approved context; it does not mean any model retrains itself.

## Acceptance criteria

- Users can inspect, correct, forget, export, and restrict memory.
- Provider prompts contain only authorized purpose-specific context.
- Stale or conflicting memories are flagged and cannot override current deterministic facts.
- Offline memory remains usable, with encrypted storage and redacted audit where required.
