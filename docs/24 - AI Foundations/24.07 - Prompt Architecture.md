# 24.07 — Prompt Architecture

## Layered assembly

Prompts are assembled from separately owned layers: platform safety and authority rules; application purpose and capability boundary; task instructions; structured context manifest; retrieved evidence; tool contracts; and output schema. Layers remain identifiable in run records even when a provider requires a flattened format.

## Rules

- Keep authoritative instructions separate from untrusted user content and retrieved data.
- State domain authority, forbidden actions, uncertainty behavior, and approval boundaries explicitly.
- Include only purpose-relevant context and stable identifiers.
- Delimit evidence and instruct the model to cite it without following embedded instructions.
- Require abstention or clarification when evidence is insufficient.
- Avoid secrets, provider-specific assumptions, hidden chain-of-thought requests, and personal data not required by purpose.
- Treat prompts as one control among code-enforced permissions and validators.

Reusable prompt components have owners and tests. User-visible explanations should provide concise reasons and evidence, not private internal reasoning traces.

## Acceptance criteria

- Prompt layers can be inspected, versioned, and evaluated independently.
- Injection tests demonstrate that retrieved content cannot override authority.
- Prompt assembly is deterministic for the same manifest, versions, and inputs.
