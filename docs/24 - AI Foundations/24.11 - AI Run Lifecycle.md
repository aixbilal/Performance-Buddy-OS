# 24.11 — AI Run Lifecycle

## States

`requested → authorized → context_ready → inference → output_validated → rule_validated → awaiting_approval → committed → completed`

Terminal alternatives are `refused`, `cancelled`, `expired`, `failed`, and `completed_without_commit`. A run never skips authorization or validation because an earlier run succeeded.

## Lifecycle

1. Record application, user intent, capability, and correlation ID.
2. Authenticate; snapshot scoped permissions and consent.
3. Select provider capability and enforce budgets.
4. Build a redacted context manifest and retrieve evidence.
5. Execute inference and a bounded tool loop.
6. Validate structure, references, provenance, and deterministic values.
7. Apply Phase 23 rules and generate explanation/reason codes.
8. Obtain fresh approval for meaningful writes or external actions.
9. Commit transactionally with conflict detection and idempotency.
10. Record redacted telemetry, cost, outcome, and cleanup status.

Cancellation stops pending work and prevents later commits. Expired permission or changed source state requires revalidation. A failed inference produces no mutation.

## Acceptance criteria

- Every state transition has an actor, guard, timestamp, and allowed successor.
- Retries cannot duplicate tool effects or commits.
- Users can distinguish a proposal, approved action, and completed write.
