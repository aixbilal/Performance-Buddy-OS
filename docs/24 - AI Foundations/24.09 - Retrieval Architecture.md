# 24.09 — Retrieval Architecture

## Retrieval flow

Retrieval converts a purpose-bound query into permission-filtered evidence. The flow is: identify eligible sources → enforce access before search → normalize query → search lexical/semantic indexes → rerank within budget → return bounded passages with provenance → disclose gaps.

## Evidence record

Each passage carries source ID, owner domain, location, content hash or revision, timestamp, authority classification from 00.06, sensitivity, retrieval method, and score. Scores rank candidates; they do not establish factual authority.

## Source handling

Official records outrank personal notes for institutional facts; personal records govern personal state; model-generated summaries are derived evidence and link to originals. Conflicts remain visible and follow 00.18. Missing, stale, inaccessible, or contradictory evidence causes qualification or abstention—not fabrication.

Permissions apply before embedding search and again before passage return. Remote embedding or inference receives only the minimum approved content. Index deletion and permission changes propagate promptly, including derived caches.

## Acceptance criteria

- Answers can cite retrievable evidence at the claimed revision.
- Unauthorized documents cannot influence ranking or output.
- Empty-result, stale-source, conflict, and prompt-injection cases are tested.
