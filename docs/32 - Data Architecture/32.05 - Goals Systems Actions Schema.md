# 32.05 — Goals, Systems, and Actions Schema

## Entities

`Goal`: outcome/direction, type, scope, priority, target/evidence contract, horizon, state. `System`: repeatable process, cadence/conditions, active state. `Action`: concrete commitment, description, owner context, stopping condition, estimate, deadline/window, fixed/flexible, priority, state. `Milestone` and `LearningPathUnit` provide checkpoints/structure. Typed link records connect them.

## Invariants

An action completion does not complete a goal automatically. Progress is a derived record with input and rule versions. Links carry role, order, effective dates, and provenance; prohibited dependency cycles fail. Archiving a parent preserves children/history and requires explicit treatment of future actions.

## Acceptance criteria

- Every action traces to its origin when one exists.
- Goal/system/action states and transitions match Phase 11.
- Cross-goal systems share one record without double-counting evidence.
