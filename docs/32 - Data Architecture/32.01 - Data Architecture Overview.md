# 32.01 — Data Architecture Overview

## Architecture

The initial product uses a local-first logical data model behind domain repositories and commands. Physical storage may be one database plus files/indexes; logical ownership does not require microservices or one database per domain.

## Data classes

1. Canonical domain records.
2. External/official source references and imported personal records.
3. Append-only revisions, commands, and audit events.
4. Deterministic results with input/rule manifests.
5. Disposable search, analytics, and synchronization projections.
6. AI runs, recommendations, approvals, and governed memory.

## Rules

Repositories enforce owner invariants and optimistic concurrency. Cross-domain consumers use stable contracts, never direct table coupling. Transactions protect one business command; cross-owner workflows use validated commands and auditable outcomes. Backups and exports preserve schema/provenance and are not synchronization.

Exact database, ORM, serialization, event log, and file layout are `RESEARCH REQUIRED` under Phase 44.

## Acceptance criteria

- CORE CRUD/calculation remains local and deterministic.
- Rebuilding disposable projections cannot change source records.
- Storage failure is detectable, recoverable, and cannot produce silent partial authority.
