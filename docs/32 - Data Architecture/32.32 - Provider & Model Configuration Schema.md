# 32.32 - Provider & Model Configuration Schema
## Entities

`Provider`: provider ID/type (`local`, `gemini`, `groq`, `future`), adapter/version, status, region/retention, account/project metadata, policy refs, health. `ModelConfiguration`: model ID/version, provider, capabilities, limits, structured-output/tool support, evaluation status, parameters, cost/rate metadata.

`CredentialReference`: opaque credential ID, provider/account/project scope, secret-store locator, lifecycle, rotation/expiry, last validation; never secret value. `AgentProviderEligibility`: agent/task class, provider/model, priority, required locality/capability, effective dates, policy/evaluation refs. `RoutingAttempt` records selection reasons, failure class, failover chain, and disclosure.

## Integrity and acceptance criteria

- Agents, providers/models, and credentials have independent keys and lifecycles.
- One credential may serve legitimate multiple routes; key count never determines agent count.
- Secret values cannot appear in database exports, prompts, logs, or memory.
- Routing constraints prevent local-only data from selecting remote providers.
