# 32.23 — Device and Sync Metadata

## Entities

`Device`: opaque ID, installation ID, platform/app/schema versions, registration/status, last seen, capability flags, key refs. `SyncOperation`: operation ID, entity/revision, origin device, logical/vector clock or ordering metadata, payload hash, state, attempts/errors. `SyncCursor`, `Tombstone`, and conflict records support transport.

## Rules

Sync is optional and not backup. Metadata never outranks business records or permissions. Device names are user-friendly metadata, not identity/authorization. Exact conflict algorithm and cloud transport belong to later sync phases. Never-AI/local-only classifications constrain payloads.

## Acceptance criteria

- Replays are idempotent and origin loops are prevented.
- Device removal/revocation blocks future sync without deleting owner data silently.
- Clock skew and offline concurrency remain detectable for conflict handling.
