# 32.20 — Approval and Rejection Schema

## Entities

`DecisionRequest`: proposal ID/version, targets/versions, displayed impact hash, approval tier, expiry. `ApprovalDecision`: actor, decision (`APPROVE`, `EDIT`, `REJECT`, `DEFER`), scope/batch items, timestamp, UI/channel, optional reason, consent refs, and signature/integrity metadata. `CommitOutcome`: command/idempotency, status, changed revisions, errors, undo ref.

## Invariants

Approval applies only to the exact displayed proposal and targets. Edit creates a new proposal/request. Rejection/defer causes no commit. Stale, expired, revoked, or replayed decisions fail. Decision records cannot grant data permission beyond the separately referenced consent.

## Acceptance criteria

- Approval bypass/replay, batch mismatch, double submit, and stale target tests pass.
- The record distinguishes approved, attempted, partially committed, and completed.
- Rejection reason remains optional and privacy classified.
