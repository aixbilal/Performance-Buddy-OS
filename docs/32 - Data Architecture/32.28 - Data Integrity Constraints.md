# 32.28 — Data Integrity Constraints

## Constraint layers

Database constraints protect types, nullability, uniqueness, foreign keys, and basic ranges. Domain validators enforce lifecycle, units, time, recurrence, graph, policy, permissions, and cross-field semantics. Phase 23 enforces cross-domain/protected constraints. Import/migration reconciliation verifies provenance and totals.

## Mandatory invariants

Opaque IDs/type/owner immutable; revisions monotonic; timestamps valid; references resolve or are explicitly unresolved; money uses currency-safe decimals; marks/weights validate; intervals and recurrence are coherent; prohibited graph cycles fail; derived results have inputs/versions; AI records cannot masquerade as source facts; approval binds exact proposal/targets; privacy classification never weakens through derivation.

## Operations

Run continuous write-time validation plus scheduled integrity scans. Quarantine corrupted/imported data; never auto-“repair” consequential values without evidence. Repairs are commands with before/after, reason, source, actor, and audit.

## Acceptance criteria

- Property, fuzz, concurrency, migration, corruption, and restore tests cover every invariant.
- Integrity failures block unsafe writes and identify affected records.
- Recovery preserves originals/evidence and produces reproducible reconciliation.
