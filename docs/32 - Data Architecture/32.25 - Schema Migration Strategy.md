# 32.25 — Schema Migration Strategy

## Process

Inventory affected entities/projections; define forward and rollback/restore plan; back up and verify; test on representative copies; run preflight capacity/integrity checks; acquire migration lock; apply idempotent steps transactionally where possible; record migration ledger/checkpoints; validate counts, hashes, invariants, and sampled semantics; rebuild projections; then release.

## Rules

Migrations never depend on AI. Destructive/irreversible transformations require explicit decision, export/backup, and shadow-copy strategy. Expand/migrate/contract supports compatibility where needed. Failed migrations stop safely and retain diagnostics without exposing private content.

## Acceptance criteria

- Upgrade from every supported version and interrupted-resume paths are tested.
- Before/after reconciliation proves no silent loss or semantic drift.
- Rollback or documented forward recovery is proven before release.
