# 32.29 - Agent Profiles & Personas Schema
## Entities

`AgentProfile`: agent ID, canonical name, role, visibility, objectives, task classes, tool policy refs, memory-scope refs, consultation policy, output schemas, escalation agent, lifecycle, versions, timestamps.

`PersonaProfile`: persona ID/version, agent ID, role label, tone constraints, language/accessibility preferences, avatar token set, motion state set, disclosure text, effective dates. Provider/model/credential IDs are intentionally absent; runtime assignments use separate configuration.

Required profiles cover the three persistent visible companions and registered hidden specialists. Immutable IDs survive display-name, visual, model, and provider changes. Historical versions support audit and personality-drift evaluation.

## Integrity and acceptance criteria

- One active persona version per visible agent and no duplicate canonical agent ID.
- Head Coach escalation references resolve without cycles.
- Profiles cannot embed secrets or grant permissions outside policy records.
- Deleting a provider cannot cascade-delete profiles.
