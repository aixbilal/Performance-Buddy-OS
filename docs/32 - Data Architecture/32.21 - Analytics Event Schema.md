# 32.21 — Analytics Event Schema

## Entity

`AnalyticsEvent`: event ID/type/version, owner/source entity and revision, occurred/recorded times, actor/device, domain, privacy class, payload schema, idempotency key, correction/supersession, and provenance. Events describe completed facts; they are not commands.

## Rules

Use the minimum payload and owner IDs rather than copied mutable objects. Late/out-of-order events are supported. Corrections append events. Event time and ingestion time remain distinct. Consumers maintain checkpoints and rebuild disposable projections. Sensitive domains may suppress or aggregate events by permission.

## Acceptance criteria

- Duplicate, late, reordered, corrected, deleted, and replayed streams yield deterministic projections.
- Schema evolution preserves old-event decoding.
- Analytics cannot mutate source entities or infer missing events.
