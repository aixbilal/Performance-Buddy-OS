# 32.03 — Entity Relationship Map

## Major relationships

`Goal ↔ System → Action → PlanItem → Session/ExecutionLog`; `TrackerDefinition → ScheduleRule → Occurrence → TrackerRecord`; `University → Program → CurriculumVersion → SemesterDefinition → CourseDefinition`; `Enrollment → CourseAttempt → AssessmentScheme → AssessmentItem → MarkRecord → GradeResult`; `KnowledgeEntity ← LearningEvidence`; development, fitness, and routine records link to actions/sessions/evidence; `AIRecommendation → ApprovalDecision → OwnerCommand`; all may link `SourceProvenance` and analytics events.

## Rules

Relationships use stable IDs and explicit link entities when they carry role, order, effective dates, weight, or provenance. Many-to-many links never duplicate owner records. Dependency graphs reject prohibited cycles. Parent archive/delete does not silently destroy child evidence; behavior is restrict, detach, archive, or explicitly cascaded per relationship.

## Acceptance criteria

- Cardinality, ownership, requiredness, and delete/restore behavior are documented for every link.
- Graph integrity tests detect dangling, circular, and cross-privacy references.
- Cross-domain views can be rebuilt from owner records and links.
