# 32.18 — AI Recommendation Schema

## Entity

`AIRecommendation`: ID/version, application/capability/mode, objective/horizon, status, run ID, included domains/consents, source manifest, facts/observations/assumptions/hypotheses, proposed typed owner commands, expected benefit range, trade-offs/displaced work, alternatives, constraints, confidence/uncertainty, Phase 23 validation result/reasons, expiry/review trigger, and prior-guidance change reason.

## Lifecycle

`DRAFT → VALIDATED/VALID_WITH_WARNINGS → PENDING_DECISION → ACCEPTED/EDITED/REJECTED/DEFERRED/EXPIRED/BLOCKED`; acceptance does not mean committed. Each edit creates a version and revalidation. Owner command outcomes link separately.

## Acceptance criteria

- Every material claim links evidence or is labeled inference.
- Stale/blocked/rejected/expired recommendations cannot commit.
- Recommendations never become domain facts through serialization alone.
