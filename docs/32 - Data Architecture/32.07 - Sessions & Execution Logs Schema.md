# 32.07 — Sessions and Execution Logs Schema

## Entities

`Session`: type, domain, plan/action refs, planned/actual timing, lifecycle, assistance mode, interruption state, notes ref, evidence refs. `SessionSegment`: start/end, state (active/pause/interruption), device/source. `ExecutionLog`: append-only event type, occurred/recorded times, actor/device, payload schema/version, idempotency key, and correction link.

## Invariants

Duration is derived from valid non-overlapping segments; wall-clock and active time differ. Ending, cancelling, abandoning, and completing are distinct. Evidence-based completion follows owner rules. Corrections append events/revisions; logs cannot be rewritten silently.

## Acceptance criteria

- Pause/resume, crash recovery, duplicate event, clock drift, and cross-device cases reconcile deterministically.
- AI-off and assisted modes remain queryable.
- Logs cannot prove learning or completion beyond their typed evidence.
