# 32.24 — Data Versioning

## Version dimensions

Keep `schema_version`, `record_revision`, domain definition/policy version, calculation/rule version, source version, event version, API/serialization version, and product capability label separate. They must not share one ambiguous “version” field.

## Rules

Records use optimistic revision checks. Published definitions/rules are immutable; new versions link supersession and effective scope. Historical derivations store exact input and version manifests. New rules apply prospectively unless an approved recalculation creates a new result; history is not silently rewritten.

## Acceptance criteria

- Historical results reproduce with retained versions or show a precise unavailable dependency.
- Parallel curriculum/policy/schema versions coexist.
- Version comparisons and compatibility rules are deterministic and tested.
