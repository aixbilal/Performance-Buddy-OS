# 32.31 - Agent Conversations & Council Schema
## Entities

`AgentConversation`: conversation ID, user/session/purpose, initiating trigger, Head Coach, status, policy/budget refs, timestamps, retention. `ConsultationMessage`: message ID, correlation/parent, sender/recipient, purpose, permitted context manifest/hash, schema version, structured finding/refusal, evidence refs, confidence, provider-run ref, timestamps.

`CouncilRun`: participants, rounds, deadline/budgets, findings, disagreement records, synthesis ID, termination reason. `Synthesis`: candidate recommendation, alternatives, assumptions, evidence, dissent, feasibility result, rule-validation ref, user-decision ref.

## Rules and acceptance criteria

Messages are append-only, ordered, idempotent, and contain no credentials/private reasoning. Context content is stored only when policy permits; hashes/references/redaction are preferred. Exactly one final synthesis may advance to validation. Council cancellation or failure records whether any write occurred.
