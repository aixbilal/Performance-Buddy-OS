# 32.16 — Routine Schema

## Entities

Routine behavior uses tracker definitions/occurrences/records plus typed extensions: `PrayerRecord` multi-check details, hydration/nutrition/skincare/smoking-avoidance records, `ReadingRecord`, `LanguagePracticeRecord`, and `ReflectionRecord`. Extensions reference the base occurrence/record and add only owner-specific fields.

## Privacy

Prayer details, exception reasons, reflections, smoking triggers, nutrition detail, photos/reactions, recordings, and support notes are private-by-default. Fields carry category and AI data zone; metadata/derivatives inherit strict classification.

## Invariants

No inferred prayer, intention, smoking, diet, mood, diagnosis, or worth. Language practice tracks speaking/listening/vocabulary/grammar evidence and maintenance mode; time is not proficiency. Reflection text is not analytics by default.

## Acceptance criteria

- Category permission partitions prevent cross-routine leakage.
- Multi-check and maintenance states retain precise semantics.
- Generic trackers cannot expose private extension fields accidentally.
