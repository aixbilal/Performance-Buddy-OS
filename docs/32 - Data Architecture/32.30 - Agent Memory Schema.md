# 32.30 - Agent Memory Schema
## Entities

`AgentMemory`: memory ID, subject/user, owner agent, memory class, content or encrypted reference, structured claim, source/provenance refs, sensitivity, domain, purpose, confidence, observed/effective/expiry times, status, supersession, consent/permission ref, locality, retention, created-by run, review and deletion metadata.

`MemoryAccessGrant`: agent, purpose, domain/fields, operations, locality, start/expiry, consent/policy, revocation. `MemoryRetrievalEvent` records query purpose, selected IDs, exclusions/reasons, provider exposure class, and redacted audit metadata.

## Rules

Facts from authoritative domain stores are linked, not duplicated as mutable truth. Summaries inherit strict source sensitivity. Candidate memories remain pending until validation/approval policy passes. Credentials and private reasoning are forbidden.

## Acceptance criteria

- Contradictory, stale, expired, revoked, and superseded memory is excluded or flagged.
- Forget/export/correction operations are traceable and scoped.
- Specialist access expires with the task lease.
