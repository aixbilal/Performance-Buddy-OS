# 32.04 — IDs and Identity

## ID policy

Use globally unique, opaque, immutable identifiers generated offline. Exact algorithm is `RESEARCH REQUIRED`; it must support collision resistance, ordering only if privacy-safe, portability, and stable textual serialization. Human labels, filenames, course codes, dates, and provider IDs are never primary identity.

## External identity

External IDs are namespaced by source/system and linked with verification/effective metadata. Aliases aid matching but never merge automatically. Merge preserves retired IDs as redirects; split creates new IDs and maps historical links explicitly.

## Sync and security

Device IDs and operation IDs are separate from user/entity IDs. IDs must not encode sensitive attributes or expose sequential counts. Import idempotency uses source fingerprint plus namespace, not label alone.

## Acceptance criteria

- Offline concurrent generation and import replay produce no collisions/duplicates.
- Rename, merge, split, export/import, and restore preserve resolvable identity.
- Authorization never relies on ID secrecy.
