# 32.02 — Canonical Entity Model

## Common fields

`id`, `entity_type`, `owner_domain`, `schema_version`, `record_revision`, `lifecycle_state`, `created_at/by`, `updated_at/by`, `effective_from/to` where applicable, `privacy_class`, `ai_data_zone`, `source_refs`, `deleted_at/by`, and `deletion_reason`.

## Rules

IDs are immutable. Entity type and owner do not change through ordinary edits. Revision increments atomically on meaningful change. Lifecycle state is domain-defined; deletion is orthogonal. Effective time describes when meaning applies; recorded time describes when the system learned it.

Optional fields are explicit null/unknown, never magic values. Enumerations are versioned. User text is stored separately from normalized values when normalization matters. Derived entities add method/rule/model versions, input references/revisions, confidence where meaningful, and expiry.

## Acceptance criteria

- Every canonical entity maps to one owner and lifecycle.
- Serialization round-trips preserve unknown versus absent values and timestamps.
- AI cannot create an `APPROVED`/authoritative entity without an owner command.
