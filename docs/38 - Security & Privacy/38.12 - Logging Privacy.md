# Logging Privacy

## Principle

Logs support operation and incident recovery with the minimum necessary information. They are not a shadow copy of user data.

## Allowed structure

Prefer event type/version, timestamp, severity, component, correlation ID, stable opaque entity reference, operation/result, duration, bounded reason code, and redacted environment metadata. Record category references rather than content.

Never log credentials, tokens, keys, passphrases, recovery codes, full prompts/responses, note or reflection text, raw marks or money details, voice/image content, unredacted paths, provider payloads, database rows, or sensitive notification text. Exceptions require explicit security purpose, approval, short retention, encryption, and access audit.

Logs are structured, size-bounded, rotation-controlled, access-restricted, integrity-protected where required, and separated by environment. Debug logging expires automatically and cannot silently enable remote upload. Support bundles show an exact preview and require consent.

## Acceptance criteria

- Secret and sensitive-data seeded tests find no prohibited output.
- Rotation, disk-full, crash, and malformed-input tests cannot leak content.
- Users can inspect and approve diagnostic export scope.
