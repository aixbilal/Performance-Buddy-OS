# AI Provider Data Exposure

## Principle

Remote AI exposure is optional, purpose-specific, minimized, and disclosed. A local-model failure never silently falls back to a remote provider.

## Preflight

Before each remote run, validate AI application, domain/category, operation, purpose, source scope, data zone, provider/model, region where known, retention/training controls, memory, expected output, cost/quota, consent validity, and expiry. `ASK_EVERY_TIME` data requires fresh contextual consent. `LOCAL_ONLY` and `NEVER_AI` content and revealing derivatives are blocked.

Prompts, retrieval chunks, tool results, images, audio, filenames, metadata, and system diagnostics all count as exposure. Local preprocessing does not convert remote processing into local processing. The smallest sufficient context is sent, and unknown provider behavior is disclosed or blocks sensitive use.

## Evidence and control

Run records store references/categories and provider/model/adapter versions without duplicating sensitive content. Users can deny, reduce scope, revoke, and pursue provider deletion where available. Provider switching rechecks consent.

## Acceptance criteria

- Network traces match the disclosed destination and minimized payload.
- Retry, failover, specialist, tool-call, and background paths preserve permissions.
- Denial or outage leaves trusted local workflows intact.
