# File Encryption

## Scope

File encryption applies where policy requires protection beyond operating-system storage: exports, backups, sync packages, handoff packages, sensitive attachments, and temporary transfer artifacts. External source files such as an Obsidian vault remain user-owned and are not silently rewritten or encrypted.

## Envelope

An encrypted artifact records format and version, algorithm identifier, key reference—not the key—integrity/authentication data, creation purpose, data classification, retention, and compatible recovery instructions. Filenames and surrounding metadata are minimized because encryption of content alone does not hide access patterns.

Keys and passphrases use the Phase 38.06 boundary. Encryption and decryption occur in a trusted process with bounded plaintext lifetime. Partial output uses atomic replacement and cleanup; failure cannot replace a valid source with a corrupt artifact.

`RESEARCH REQUIRED`: approved formats, libraries, key derivation, password requirements, recovery, large-file streaming, metadata protection, and cross-platform interoperability. No custom cryptography.

## Acceptance criteria

- Tamper, wrong-key, interrupted-write, large-file, and cross-platform tests pass.
- Unencrypted originals are not deleted until encrypted output is verified.
- Sharing UX clearly distinguishes encrypted content from exposed metadata.
