# Threat Model

## Assets

Protected assets include canonical records, private notes and routines, academic marks, money data, source files, AI context and memory, credentials, encryption/signing keys, backups, sync history, permissions, provenance, audit evidence, and product integrity.

## Adversaries and failures

Model malicious local users or malware, stolen/unlocked devices, compromised accounts/providers/dependencies, hostile imported files and notes, prompt injection, network interception, forged callbacks, supply-chain tampering, insider access, accidental disclosure, insecure backups, log leakage, corruption, and user error.

## Trust boundaries

Review UI-to-privileged bridges, worker/sidecar processes, local database and files, OS secret storage, Obsidian roots, local AI runtimes, integrations, network queues, cloud sync, remote AI, notifications, exports, installers, updates, and support diagnostics.

## Method

For each data flow record assets, actors, entry points, assumptions, threats, likelihood, impact, existing controls, residual risk, owner, test, and review trigger. Apply spoofing, tampering, repudiation, information disclosure, denial of service, privilege escalation, and privacy-abuse analysis where relevant.

`RESEARCH REQUIRED`: approve the formal methodology, risk matrix, security baselines, and review cadence.

## Acceptance criteria

- Threats map to controls and executable verification.
- New providers, permissions, data zones, and privileged bridges trigger review.
- High residual risks cannot ship without explicit time-bounded acceptance.
