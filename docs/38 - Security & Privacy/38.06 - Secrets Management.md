# Secrets Management

## Secret classes

Secrets include passwords, API keys, OAuth tokens, session secrets, private encryption/signing keys, recovery codes, database keys, webhook secrets, and credentials granting authority. They are mandatory `NEVER_AI`.

## Storage and access

Store secrets in approved OS or managed secret stores using opaque references in application configuration. Access is least-privilege, purpose-scoped, short-lived in memory, and unavailable to UI renderers, ordinary workers, logs, analytics, exports, prompts, support bundles, and crash reports.

Never hard-code production secrets, commit them to source, pass them through command lines where observable, or reuse them across environments. Use separate development, test, and production credentials. Rotation, expiry, revocation, account disconnect, backup exclusions, and emergency invalidation are documented.

Secret detection scans source, artifacts, logs, fixtures, and packages. Suspected exposure triggers immediate containment and rotation; deleting a leaked value from history does not make it safe again.

`RESEARCH REQUIRED`: select platform stores, CI/release secret service, access broker, rotation cadence, and recovery process.

## Acceptance criteria

- Secret-seeded tests show no log, export, AI, telemetry, or package exposure.
- Revoked and expired credentials fail closed.
- Builds and tests run with replaceable non-production secrets.
