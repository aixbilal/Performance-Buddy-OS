# Cloud Security

## Scope

Cloud security applies only to optional `CLOUD` services and never converts them into a prerequisite for CORE. It covers identity, authorization, device registration, network boundaries, data storage, keys, provider operations, audit, deletion, backup, and incident response.

## Controls

Use authenticated encryption in transit, encryption at rest, least-privilege service identities, environment and tenant isolation, scoped authorization, secure secret/key management, input and webhook validation, rate and abuse controls, dependency and image scanning, hardened configuration, protected deployment, audit trails, and monitored integrity/availability signals.

Data minimization and zone enforcement occur before upload. Cloud operators and services cannot silently claim semantic authority. Device revocation, session invalidation, key rotation, export, deletion, provider outage, quota, and regional/retention commitments require tested procedures.

End-to-end encryption can change search, conflict handling, recovery, and key enrollment; the implemented boundary must be disclosed accurately.

`RESEARCH REQUIRED`: cloud provider, regions, identity, key service, network design, compliance targets, monitoring, retention, and end-to-end feasibility.

## Acceptance criteria

- Tenant/access, revoked-device, replay, tamper, outage, backup, and deletion tests pass.
- Cloud loss cannot erase authoritative local data.
- Deployment configuration is reproducible, reviewed, and least-privilege.
