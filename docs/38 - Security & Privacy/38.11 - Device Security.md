# Device Security

## Device posture

Desktop and mobile clients use OS protections available on supported platforms: per-user storage, screen/device lock guidance, secure key storage, signed updates, sandboxing/process isolation, permission prompts, and protected notifications. The product does not claim to defeat a fully compromised administrator/root environment.

## Registration and lifecycle

Cloud-enabled installations receive opaque IDs and cryptographic credentials. User-visible device names are descriptive only. States include pending, active, suspended, revoked, and retired. Enrollment is authenticated and replay-resistant; rotation preserves domain identity.

Revocation stops future cloud access and key use promptly but cannot promise remote wipe or silently erase local data. Lost-device response includes session invalidation, device revocation, credential/key rotation, recent-activity review, backup assessment, and clear disclosure of residual local exposure.

## Local protections

Sensitive previews are hidden by default. Biometric unlock delegates to approved OS APIs and has a secure fallback. Clipboard, screenshots, backups, debugging, rooted/jailbroken devices, and developer mode receive explicit risk decisions.

## Acceptance criteria

- Revoked credentials and replayed enrollment fail closed.
- Lock-screen, backup, clipboard, and notification leakage tests pass.
- Device compromise guidance distinguishes implemented control from recommendation.
