# 25.03 — Local vs Cloud Decision Boundary

## Decision order

Choose execution location per AI application and run, after permissions and before content leaves its source boundary. The decision considers privacy policy, user preference, required capability, measured quality, device readiness, latency, energy, availability, and cost.

## Boundary matrix

| Condition | Required behavior |
|---|---|
| Local model meets all gates | Prefer local when user settings permit |
| Remote processing prohibited | Local or deterministic/manual fallback only |
| Local quality below required threshold | Do not use it for that task |
| Device lacks resources | Offer fallback without destabilizing CORE |
| Cloud could materially improve result | Explain data exposure and obtain scoped consent |
| Network/provider unavailable | Local if qualified; otherwise manual/CORE path |

`CLOUD` is optional and never a hidden continuation of a failed local run. Consent to sync, backup, or general AI does not authorize remote inference for a data category. A provider switch must preserve application requirements and disclosure.

## Mixed execution

Hybrid retrieval may keep indexing local while sending only selected passages remotely, but this is still `CLOUD`; permissions apply before selection, content is minimized, and exposure is logged. Local preprocessing must not create a misleading privacy claim.

## Acceptance criteria

- The execution decision and reason are auditable.
- No automatic fallback weakens privacy, capability, or cost constraints.
- Airplane-mode and remote-denial tests preserve supported local/CORE workflows.
