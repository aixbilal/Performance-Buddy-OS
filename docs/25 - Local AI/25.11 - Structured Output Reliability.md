# 25.11 — Structured Output Reliability

## Goal

Local models must meet the same Phase 24.05 contract as remote adapters. Smaller models or constrained runtimes receive no relaxed authority merely because they run privately.

## Reliability pipeline

Prefer runtime-enforced grammar or schema decoding when supported. Then parse strictly, validate schema/version/types/ranges, resolve references, verify evidence, recompute deterministic values, and apply Phase 23 rules. Record first-pass validity separately from repaired validity.

A single bounded repair attempt may fix syntax or schema shape only when no side effect occurred and the application permits it. Repair cannot add unsupported facts, hide missing evidence, or increase authority. Repeated failure triggers a deterministic/manual fallback.

## Measurements

Track first-pass parse rate, schema adherence by field, semantic validity, invented identifier rate, evidence-link validity, repair success, latency, and failure by input length and hardware tier. Passing JSON syntax alone is insufficient.

## Acceptance criteria

- Mandatory thresholds are task- and consequence-specific and set before release.
- Malformed, truncated, extra-field, wrong-version, and adversarial outputs fail safely.
- No model output reaches a domain command without independent validation and applicable approval.
