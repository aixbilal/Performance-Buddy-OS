# 25.09 — Extraction

## Scope

Local extraction proposes structured fields from user-selected text, images already processed into permitted text, notes, or imported records. Typical fields include dates, durations, marks, task names, amounts, units, topics, and references.

## Output contract

Every field carries raw source span, normalized candidate, type, confidence, and transformation notes. The result also identifies missing required fields, conflicts, and unreadable regions. Absence is represented explicitly; the model must not fill gaps from plausibility.

## Validation

Schemas enforce types, ranges, locale, currency, timezone, and unit rules. Domain services verify identifiers and recompute derived values. Consequence controls review: academic marks, financial amounts, deadlines, health-related signals, and bulk imports require visible verification before commit. Original evidence remains linked to the accepted record.

One bounded repair pass may correct format only; it cannot manufacture evidence. OCR, if later supported, is a separate fallible source stage and must expose its confidence.

## Acceptance criteria

- Benchmarks report exact match, normalized match, omission, and invented-field rates.
- Locale, decimal, date, currency, negation, table, and adversarial-text cases are tested.
- Failed extraction preserves the source and offers manual entry.
