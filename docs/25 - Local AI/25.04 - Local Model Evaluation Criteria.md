# 25.04 — Local Model Evaluation Criteria

## Qualification dimensions

A model is approved per task—not globally. Evaluation covers task accuracy, schema adherence, calibration, grounding, injection resistance, unsafe output, language coverage, latency, memory use, sustained thermals, energy, package size, license, provenance, update policy, and runtime compatibility.

## Task-specific evidence

Command parsing emphasizes intent/slot accuracy and safe ambiguity. Classification uses per-class precision, recall, imbalance behavior, and abstention. Extraction measures exact and normalized field scores plus invented-field rate. Retrieval measures recall, ranking quality, citation correctness, and permission isolation. Structured output measures parse success before and after the single allowed repair path.

## Release rules

Test on representative user data that is consented, minimized, de-identified where possible, and separated from tuning. Report results by hardware tier, model/version, quantization, runtime, prompt/schema, language, and workload length. Average scores cannot hide safety-critical class failures.

Licensing and model provenance must permit intended distribution and use. Artifact hashes and a software bill of materials are required before installation approval.

## Acceptance criteria

- Thresholds are defined before comparison and map to feature consequence.
- A model failing any mandatory safety, permission, or reliability gate is not promoted.
- Results are reproducible and feed Phase 24.17 evaluation evidence.
