# 25.02 — Local AI Responsibilities

## Owned responsibilities

Phase 25 owns local model/runtime selection criteria, device qualification, resource budgets, lifecycle management, inference adapter behavior, local task benchmarks, model artifact integrity, and graceful fallback.

Eligible workloads include bounded command interpretation, classification, field extraction, lightweight transformation, embeddings, reranking, and source-grounded response drafting when evaluation thresholds are met.

## Responsibilities retained elsewhere

- Phase 04 domain services own facts and commands.
- Phase 16 owns vault permissions, file watching, lexical indexes, and index recovery.
- Phase 23 owns deterministic rules, protected constraints, validation, overrides, and reason codes.
- Phase 24 owns prompts, schemas, tools, memory, run lifecycle, provider abstraction, budgets, and release gates.
- Phase 31 owns security implementation and threat controls.

## Operational duties

The local subsystem verifies model artifacts, reports readiness, observes resource limits, supports cancellation, isolates failures, records redacted run metadata, and removes derived caches when permission or model versions change. It must not scan arbitrary files or start persistent inference without a declared feature purpose.

## Acceptance criteria

- Each component has one documented owner and interface.
- Local AI cannot bypass a domain API or Phase 24 run lifecycle.
- Installation, update, disablement, cache purge, and uninstall behavior are testable.
