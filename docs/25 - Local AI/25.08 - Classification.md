# 25.08 — Classification

## Scope

Local classification assigns one or more labels from a versioned, application-owned taxonomy—for example note type, command family, expense-category suggestion, or study-topic candidate. Labels are proposals unless the domain explicitly defines a low-consequence auto-accept rule validated by Phase 23.

## Contract

Results include taxonomy/version, candidate labels, calibrated scores where meaningful, evidence spans or features, abstention reason, model/runtime version, and input revision. The classifier cannot invent labels outside the taxonomy.

## Reliability rules

Evaluate each class separately, including rare and sensitive classes. Define acceptance, review, and abstention thresholds from consequence and measured calibration. Multi-label and mutually exclusive taxonomies declare different validation. User correction is stored as domain evidence only with normal consent; it is not silently reused as global training data.

Sensitive inference is prohibited unless the application purpose, consent, and boundary documents explicitly permit it. Classification cannot convert private content into a broader-access metadata leak.

## Acceptance criteria

- Confusion matrices and per-class metrics are versioned by representative dataset.
- Low-confidence and out-of-scope inputs abstain safely.
- Permission tests ensure labels and logs do not reveal inaccessible source content.
