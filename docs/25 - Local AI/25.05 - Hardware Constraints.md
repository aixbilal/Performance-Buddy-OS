# 25.05 — Hardware Constraints

## Principle

Local AI adapts to the device; the product does not assume a dedicated GPU or consume resources without limits. Exact supported tiers are `RESEARCH REQUIRED` until benchmarks establish them.

## Readiness profile

At minimum, qualification records operating system and architecture, CPU instruction support, available and total memory, supported GPU/backend and memory, free storage, power state, thermal behavior, runtime compatibility, and user-configured limits. Raw hardware details remain local unless diagnostic sharing is explicitly enabled.

## Resource policy

- Reserve memory and compute for CORE responsiveness.
- Use bounded context, batch size, concurrency, threads, and cache.
- Pause or reduce optional work on battery, thermal pressure, low memory, focus activity, or interactive load.
- Never download a model that exceeds declared storage policy without confirmation.
- Unload idle models according to a configurable policy.
- Cancel cleanly and release resources after failure.

Readiness is rechecked after runtime, driver, model, or major system changes. Benchmark eligibility is distinct from real-time availability.

## Acceptance criteria

- Unsupported devices see a clear fallback, not crashes or endless loading.
- Resource stress tests preserve data integrity and CORE response targets.
- Storage estimates, download size, memory expectation, and removal controls are shown before installation.
