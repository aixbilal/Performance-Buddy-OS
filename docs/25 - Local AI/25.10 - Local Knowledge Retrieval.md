# 25.10 — Local Knowledge Retrieval

## Architecture

Local retrieval builds on Phase 16’s permission-partitioned, disposable indexes and Phase 15’s source model. Lexical search remains the offline CORE baseline. `LOCAL` may add on-device embeddings, semantic candidates, reranking, or source-grounded synthesis after evaluation.

## Query flow

Apply permissions before search; select eligible source collections; retrieve lexical and optional semantic candidates; combine them with an explainable strategy; return bounded passages carrying source ID, revision/checksum, location, authority, timestamp, score, and match reason. Permissions are checked again before context assembly.

## Index rules

Embedding records include chunk and source checksums, model/version, dimensions, normalization, index generation, and privacy partition. Incompatible vectors never mix. Source change, permission revocation, model change, or deletion invalidates affected projections. Indexes are rebuildable and never modify vault files.

Generated answers cite local passages and disclose insufficient, stale, or conflicting evidence. Retrieved text is untrusted data and cannot override system/application instructions.

## Acceptance criteria

- Disabling semantic retrieval leaves complete lexical search available.
- Permission leakage, stale vectors, empty results, conflicts, and injected instructions are tested.
- Benchmark evidence justifies semantic/reranking promotion on each supported hardware tier.
