# 29.22 - Provider Assignment & Failover
## Assignment order

For each invocation, filter providers by data permission, locality, required capability, structured-output reliability, and policy. Rank eligible options using user preference, offline state, task risk, evaluated quality, latency, health, and cost/budget. Agent identity remains unchanged.

## Failover

Classify authentication, permission, rate-limit, timeout, outage, malformed output, safety refusal, and capability mismatch. Use bounded retry only when safe and idempotent. Fail over to another approved endpoint/provider or local/deterministic mode only if privacy and capability requirements still hold. Material degradation is disclosed; consequential output is revalidated.

Routing never rotates keys to evade quota, provider terms, regional controls, or safety enforcement. Credential selection is explicit and auditable.

## Acceptance criteria

- Provider outage preserves identity, permissions, correlation, and audit history.
- No remote fallback receives data classified local-only.
- Structured-output failure cannot reach synthesis as valid evidence.
- Exhausted options fail safely with actionable status.
