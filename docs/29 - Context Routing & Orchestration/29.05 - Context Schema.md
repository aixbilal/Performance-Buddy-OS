# 29.05 — Context Schema

## Required envelope

The context envelope includes schema/version, run/application/capability, objective, horizon, locale/timezone, permission and consent references, source items, domain summaries, deterministic measures, governed memory references, user-confirmed preferences, constraints, assumptions, conflicts, missing data, freshness, trust classification, budget, and redaction metadata.

## Source item fields

Each item carries stable source/entity ID, owner domain, revision/checksum, authority class, captured/effective time, location, sensitivity, permitted purpose, content or bounded reference, derivation method, confidence where derived, and expiry.

## Versioning

Schemas are immutable and semantically versioned. Major changes are incompatible; compatible additive fields require explicit unknown-field policy. Historical checkpoints retain their original schema and migration record. Validation checks types, ranges, identifiers, enums, cross-field invariants, size, and permission partitions.

## Acceptance criteria

- Invalid, unknown, oversized, stale, or unauthorized fields fail before inference.
- Fixtures cover each capability and sensitive-data exclusion.
- Schema validation proves structure, not semantic truth; CORE/source checks remain required.
