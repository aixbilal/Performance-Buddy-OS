# 29.19 - Agent-to-Agent Communication
## Communication contract

Agents communicate through typed consultation envelopes, not unrestricted shared chat. Each envelope records correlation ID, sender, recipient, purpose, permitted context references, question, output schema, deadline/budget, provenance requirements, and retention class.

Recipients may answer, refuse for insufficient permission/evidence, or request a scoped clarification through the orchestrator. Messages cannot broaden scope, grant tools, transmit credentials, include never-AI data, or trigger side effects. Raw private reasoning is neither requested nor stored; concise findings and evidence are.

Communication improves application context and recommendations through approved records and summaries. It does not retrain participating models. The Head Coach receives specialist results and owns synthesis before rules validation.

## Acceptance criteria

- Permission checks occur on every message boundary.
- Loops, fan-out, token use, retries, and time are bounded.
- Replayed or duplicate messages cannot duplicate actions.
- Audit views show who consulted whom and which evidence influenced the proposal.
