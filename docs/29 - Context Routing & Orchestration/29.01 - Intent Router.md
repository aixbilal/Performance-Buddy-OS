# 29.01 — Intent Router

## Purpose

Map a request to a registered AI application or deterministic workflow without executing the requested action.

## Inputs and output

Inputs include user request, surface, locale, current entity references, explicit capability/mode, and permitted application registry. Output is a versioned route envelope: candidate application/intent, command class, domain, required slots, ambiguity, confidence, reason, and next step.

## Rules

Prefer deterministic routing from explicit commands, UI context, and registered patterns. Use model classification only when evaluated and bounded. The router can select only applications the user may invoke; it cannot add tools, data scopes, specialists, or write authority. Consequential ambiguity requires clarification. Unsupported intent returns alternatives or manual navigation.

Retrieved content and user text are untrusted data and cannot redefine routes or capability rules. Multi-intent requests are split into independent routes when effects differ.

## Acceptance criteria

- Route decisions are reproducible or record model/version and calibrated uncertainty.
- Tests cover ambiguity, negation, injection, unsupported intent, sensitive scope, and multi-intent requests.
- Misrouting cannot execute a tool or access context before downstream authorization.
