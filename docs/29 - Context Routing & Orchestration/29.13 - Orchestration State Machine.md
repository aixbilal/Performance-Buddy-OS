# 29.13 — Orchestration State Machine

## States

`RECEIVED → ROUTED → AUTHORIZED → CONTEXT_READY → MODEL_SELECTED → RUNNING → OUTPUT_VALIDATED → RULE_VALIDATED → AWAITING_APPROVAL → COMMITTING → COMPLETED`

Terminal/alternate states are `NEEDS_CLARIFICATION`, `PAUSED`, `CANCELLED`, `EXPIRED`, `REFUSED`, `FAILED`, and `COMPLETED_WITHOUT_COMMIT`.

## Transition contract

Each transition declares source/target, actor, guard, input/output schema, permission check, budget effect, timestamp, idempotency key, retry policy, checkpoint policy, and emitted audit event. Only domain command handlers enter `COMMITTING`; model/specialist steps cannot.

Authorization, context, and rule validation are rechecked after resume or material state change. Cancellation blocks new tool calls and commits. Unknown or invalid state fails closed. Concurrent workers acquire a lease and compare state versions.

## Acceptance criteria

- A generated transition table has no unauthorized skip or unreachable required state.
- Property tests cover duplicates, reordering, crashes, lease expiry, stale approval, and cancellation races.
- Every terminal state releases resources and accurately reports whether any commit occurred.
