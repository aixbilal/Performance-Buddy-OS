# 29.09 — Sequential Specialist Pipeline

## Purpose

Coordinate bounded specialist stages when evaluation proves one call cannot satisfy a V3 task safely or accurately.

## Pipeline

`plan → permission/context gate → specialist stages → deterministic validation → manager synthesis → recommendation validation → approval handoff`

Each stage has a versioned contract, allowed input partitions, tools, output schema, budgets, timeout, retries, and fallback. Stages consume typed artifacts, not uncontrolled conversations. Later specialists cannot rewrite earlier output; they append critiques or alternatives. Independent read-only stages may run in parallel only when ordering and side effects are irrelevant.

The pipeline is finite and declared before execution. Specialists cannot spawn specialists, expand domains, create memory, approve, or commit. Failure can skip an optional stage only when the application contract defines a safe degraded result.

## Acceptance criteria

- End-to-end and per-stage tests cover disagreement, malformed output, timeout, cancellation, and permission isolation.
- Ablation evidence justifies every specialist stage.
- Pipeline replay never duplicates tool effects or turns partial output into a write.
