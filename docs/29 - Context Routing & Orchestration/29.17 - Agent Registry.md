# 29.17 - Agent Registry
## Registry contract

The Agent Registry is the application source of truth for agent ID, role, visibility, persona version, objectives, allowed task classes, tool grants, memory scopes, consultation permissions, output schema, escalation path, and lifecycle state. Provider/model/key mappings are separate runtime references.

Required persistent entries are Performance Guide / Head Coach, Culture & Knowledge Guide, and Growth & Communication Guide. Hidden entries initially include Academic, Development, Recovery, Language, and Research specialists; future specialists use the same registration and review process.

## Rules

Only enabled, version-compatible agents may be invoked. Registration cannot grant data or tools beyond Phase 30 policy. The Head Coach is the sole default synthesizer. Registry changes are versioned, validated, auditable, and cannot be authored by an agent itself.

## Acceptance criteria

- Duplicate IDs, missing schemas, excessive scopes, and circular escalation fail validation.
- Provider replacement requires no registry identity change.
- Disabled specialists cannot receive context or execute tools.
