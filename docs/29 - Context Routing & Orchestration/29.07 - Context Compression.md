# 29.07 — Context Compression

## Purpose

Reduce context size while preserving authority, constraints, provenance, conflicts, and task-relevant evidence.

## Methods

Prefer deterministic field projection, deduplication, normalized tables, source-referenced excerpts, time-bucket aggregation, and previously validated version-keyed summaries. Model-generated compression is derived evidence and must retain source links, uncertainty, method/model version, and expiry.

## Preservation rules

Never compress away protected constraints, permissions, negative evidence, material counterexamples, source conflicts, units, dates, or distinction between fact and inference. Quotations are bounded and traceable. Compression cannot convert missing information into a conclusion or merge incompatible metrics.

Compare compressed output with the source manifest using coverage, factual consistency, citation, constraint-retention, leakage, token reduction, and downstream task quality tests. If required information cannot fit safely, narrow the task or request a larger approved model/context rather than truncating silently.

## Acceptance criteria

- Compression artifacts are versioned, invalidated by source change, and reproducible where deterministic.
- Adversarial tests protect constraints, conflicts, negation, and rare critical facts.
- Uncompressed/source inspection remains available to validation and the user where permitted.
