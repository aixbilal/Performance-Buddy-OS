# 29.06 — Context Selection

## Principle

Select context for the declared purpose, not everything available. More context can increase privacy risk, distraction, cost, latency, and prompt-injection surface.

## Selection order

Apply permissions and exclusions; include required invariants/constraints; include current target entities; retrieve direct supporting evidence; add minimal user-confirmed preferences and governed memory; add cross-domain summaries only when the application explicitly requires them; then rank optional items by relevance, authority, freshness, coverage, diversity, and budget.

## Rules

Hard constraints and conflicting evidence cannot be removed merely to fit a budget. Summaries do not silently replace required primary evidence. Missing data is represented, not inferred. Sensitive money, prayer, reflection, smoking, nutrition, health-adjacent, and private routine data are excluded by default and purpose-specifically consented.

Selection produces inclusion/exclusion reason codes and a coverage report.

## Acceptance criteria

- Ablation tests measure quality and leakage as context changes.
- Data-rich domains do not automatically dominate cross-domain reasoning.
- Users can inspect included categories and revoke future use.
