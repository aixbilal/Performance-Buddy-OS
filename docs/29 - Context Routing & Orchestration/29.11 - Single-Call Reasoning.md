# 29.11 — Single-Call Reasoning

## Purpose

Use one bounded inference call when a complete permissioned context and schema can answer the task without iterative tool discovery or specialist decomposition.

## Eligible cases

V1 explanations/classification/drafts, bounded V2 interpretation of precomputed analytics, and standard V3 scenario selection may qualify when context fits, tools are unnecessary or precomputed, output validation is strong, and evaluations meet thresholds.

## Flow

Build/freeze context; select model; invoke once with versioned prompt/schema; validate structure, provenance, references, and deterministic facts; apply Phase 23; then return answer/proposal. A formatting repair counts as a separately bounded operation and cannot add facts.

Single-call mode cannot hide multiple autonomous subcalls inside a provider feature. If evidence is insufficient, it abstains or routes to an explicitly approved sequential/deep workflow; it does not silently escalate.

## Acceptance criteria

- Single-call baselines are measured before more complex orchestration is adopted.
- Quality, schema, injection, latency, cost, and failure thresholds pass.
- Failure or truncation produces no tool effect or trusted mutation.
