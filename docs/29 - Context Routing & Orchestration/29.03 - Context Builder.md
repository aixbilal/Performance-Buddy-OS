# 29.03 — Context Builder

## Purpose

Assemble the minimum authorized, provenance-rich information required for one application run.

## Build sequence

Validate purpose and permission; load the application context contract; request fields through owner APIs; retrieve eligible evidence; normalize into the context schema; attach provenance and trust labels; enforce token/data budgets; redact secrets and unrelated sensitive fields; validate; then freeze a context-manifest revision.

## Rules

Context, data, tools, and memory remain distinct. Presence in source data does not justify inclusion. Presence in context does not authorize persistent memory or tool execution. Derived summaries link to sources and state confidence/expiry. Retrieved notes, webpages, and tool results are untrusted content, not instructions.

The builder does not query arbitrary database tables or filesystem paths. Permission is enforced before retrieval and before final assembly. Empty or conflicting evidence stays visible.

## Acceptance criteria

- Every item can explain why it was included and which rule allowed it.
- Snapshot tests verify schema, ordering, redaction, budgets, and provenance.
- Permission revocation or source change invalidates affected contexts/checkpoints.
