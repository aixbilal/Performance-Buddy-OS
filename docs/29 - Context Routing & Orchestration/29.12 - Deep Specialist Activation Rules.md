# 29.12 — Deep Specialist Activation Rules

## Eligibility

Activate deep specialists only for an approved V3 application when task complexity, domain breadth, conflicts, horizon, or evaluation evidence shows standard/native reasoning is insufficient. Deep mode is never inferred solely from a long message or user anxiety.

## Required gates

Confirm explicit user opt-in; objective and horizon; required domains/data categories; sensitive consent; standard-mode insufficiency reason; expected specialists; provider/location; time/token/cost/tool budgets; checkpoint/retention policy; cancellation; and fallback.

## Prohibitions

Activation cannot expand permissions, bypass provider consent, relax constraints, create an unbounded agent loop, or grant specialists tools beyond their manifests. A specialist may be skipped when evidence is missing; orchestration cannot manufacture context to keep the pipeline running.

Activation and refusal reason codes are stored. The user can choose a narrower standard analysis.

## Acceptance criteria

- Tests cover hidden escalation, sensitive scope, budget limits, cancellation, and unavailable specialists.
- Evaluations demonstrate material benefit for each activated task class.
- Activation never changes write/approval authority.
