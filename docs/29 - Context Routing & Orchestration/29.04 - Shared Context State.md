# 29.04 — Shared Context State

## Definition

Shared context state is the typed, run-scoped workspace passed between authorized orchestration steps. It is not global mutable memory, a chat transcript, or a source of truth.

## Partitions

State separates immutable run manifest, permission snapshot, user objective, context references, derived measures, assumptions, tool results, specialist outputs, validation results, budgets, and pending proposal. Each partition has an owner and write policy.

## Mutation rules

Steps append versioned artifacts or replace only explicitly mutable orchestration fields using compare-and-swap/version checks. Facts are referenced from domain sources; specialists cannot overwrite one another or the evidence partition. Sensitive partitions are available only to declared steps. Free-form model text never becomes control state without schema validation.

State has run TTL, encryption/secure-storage policy, redacted observability representation, and cleanup status. Promotion to persistent memory follows Phase 24.10 separately.

## Acceptance criteria

- State transitions are typed, attributable, ordered, and replay-safe.
- Permission and specialist isolation tests prevent lateral data leakage.
- Cleanup removes transient content while retaining only governed audit metadata.
