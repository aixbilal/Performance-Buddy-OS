# 29.16 — LangGraph Evaluation Criteria

## Status

LangGraph is a named candidate, not an approved dependency. Its current capabilities, license, supported runtimes, APIs, persistence behavior, and maintenance status are `RESEARCH REQUIRED` at evaluation time from primary documentation and a pinned prototype.

## Evaluation scope

Apply all criteria in 29.15, with specific tests for typed graph/state representation, conditional routing, durable checkpointing, resumability, interrupts/human approval, cancellation, retries, idempotent tools, streaming, subgraph/specialist isolation, concurrent runs, schema migration, observability, local model adapters, provider neutrality, and storage/security boundaries.

## Prototype scenarios

Implement one V1 proposal/approval flow, one scheduled V2 analysis, one standard V3 route, and one bounded deep-specialist pipeline. Inject crashes before/after tool calls and approval; revoke permissions; change source versions; cancel; exhaust budgets; migrate a checkpoint; and remove the framework behind the project adapter.

## Decision rule

Adopt only if evidence shows material net benefit over native orchestration without unacceptable lock-in or safety regression. Pin versions and adapters; never let graph objects enter domain contracts. Otherwise retain native orchestration and record reassessment triggers.

## Acceptance criteria

- Evaluation uses current primary-source evidence and reproducible prototype results.
- Every mandatory safety/recovery test passes; feature breadth alone cannot compensate.
- The decision includes upgrade, rollback, checkpoint migration, and exit plans.
