# Background Processes

## Scope

Background processes may run timers, recurrence and reminders, index refresh, file watching, backup triggers, sync retries, retention work, and approved local-AI tasks. Each job retains the Phase 33 scheduler contract: stable identity, owner, schedule, constraints, misfire policy, priority, lease, idempotency key, attempts, result, and cancellation.

## Execution rules

Workers are supervised, observable, resource-bounded, and isolated from the UI. They invoke application commands rather than writing domain tables directly. Concurrent instances use leases or equivalent coordination. Restart, sleep, clock or timezone change, battery saver, thermal pressure, and shutdown apply declared policies.

Network-dependent jobs queue or fail visibly and never block local jobs. Background AI can create analysis or proposals within permission but cannot silently commit them. Repeated failure uses bounded backoff and a visible terminal state, not a wake or retry storm.

OS background execution is best-effort; persisted schedule truth remains local and reconciles when the app resumes.

## Acceptance criteria

- Duplicate trigger and process-crash tests produce no duplicate side effects.
- Users can inspect, pause, retry, or cancel eligible work.
- Worker failure cannot corrupt canonical data or freeze CORE.
