# Desktop Architecture Requirements

## Required architecture

The desktop implementation must provide:

- a clear split among presentation, application commands, domain rules, infrastructure adapters, and privileged OS bridges;
- durable offline startup and local database access;
- least-privilege filesystem, notification, shortcut, tray, and network permissions;
- typed, versioned inter-process messages with sender validation and bounded payloads;
- crash isolation for optional AI, indexing, sync, and background workloads;
- accessible, responsive rendering on supported displays and scale factors;
- deterministic command handling independent of renderer state;
- structured redacted diagnostics, health checks, cancellation, and recovery;
- secure configuration and secret storage;
- testable adapters and replaceable framework-specific edges.

## Security boundary

Untrusted note content, imported files, links, and AI output never gain executable privilege. Web-style renderers use isolation, restricted navigation, no arbitrary code evaluation, and a narrow allowlisted bridge.

## Performance

CORE responsiveness takes priority over indexing, sync, animation, and local AI. Resource budgets and representative datasets require measured acceptance thresholds.

## Acceptance criteria

- Threat modeling covers renderer compromise and privileged-bridge abuse.
- Optional worker failure cannot corrupt the canonical store.
- Architecture tests enforce dependency direction and message validation.
