# Keyboard Shortcuts

## Architecture

Every shortcut maps to a stable command ID shared with the command palette. Commands declare scope, availability, default binding, conflicts, permissions, and whether global OS registration is requested.

## Rules

- Global shortcuts are few, user-visible, configurable where feasible, and disabled when denied or conflicting.
- Contextual bindings never override text entry, input methods, browser conventions needed by the shell, operating-system accessibility, or assistive technology.
- Destructive actions have no easy single-key binding.
- Tab and arrow behavior follows established control conventions; Escape cancels safely without silent data loss.
- Reordering, drag operations, charts, and pointer gestures have keyboard alternatives.
- Shortcut help is searchable and reflects the active context and actual bindings.

Registration and unregistration are idempotent across startup, settings changes, suspend/resume, and multiple instances. A failed global registration degrades to an in-app path.

## Acceptance criteria

- End-to-end keyboard tests cover planning, sessions, capture, approval, settings, and recovery.
- Conflict detection prevents silent binding takeover.
- Focus returns predictably after dialogs, panels, and route changes.
