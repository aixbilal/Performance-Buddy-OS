# Electron Evaluation

## Candidate position

Electron may offer a mature Chromium/Node ecosystem, broad desktop APIs, established packaging, and strong web-development productivity. These are hypotheses to verify against current supported releases and the product's actual workloads.

## Required evaluation

Assess process sandboxing, context isolation, restricted preload bridges, navigation and permission handlers, content security policy, dependency exposure, update signing, native modules, database drivers, tray/notification behavior, accessibility, multi-window lifecycle, crash reporting, binary size, cold start, memory, battery, and renderer recovery.

The renderer must never receive unrestricted Node or filesystem access. Privileged operations use narrow typed IPC commands, validate origin and payload, apply domain authorization, and return bounded results. Imported Markdown and AI output are rendered as untrusted content.

## Risks

Primary risks include a large attack surface, supply-chain/native-module burden, resource use, insecure IPC, and framework updates. Mitigations require measurable tests, dependency policy, rapid security patching, and least privilege.

`RESEARCH REQUIRED`: benchmark the current stable Electron line and proposed plugins; no selection is approved here.

## Acceptance criteria

- Security checks demonstrate sandboxed renderers and an allowlisted bridge.
- Packaging and performance meet declared minimum-hardware targets.
- Native dependency and update risks have tested mitigations.
