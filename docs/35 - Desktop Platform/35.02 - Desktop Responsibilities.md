# Desktop Responsibilities

## Owned responsibilities

The desktop platform owns application startup and shutdown, shell routing, window lifecycle, OS permissions, local service composition, system integration, update and packaging hooks, accessibility bridge support, deep links, file dialogs, background-process supervision, tray integration, notification delivery, and shortcut registration.

## Delegated responsibilities

Domain services own business rules and entities. Phase 33 owns local authority and offline behavior; Phase 32 owns schemas; Phase 16 owns vault semantics; Phase 25 owns local-model policy; Phase 30 owns AI permissions; Phase 34 owns sync semantics. Desktop adapters invoke these contracts and present their outcomes.

## Prohibited responsibilities

UI components, tray handlers, notification callbacks, and background workers must not write directly to storage, invent domain state, bypass command validation, or silently approve AI actions. Platform telemetry cannot collect private content by default.

## Lifecycle obligations

Startup verifies configuration, database readiness, migrations, required paths, and recoverable prior work before accepting writes. Shutdown safely checkpoints durable work without falsely promising completion of remote or long-running tasks.

## Acceptance criteria

- Every OS entry point maps to an authorized application command.
- Platform failures are isolated from valid local records.
- Responsibility tests detect direct UI-to-database and worker-to-domain bypasses.
