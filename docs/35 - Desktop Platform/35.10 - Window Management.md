# Window Management

## Window model

The default experience uses one primary command-center window. Dialogs and supporting windows are added only when they improve a defined workflow. Multi-window, split-view, and multi-monitor expansion remain `RESEARCH REQUIRED`.

## State rules

Window geometry, display, safe route, and non-sensitive presentation preferences may persist. Restoration clamps windows to available displays and scale factors so they cannot reopen off-screen. Full-screen, focus mode, minimize, maximize, sleep/resume, display removal, and DPI changes preserve usable state.

Only one authoritative edit session may own a record at a time unless the domain supports explicit concurrency. Secondary windows cannot hide approvals, confirmations, errors, or unsaved changes. Closing the last visible window follows a declared platform policy and does not silently terminate active timers or lose durable queued work.

## Security and accessibility

New windows use the same sandbox and restricted bridge as the main renderer. Focus moves predictably, modal ownership is explicit, and closing returns focus to the invoker where possible.

## Acceptance criteria

- Restore works after monitor and scale changes.
- Duplicate windows cannot bypass edit or approval guards.
- Crash/restart restores only verified safe state.
