# System Tray & Quick Capture

## Purpose

The tray may provide fast access to open the command center, create a capture, inspect an active timer, pause or resume eligible sessions, and view scoped status. It is a convenience surface, not a second application authority.

## Capture contract

Quick capture records minimal user input durably into an inbox or explicit destination with timestamp, source surface, and processing state. Ambiguous text remains unclassified until the user or an approved rule resolves it. Capture never fabricates completion, evidence, priority, or domain meaning.

Tray commands use the same application command handlers, permissions, validation, and audit rules as the main window. Sensitive previews are hidden by default and configurable. Destructive or consequential actions open an appropriate confirmation surface.

## Lifecycle

Tray availability and close-to-tray behavior are platform-dependent, disclosed, and configurable. Multiple instances coordinate a single logical tray owner. If tray startup fails, the main application continues.

## Acceptance criteria

- Capture survives window closure and application restart after acknowledged success.
- Tray actions cannot bypass approval or validation.
- Keyboard and main-window alternatives exist for tray functionality.
