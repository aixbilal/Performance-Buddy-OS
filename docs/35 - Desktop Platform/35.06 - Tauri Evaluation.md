# Tauri Evaluation

## Candidate position

Tauri may provide smaller packages, a Rust privileged layer, and OS webview reuse. Benefits and limitations vary by operating system, webview, plugins, and current supported release, so they require direct testing.

## Required evaluation

Assess command and capability permissions, protocol and navigation restrictions, Rust boundary safety, plugin maturity, webview consistency, accessibility, database and filesystem plugins, tray/notifications/shortcuts, updater signing, deep links, multi-window behavior, local sidecars, local-AI process management, crash recovery, package size, startup, memory, and developer complexity.

The frontend receives only explicitly permitted commands. Rust commands validate payload, path scope, caller context, authorization, and response limits. Sidecars are pinned, authenticated where appropriate, supervised, and never trusted merely because they are local.

## Risks

Primary risks include platform webview differences, plugin gaps, Rust/toolchain complexity, sidecar packaging, and ecosystem changes. Each needs a tested mitigation or an accepted limitation.

`RESEARCH REQUIRED`: benchmark the current stable Tauri line and proposed plugins; no selection is approved here.

## Acceptance criteria

- Equivalent prototypes run on every proposed supported OS.
- Capability scoping prevents unintended privileged access.
- Webview and plugin gaps have evidence-backed dispositions.
