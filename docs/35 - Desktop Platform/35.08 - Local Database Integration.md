# Local Database Integration

## Integration contract

The desktop opens the canonical local database without network access through application repositories, never direct UI queries. Connections enforce Phase 33 integrity settings, prepared or typed access, transactions, revision recording, and audit/event consistency.

## Process ownership

`RESEARCH REQUIRED`: choose the exact database engine, driver, ORM/query layer, connection topology, and single-writer coordination. Any design must prevent renderer access to raw database credentials or files and handle multiple app instances safely.

Startup verifies schema compatibility, required migrations, integrity state, available disk space, and key access before accepting writes. Migration runs expose progress, cancellation boundaries, backup requirements, and recovery. The application never replaces an unreadable database with an empty one silently.

## Operational behavior

Long reads and maintenance work are cancellable and bounded. Disk-full, lock contention, power loss, corruption, and interrupted migration produce safe, actionable states. Consistent export and backup operate from verified snapshots.

## Acceptance criteria

- One business command commits data, revision, and audit records atomically.
- Crash and contention tests preserve integrity.
- Database failure cannot be hidden by an apparently usable empty workspace.
