# Local AI Integration

## Boundary

Local AI runs as an optional `LOCAL` capability behind the same structured tool, permission, validation, provenance, and approval contracts used by other AI providers. The desktop remains fully usable when no model is installed or hardware is unsupported.

## Runtime isolation

Model runtimes execute outside the UI thread and preferably in a supervised worker or sidecar. Requests have typed schemas, bounded context, cancellation, timeout, resource budgets, and correlation IDs. Outputs are untrusted until parsed, validated, and labeled with model and prompt versions.

Hardware readiness, model downloads, storage use, memory, thermal state, battery, privacy, and removal controls follow Phase 25. CORE work preempts or pauses AI under pressure. A failed or hung runtime is terminated without compromising local records.

No AI output directly commits meaningful changes. The desktop presents proposals and approvals according to Phase 30, and private context remains inside its approved data zone.

`RESEARCH REQUIRED`: runtime, process protocol, model formats, distribution, and benchmark tiers.

## Acceptance criteria

- Killing the AI worker leaves CORE responsive and data intact.
- Resource stress respects configured limits.
- Every output carries provenance and passes structured validation.
