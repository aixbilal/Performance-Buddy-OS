# Desktop Framework Evaluation

## Decision scope

The framework decision must support the approved product architecture rather than determine it. Electron and Tauri are initial candidates, but alternatives may be evaluated using the same evidence.

## Evaluation matrix

Compare supported operating systems and architectures, security model, process isolation, filesystem and database integration, background execution, tray/notification/shortcut APIs, accessibility, window behavior, updater and signing support, package size, startup time, memory and battery use, developer productivity, testing, debugging, ecosystem maturity, maintenance health, licensing, and migration risk.

Use representative prototypes: cold start; database-heavy Today view; vault indexing; timer across sleep/resume; tray capture; notification actions; local-AI worker; signed install/update; crash recovery; and accessibility navigation.

## Governance

Weighted criteria, benchmark hardware, test data, versions, measurements, known gaps, mitigations, and rejected alternatives belong in an approved architecture decision record. Popularity alone is not evidence.

`RESEARCH REQUIRED`: final framework, version, plugins, updater, and operating-system support matrix.

## Acceptance criteria

- Both leading candidates run equivalent risk-focused prototypes.
- Security and lifecycle blockers outweigh cosmetic convenience.
- The decision includes exit costs and a framework-boundary strategy.
