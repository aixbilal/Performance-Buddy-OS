# Filesystem Integration

## Boundary

Desktop filesystem access is provided through a privileged, allowlisted adapter. Users explicitly select roots or files; paths are canonicalized and checked against the approved scope on every operation.

## Security rules

Reject traversal, symlink or junction escape, alternate streams where applicable, device paths, unsupported types, and size-policy violations. Reading never executes macros, scripts, embedded commands, or imported content. Logs redact sensitive paths and content.

Obsidian indexing is read-only by default and follows Phase 16. Any future write requires separate approval, compare-before-write, exact diff preview, atomic same-directory replacement where supported, conflict detection, backup/recovery, and audit evidence.

## Reliability

File operations handle unavailable drives, permission change, concurrent edit, rename, delete, encoding errors, watcher overflow, sleep/resume, and removable media. Watchers are hints; periodic reconciliation detects missed events. Long work is cancellable and never blocks the UI thread.

## Acceptance criteria

- Security tests cover traversal and link escape on supported systems.
- Permission loss cannot cause destructive fallback or scope expansion.
- Concurrent external edits are preserved and surfaced.
