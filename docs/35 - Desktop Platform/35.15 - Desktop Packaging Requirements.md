# Desktop Packaging Requirements

## Release artifacts

Desktop packages are reproducible, versioned, integrity-verifiable, and built for an explicitly supported operating-system and architecture matrix. Artifacts include application binaries, required runtimes or sidecars, licenses, migration compatibility, and release notes without undeclared network installers.

## Security and trust

Production artifacts use platform signing and notarization where applicable, protected signing keys, dependency and malware scanning, software bills of materials, provenance, checksums, and verified update metadata. The updater validates signature, channel, version, compatibility, and rollback policy before installation.

## Installation lifecycle

Install, upgrade, downgrade refusal, repair, uninstall, and per-user/per-machine behavior are tested. Uninstall distinguishes application removal from user-data deletion and requires explicit consent for the latter. Updates do not erase local data, reset permissions, weaken sandboxing, or silently enable cloud/AI.

Database backup and migration precede breaking local changes; interrupted update recovery is documented and tested. Offline installers and export remain available according to release policy.

`RESEARCH REQUIRED`: package formats, updater, signing services, release channels, support matrix, and rollback mechanism.

## Acceptance criteria

- Clean install, upgrade, interrupted update, repair, and uninstall tests pass.
- Tampered or incompatible artifacts fail closed.
- Published artifacts can be traced to reviewed source and dependencies.
