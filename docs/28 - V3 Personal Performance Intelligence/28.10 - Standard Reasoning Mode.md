# 28.10 — Standard Reasoning Mode

## Purpose

Provide the default V3 experience for a bounded decision with controlled context, latency, and cost.

## Contract

Standard mode uses one declared objective, a limited horizon, permissioned domain summaries, deterministic measures, and a small alternative set. It runs through a single model call or native sequential pipeline unless tool results require a bounded continuation.

## Flow

Validate objective and permissions; assemble provenance-rich summaries; apply hard constraints; generate alternatives; invoke CORE validation; produce one recommendation and alternatives; disclose assumptions, uncertainty, and expiry; then route any proposed change to approval.

Standard mode does not silently switch to deep reasoning, add domains, create specialists, or exceed cost/time budgets. If evidence or complexity is insufficient, it requests clarification, returns a narrower result, or offers deep mode with an explicit scope/cost/privacy preview.

## Acceptance criteria

- Standard requests meet defined quality, latency, token/cost, and cancellation targets.
- The same manifest yields traceable, materially consistent results within evaluated variance.
- Failure degrades to V2/V1/CORE without mutation or hidden escalation.
