# 28.11 — Deep Reasoning Mode

## Eligibility

Deep mode is opt-in for complex, high-impact, long-horizon scenario comparison when standard mode cannot meet an evaluated need. It is not a “more correct” button and does not gain additional authority.

## Approval preview

Before running, show objective, domains/data categories, horizon, execution location/provider, expected time/cost range, memory behavior, specialist use if any, and cancellation route. Reacquire sensitive-category consent.

## Execution

Decompose bounded questions; gather evidence through permissioned tools; maintain an assumption and conflict register; generate independent scenarios; validate intermediate facts and final owner commands; synthesize; and stop at time, token, tool, retry, or evidence limits. Partial output is labeled and cannot commit.

Deep mode never exposes private chain-of-thought. User explanations provide evidence, concise reasons, assumptions, alternatives, and uncertainty. The user can cancel; cancellation prevents later commits.

## Acceptance criteria

- Evaluations show material benefit over standard mode for approved task classes.
- Deep runs obey fixed budgets, permissions, approval, and provider disclosure.
- Timeout, cancellation, specialist disagreement, and partial failure leave trusted data unchanged.
