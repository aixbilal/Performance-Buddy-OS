# 28.07 — Development Reallocation

## Purpose

Propose bounded capacity for development learning and projects when trajectory, deadlines, dependencies, or strategic opportunities justify it relative to other feasible work.

## Inputs

Learning paths, modules, practice/build evidence, project milestones, skill evidence, dependencies, recent load/neglect, portfolio commitments, user goals, academic risk, available windows, and recovery constraints.

## Rules

Development does not automatically lose to academics. If academic obligations are on trajectory and development has stalled, a meaningful development block may be highest value. Conversely, high-consequence exams/prerequisites can trigger a temporary maintenance plan. AI-assisted work and AI-off practice remain distinct evidence.

V3 recommends learn/practice/build actions tied to evidence, not vague coding time. It cannot claim mastery, invent portfolio deadlines, or replace user values with market assumptions. Any reduced domain and recovery impact is explicit.

## Acceptance criteria

- Reallocation respects Phase 18 dependencies, load management, and evidence semantics.
- Recommendations identify concrete output, duration, trade-offs, and review point.
- Tests prevent data-rich development records from gaining automatic priority.
