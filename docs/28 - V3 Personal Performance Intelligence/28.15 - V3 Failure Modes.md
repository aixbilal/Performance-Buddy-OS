# 28.15 — V3 Failure Modes

## Failure classes

Insufficient or biased evidence; stale/conflicting facts; permission leakage; unsupported causal inference; objective misspecification; value inference; constraint bypass; false precision; overcommitment; domain starvation; unsafe recovery advice; invented policy/calculation; specialist echo/chaining; manager overreach; provider/tool failure; runaway cost/latency; stale approval; and persuasive but ungrounded narrative.

## Containment

Fail closed for permissions, safety, constraints, validation, and uncertain writes. Bound context, tools, specialists, retries, time, and cost. Require counterexamples and alternative scenarios. Recompute facts through CORE. Preserve conflicts and abstain when evidence cannot distinguish choices. Never auto-fallback to broader cloud exposure or deeper mode.

## Recovery

Return `INSUFFICIENT_EVIDENCE`, `NO_FEASIBLE_OPTION`, `BOUNDARY_REFUSAL`, or a narrower V2/V1/CORE path. Preserve user input, discard uncertain partial actions, release resources, and record redacted diagnostics. Failure and rejection never reduce future user control or trigger pressure.

## Acceptance criteria

- Adversarial, chaos, counterfactual, permission, and protected-constraint suites cover every class.
- Ambiguous provider/tool outcomes cannot create duplicate or hidden writes.
- Kill switch and rollback disable V3 without damaging lower capabilities or records.
