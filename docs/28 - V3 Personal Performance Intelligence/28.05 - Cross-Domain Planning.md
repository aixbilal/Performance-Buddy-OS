# 28.05 — Cross-Domain Planning

## Purpose

Build a coherent proposal across approved domains while preserving each domain's owner, semantics, privacy, and independent measures.

## Planning flow

Collect authorized commitments, goals, deadlines, evidence, capacity, modes, and constraints; normalize only compatible units; generate domain-owned demand/options; reserve hard constraints; form scenarios; expose trade-offs and unknowns; validate every owner command; then synthesize a proposal.

## Rules

No universal score collapses grades, knowledge, coding, training, prayer, routines, language, and money. Cross-domain reasoning compares alternatives through explicit priorities and constraints, not moral totals. Richer data does not grant permanent priority. Missing data remains unknown and must not be imputed as low importance.

Private domains are excluded by default and purpose-specifically consented. Money remains a separate review domain and never an overall performance input. Each planned change is returned to its owner for validation and commit.

## Acceptance criteria

- Users can inspect, remove, or correct every included domain independently.
- Plans show capacity, displaced work, conflicts, and protected constraints.
- Domain failure yields partial/unavailable context, never fabricated defaults.
