# Milestone Trackers

## Purpose

A Milestone tracker records progress through meaningful checkpoints rather than daily repetition. It is suited to staged achievements with explicit evidence and ordering rules.

## Model

Each milestone has a stable ID, description, optional prerequisite links, target date, evidence requirement, and state. Milestones may be sequential, parallel, or independent. Progress percentages are derived from a declared weighting rule and never stored as unquestioned truth.

## Rules

- Completion requires the milestone’s own evidence contract.
- A later milestone does not automatically complete prerequisites.
- Reopening or correcting a milestone preserves revision history.
- Target dates support planning but do not alter factual state.
- Definition changes preserve the version used for past records.

## Ownership boundary

Phase 10 provides the reusable tracker shape. Phase 11 owns goal and system milestones; Development owns project milestones; Academic owns curricular and assessment checkpoints. Consumers reference the owner rather than redefine milestone meaning.

## Acceptance criteria

Dependencies are acyclic or explicitly rejected, progress calculations expose weights and inputs, overdue milestones are described neutrally, and no artificial daily streak is imposed.
