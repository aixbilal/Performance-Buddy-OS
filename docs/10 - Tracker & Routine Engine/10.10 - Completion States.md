# Completion States

## Canonical vocabulary

The shared states are `Complete`, `Partial`, `Deferred`, `Skipped`, `Excused`, `Rest`, `Maintenance`, `Not Applicable`, and `Unknown`. Owner domains declare which apply and may add detail without changing these meanings.

## Meanings

| State | Meaning |
|---|---|
| Complete | Defined requirement satisfied with proportionate evidence |
| Partial | Some useful portion completed, requirement not fully satisfied |
| Deferred | Intentionally moved to a future occurrence or plan |
| Skipped | Explicitly not done without an applicable excuse classification |
| Excused | Not expected because an approved context exception applies |
| Rest | Deliberate recovery or protected non-performance occurrence |
| Maintenance | Minimum useful action completed without full progression |
| Not Applicable | Occurrence does not apply under the governing rule |
| Unknown | No reliable factual state is available |

## Transition rules

State changes require an actor, timestamp, and reason where material. Automatic completion needs authoritative deterministic evidence. Overdue plus missing stays `Unknown`; it does not become `Skipped`.

## Acceptance criteria

Every displayed state maps to one canonical meaning, evidence remains linked, corrections are auditable, and planning or analytics does not collapse legitimate states into a misleading binary.
