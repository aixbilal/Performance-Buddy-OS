# 06.15 - Companion Interaction Model
## Purpose and ownership

Define how the three persistent visible companions appear, preserve identity, share the interface, and remain subordinate to user control. This document owns interaction behavior, not model routing, memory storage, visual tokens, or deterministic planning.

## Persistent companions

- **Performance Guide / Head Coach** is the single foreground coordinator. It frames priorities, requests specialist consultation, synthesizes disagreements, and presents one coherent proposal.
- **Culture & Knowledge Guide** supports general knowledge, culture, curiosity, reading, and broad learning connections.
- **Growth & Communication Guide** supports languages, communication practice, self-expression, and interpersonal growth.

Each companion is an agent identity: role, persona, memory scope, tools, objectives, and permissions. It is not a provider, model, endpoint, project, or API key. A provider change must not change the companion's name, history, permissions, or visible relationship with the user.

## Interaction rules

The user may address a companion directly or let the Head Coach route a request. Hidden specialists may be consulted, but their findings return through the Head Coach unless the user explicitly opens specialist detail. Responses distinguish verified facts, inferred context, and suggestions. Proposed schedule or record changes follow **AI suggests → rules validate → human decides**.

Companions may remember only policy-approved information. Local operation remains useful when cloud providers are unavailable; degraded mode must be stated calmly. No character may imply consciousness, dependency, authority over the user, or guaranteed outcomes.

## Acceptance criteria

- The same companion identity survives model/provider/key replacement.
- Only one synthesized recommendation reaches rules validation and user review.
- Direct specialist access cannot bypass permissions, validation, or approval.
- Focus Mode, offline state, uncertainty, and data disclosure are visible when relevant.
