# Desktop Interaction Model

## Purpose

Define keyboard-efficient desktop behaviors for the primary command-center surface.

## Workspace model

Desktop interaction combines stable primary navigation, a context header, main workspace, optional supporting panels, and global utilities. Layout implementation remains Phase 07/35 work; behavioral expectations are defined here.

## Interaction rules

- Primary actions are reachable by keyboard and visible text labels.
- Back/forward restores route, selection, filters, scroll/focus where safe.
- Unsaved work is preserved or explicitly resolved before navigation.
- Selection and focus are distinct and clearly communicated.
- Inline edit is limited to low-risk, contextual changes; complex/consequential edits use focused workflows.
- Supporting panels inspect relationships/evidence but do not duplicate authoritative forms.
- Drag-and-drop has keyboard and menu alternatives.

## Focus and sessions

Starting a session should require minimal setup, preserve the source action, and provide clear pause/finish/interruption behavior. Timer state survives navigation and communicates background status.

## Multi-window and resizing

Window behavior, split view, and multi-monitor support remain subject to platform research. Any implementation must preserve one authoritative edit state and avoid hidden confirmations in another window.

## Offline/optional states

Local actions continue during network loss. AI, sync, and integrations show scoped availability. The whole interface is not blocked by an optional-service failure.

## Acceptance criteria

Frequent flows complete without pointer dependence, large-screen context is useful rather than cluttered, and interaction remains predictable with AI/cloud disabled.
