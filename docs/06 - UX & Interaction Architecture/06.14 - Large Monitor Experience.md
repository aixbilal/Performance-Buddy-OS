# Large Monitor Experience

## Purpose

Define how the desktop product uses large displays for context and focused work without creating overwhelming density.

## Principle

Additional space should improve comprehension, comparison, and continuity—not display every available metric. The main task retains a clear reading width and hierarchy.

## Layout behavior

Large screens may support a primary workspace plus one or two contextual regions for the living plan, evidence, relationships, session state, or explanation. Context panels remain subordinate and collapsible. Canonical edits stay with the owner workflow.

## Use cases

- Today plan beside active session/context.
- Course detail beside topic/evidence or assessment summary.
- Development project beside learning path and notes reference.
- Weekly review beside selected domain drill-down.
- AI proposal beside before/after plan and evidence.

## Rules

- Avoid horizontal sprawl and excessive eye travel.
- Preserve keyboard order matching visual/logical structure.
- Resize/reflow instead of clipping; zoom remains supported.
- Do not require a large monitor for any CORE workflow.
- Panels do not duplicate forms or create conflicting edit states.
- Privacy-sensitive content can be hidden quickly for shared environments.

## Multi-window boundary

Multiple windows/monitors remain platform research. If introduced, the app must handle concurrent edit state, focus, approvals, and sensitive display deliberately.

## Acceptance criteria

Large-screen layouts improve task context, work at common smaller desktop sizes, retain accessible reading/focus order, and do not turn dashboards into walls of cards.
