# Mobile Capture Interaction Model

## Purpose

Define future low-friction, offline-capable mobile capture behavior while preserving desktop and domain authority.

## Status and goals

This document is `MOBILE` direction. Mobile optimizes quick capture during university and daily life: sessions, lectures, marks, deadlines, routine checks, expenses, tests, and short reviews. It does not promise desktop parity.

## Capture pattern

1. Choose or infer a bounded record type.
2. Prefill safe context such as current time or selected course.
3. Enter the minimum required fields.
4. Validate locally.
5. Confirm local save and show sync/pending state separately.
6. Offer quick correction or undo.

## Rules

- Frequent capture remains available offline.
- Defaults never fabricate marks, completion, or sensitive evidence.
- Camera/voice/AI extraction produces a reviewable draft, not a confirmed record.
- Large forms defer optional detail for later desktop completion.
- Conflicts display both values and ownership; they are not silently resolved.
- Lock-screen notifications minimize private content.

## Accessibility and interruption

Controls support platform accessibility services, scalable text, clear targets, orientation changes, and one-handed use where feasible. Interrupted capture preserves a local draft without unintended submission.

## Acceptance criteria

A common capture is fast, truthful, recoverable, permission-safe, and distinguishable from synchronization. Mobile cannot bypass approval or domain validation.
