# Keyboard-First UX

## Purpose

Define a coherent keyboard interaction model for efficient desktop use without excluding pointer or assistive-technology users.

## Core paths

Keyboard users can reach primary navigation, main content, global search, command palette, quick capture, contextual actions, forms, dialogs, tables/lists, and help. A skip-to-content path avoids repeated navigation.

## Conventions

- Tab moves among interactive elements; arrow keys operate established composite controls.
- Enter activates the primary safe action; Space toggles appropriate controls.
- Escape closes transient layers or cancels a safe current mode without losing data silently.
- Shortcuts do not override text entry or operating-system/assistive-technology conventions.
- Shortcut help is searchable and context-aware.

## Shortcut architecture

Commands use stable IDs from the palette. Global shortcuts are few, memorable, and configurable where feasible. Contextual shortcuts require visible discoverability. Destructive actions never use easy single-key triggers.

## Focus management

Opening a dialog/panel moves focus to its heading or first meaningful control; closing returns to the invoker. Route changes focus the new page heading/main region. Errors move to a summary only when useful. Focus is not reset by background refresh.

## Complex interactions

Reordering, resizing, timeline selection, and chart exploration require non-drag alternatives. Typeahead and virtual lists must preserve announcements and selection state.

## Acceptance criteria

End-to-end keyboard tests cover daily planning, session execution, capture, approval, settings, and recovery with no traps or pointer-only step.
