# PBOS V2 — PASS 1: REAL-LIFE OPERATING MODEL

Status: LOCKED

## Central objective

V2 should reduce manual PBOS operation on a normal university day while preserving user authority and trustworthy canonical state.

Target feeling:

> PBOS prepares → I live → I capture reality once → PBOS structures it → PBOS adapts → I approve meaningful changes.

Success statement:

> I use PBOS more, but I operate PBOS less.

## Real-life day model

PBOS should work around the actual flow of a university day:

- wake / morning orientation
- university commitments
- lectures
- breaks
- professor coverage changes
- unexpected assessments/deadlines
- Focus/study
- spending
- return home
- revised capacity
- development work
- exercise/routines
- language
- evening review
- tomorrow planning

The system should ask what PBOS already knows, what it can safely derive, and what still requires human truth.

## Three information classes

### A. PBOS already knows

Do not ask the user to enter it again.

Examples:

- Focus duration measured by PBOS
- linked Action
- linked course/topic
- current Planning Block
- known assessment date
- existing completion evidence
- known calendar time

### B. AI can extract but must not silently declare truth

Examples:

- “Professor covered AVL deletion.”
- “Spent 450 on food.”
- “German for 20 minutes.”
- “Deletion cases still confuse me.”

These become structured proposals.

### C. User authority is required

Examples:

- subjective understanding
- low/normal/high capacity
- external events PBOS cannot observe
- ambiguous interpretation
- meaningful planning trade-offs
- protected/locked intent
- structural routine changes

## V2 product law

> Never ask the user to manually enter data PBOS itself generated.

If PBOS measured a 41-minute Focus session, do not ask for the duration again.

## Single source of truth / evidence propagation

One canonical event should be reused wherever relevant.

Example:

One completed Focus session may feed:

- Study history
- academic activity evidence
- linked Action progress context
- Today state
- Analytics
- Review

The user should not manually update six screens.

## Natural Capture as external-reality input

Natural Capture should become a global input router:

Natural statement
→ parse
→ structured proposals
→ entity resolution
→ ambiguity handling
→ user review
→ deterministic validation
→ canonical apply
→ audit

It is not a chatbot and does not silently mutate PBOS.

## Adaptive Today as primary operational output

Today should become the place PBOS answers:

> Given reality right now, what should I do next?

It should combine current plan, actual evidence, remaining time, priorities, capacity and protected intent.

## Planner / Calendar / Today distinction

Planner:
Where could/should work fit over a longer horizon?

Calendar:
What occupies actual time?

Today:
Given current reality, what should happen next?

Today may temporarily recommend divergence from the old plan without silently rewriting Planner. Any meaningful Planner mutation is separately proposed and validated.

## Review evolution

Evening Review should be pre-populated with PBOS-known facts and ask mainly for:

- human reflection
- corrections
- missing external events
- decisions

It should not become another data-entry form.

## Manual operations V2 should eliminate or reduce

- re-entering Focus duration
- re-entering PBOS-measured development activity
- logging the same university event in multiple domains
- opening a whole domain for a tiny update
- manually recalculating urgency
- rebuilding Today after routine schedule drift
- restating known PBOS facts to AI Coach
- manually identifying unfinished work PBOS already knows
- re-entering known dates/times
- duplicate routine/language logs
- deterministic academic arithmetic by hand

## Manual operations V2 should preserve

- Accept / Modify / Reject meaningful AI proposals
- lock/protect plans
- correct Capture interpretation
- resolve ambiguity
- provide subjective capacity/understanding
- report external events PBOS cannot observe
- choose schedule trade-offs
- approve routine structure changes
- control domain permissions
- reject AI
- edit reflection conclusions

## Core conceptual pillars

1. Natural Capture — tell PBOS reality once.
2. Adaptive Today — turn state into the next best decision.
3. Evidence Propagation — PBOS-generated activity updates relevant state without duplicate entry.

Adaptive Planning, Academic Intelligence, Knowledge Intelligence, Routine Intelligence and AI Coach attach to these pillars.

## Pass 1 result

V1 is a trustworthy manually maintained operating system.

V2 should become an evidence-driven assisted operating layer that understands:

- what happened
- what matters
- what is weak
- what is urgent
- what realistically fits
- what changed
- what should happen next

while keeping meaningful decisions under user control.
