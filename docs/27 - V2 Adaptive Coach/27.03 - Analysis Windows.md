# 27.03 — Analysis Windows

## Window types

V2 supports rolling windows, calendar weeks/months, semester segments, assessment ramps, user-selected intervals, and matched comparisons such as university days versus non-university days. Exact default lengths and minimum samples are method-specific and must be empirically validated.

## Window contract

Record start/end instants, user timezone, inclusion boundary, comparison period, current study/planning mode, eligible weekdays, source coverage, missing intervals, and freshness. Windows are immutable inputs to a result; later data creates a new analysis version.

## Comparison rules

Compare like with like or explicitly expose differences. Exam weeks, recovery periods, holidays, travel, illness, curriculum changes, and schedule-mode changes are segmented rather than blended into a misleading baseline. Overlapping windows are disclosed; repeated looks do not turn noise into certainty.

Short windows support recent review but not durable claims. Long windows can hide regime changes. The system shows why a window was selected and lets the user inspect alternatives.

## Acceptance criteria

- Timezone, midnight, daylight-change, semester-boundary, and incomplete-window tests pass.
- Minimum evidence and freshness rules exist for every analysis method.
- Changing the window visibly changes the analysis scope, not historical source data.
