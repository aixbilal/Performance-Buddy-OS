# 27.13 — Scheduled Analysis Runs

## Eligibility

Scheduled V2 analysis is opt-in per application. Each schedule declares owner, purpose, domains/data categories, analysis windows, method version, execution-location policy, frequency, quiet hours, expiry, budgets, notification policy, and cancellation path.

## Run rules

At execution, reacquire authorization and consent, verify coverage/freshness, respect device/network/cost/rate limits, and use locks/idempotency to prevent overlap. Missed runs follow an explicit skip, catch-up, or merge policy. Background work yields to interactive use.

Runs may create findings, risk signals, summaries, or proposals. They may not commit meaningful changes, contact others, or create new recurring schedules. Results include generation time and expiry; low-value/no-finding runs should not interrupt the user. Notifications consolidate and follow Phase 06 calm-interruption rules.

Users can inspect run history, pause, edit, run now, or cancel. Revoked permissions stop access before analysis and invalidate affected pending results.

## Acceptance criteria

- Timezone, duplicate trigger, offline, expired consent, revoked domain, and missed-run tests pass.
- Scheduling cannot produce wake/retry storms, hidden spend, or approval bypass.
- Disabling a schedule leaves source data and existing CORE/V1 workflows intact.
