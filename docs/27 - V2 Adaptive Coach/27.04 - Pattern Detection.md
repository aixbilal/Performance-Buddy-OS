# 27.04 — Pattern Detection

## Definition

A pattern candidate is a repeated, method-defined relationship among observable events. It is not a trait, diagnosis, motive, or causal conclusion.

## Candidate contract

Include stable pattern type, analysis version, window, qualifying occurrences, counterexamples, expected baseline, effect size where appropriate, coverage, confidence, missing data, possible confounders, alternative explanations, first/last observation, and review state.

## Rules

Define recurrence and thresholds before evaluation. One event is normally insufficient. Correct for duplicated records, overlapping intervals, mode changes, and repeated testing. Show examples and counterexamples. Prefer deterministic patterns when a transparent rule is sufficient; use AI to interpret bounded results, not fabricate measurements.

Users may confirm, dismiss, or mark a pattern no longer relevant. Dismissal suppresses or tunes presentation under an explicit policy; it does not erase evidence or silently retrain a provider model.

## Acceptance criteria

- Synthetic known-pattern and no-pattern datasets measure precision, recall, and false discovery.
- Findings remain reproducible and avoid personality or moral labels.
- Pattern detection alone cannot create a plan or record mutation.
