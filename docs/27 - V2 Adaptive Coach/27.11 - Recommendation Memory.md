# 27.11 — Recommendation Memory

## Purpose

Retain governed recommendation history so V2 can avoid repetition, honor decisions, and evaluate outcomes without turning chat history into authority.

## Record types

- finding and evidence manifest;
- recommendation/proposal version;
- validation result and warnings;
- user decision: accepted, edited, rejected, deferred, dismissed, or expired;
- committed command reference where applicable;
- review plan and outcome summary.

## Required metadata

Store owner, purpose, capability, source references/revisions, sensitivity, consent basis, confidence, created/decision/expiry times, prompt/model/method versions, and revocation state. Facts are referenced from domain records, not duplicated as memory truth.

Sensitive health, money, spiritual, reflection, smoking, nutrition, and private routine information requires category- and purpose-specific consent. Rejection does not imply dislike of all similar advice; suppression scope must be explicit. Users can inspect, correct, forget, export, and disable recommendation memory.

## Acceptance criteria

- Silent memory creation and cross-purpose sensitive reuse are impossible.
- Revocation invalidates derived summaries and future analysis use.
- Disabling memory leaves stateless V1 and CORE usable and does not rewrite domain history.
