# Milestones

## Purpose

A milestone is a meaningful evidence-bearing checkpoint within a goal. Phase 11 owns goal milestone semantics; Phase 10 provides reusable milestone-tracker mechanics.

## Model

Milestones contain stable identity, parent goal, owner domain, description, success evidence, optional prerequisites, target window, weight, state, and definition version. They may be sequential, parallel, or independent.

## Rules

- Completion requires the milestone’s evidence contract, not target-date arrival.
- A later checkpoint does not silently complete prerequisites.
- Weights are optional and must expose how aggregate progress is derived.
- Reopening preserves the previous decision, evidence, actor, and reason.
- Changing success meaning creates a new effective version.

## Cross-domain boundary

Academic, Development, Fitness, Money, and other domains own their specialist checkpoints. A goal milestone may reference an authoritative domain result but cannot duplicate or alter it.

## Acceptance criteria

Dependencies are valid, evidence is proportionate, progress calculations are reproducible, target dates remain planning inputs, and overdue presentation uses neutral language.
