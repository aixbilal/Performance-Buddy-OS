# 33.04 — Local File Storage

## Scope

Local files include user-selected vault references, attachments, imports/exports, generated study/context packages, model/runtime artifacts, search indexes, caches, logs, backups, and temporary work. Each class has an owned root, permission, retention, quota, integrity, and cleanup policy.

## Rules

Store references to external user files rather than moving/editing them without explicit action. Use safe filenames, atomic write-then-replace, fsync/durability where required, checksums, and path canonicalization. Prevent traversal, unsafe links, executable uploads, and secrets in logs. Temporary/derived files never outrank database/source records.

Indexes/caches are disposable and rebuildable. Model packages are verified and removable. Backup destinations are user-visible. Disk-space checks precede large writes/downloads; partial files are quarantined or cleaned.

## Acceptance criteria

- Permission loss, moved vault, disk-full, partial write, checksum mismatch, and unsafe path tests pass.
- Cleanup cannot delete owner files or unrelated directories.
- Data zones and private filenames remain protected offline.
