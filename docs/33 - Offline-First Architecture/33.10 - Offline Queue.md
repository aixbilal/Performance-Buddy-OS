# 33.10 — Offline Queue

## Scope

The offline queue holds explicitly approved network-dependent operations such as sync batches, remote backup uploads, external/API handoffs, or cloud AI requests where deferral is allowed. Local domain writes are not queued; they commit locally.

## Item contract

Queue ID/type/version, purpose, payload reference/hash, origin entity revisions, permission/consent/provider refs, data zones, created/expiry time, priority, dependencies, attempts, backoff, idempotency key, status, cancellation, and last error.

## Rules

Encrypt/protect payloads; prefer rebuilding minimized payload at send time. Recheck permission, consent, source freshness, connectivity, cost/quota, and destination before sending. Never queue never-AI/local-only content for remote work. Retries are bounded with jitter; dead-letter state is visible. User can inspect/cancel.

## Acceptance criteria

- Replay, reorder, duplicate, expiry, revocation, provider switch, and disk-full tests pass.
- Queue processing cannot duplicate remote/local side effects.
- Queue loss cannot erase canonical local records.
