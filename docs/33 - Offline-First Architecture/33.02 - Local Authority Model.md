# 33.02 — Local Authority Model

## Authority

Domain repositories and deterministic command handlers validate and commit local CORE changes transactionally. Each record carries stable identity, revision, provenance, actor/device, and timestamps. A locally successful write is real; it is not “pending” merely because it has not synced.

## Boundaries

Official external facts retain their source authority, but their local imported/cached representation remains usable with visible version/freshness. Sync peers may hold competing revisions; neither remote arrival nor newest wall-clock timestamp wins automatically. Phase 34 owns reconciliation.

Cloud accounts, provider responses, external AI results, search indexes, analytics projections, and sync metadata never outrank canonical owner records. Permissions and protected constraints apply locally.

## Acceptance criteria

- Local commands succeed/fail entirely from local data and rules.
- Reinstall/device loss risks are addressed by backup/export without redefining authority.
- Remote data enters through import/sync validation, never direct table replacement.
