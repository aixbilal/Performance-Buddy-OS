# 33.08 — Offline AI

## Boundary

Offline AI means qualified `LOCAL` inference on user-controlled hardware. It is optional and separate from the offline-first CORE promise. CORE startup and workflows never load or require a model.

## Eligible behavior

Evaluated local applications may parse commands, classify, extract, embed/rerank, retrieve, or draft bounded responses. They use Phase 24 runs, Phase 25 hardware/model gates, Phase 29 context, and Phase 30 permissions. Local output remains probabilistic and cannot write trusted state directly.

## Failure and resource policy

Missing model/runtime, insufficient memory/storage, battery/thermal pressure, invalid output, low confidence, or timeout falls back to forms, lexical search, deterministic calculation, or manual work. Cloud fallback requires new explicit consent and disclosure; it is never automatic.

## Acceptance criteria

- Disabling/uninstalling LOCAL leaves data and CORE intact.
- Network-denial tests prove local-only/never-AI policies and no hidden egress.
- Resource stress cannot starve or corrupt CORE operations.
