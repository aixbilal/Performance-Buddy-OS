# 33.05 — Offline Feature Matrix

## Matrix

| Area | Required offline behavior | Optional/unavailable offline |
|---|---|---|
| Goals/plans/actions | Full CRUD, validation, Today/replanning | Cross-device sync |
| Sessions/trackers/routines | Execute and record all states | Remote notifications |
| Academics | Records, prerequisites, marks, GPA/CGPA/scenarios | Fetch new official sources |
| Knowledge/Obsidian | Links, permitted lexical search/index | Remote enrichment/embeddings |
| Development/fitness/money | Records, sessions, calculations/reviews | External imports/providers |
| Analytics | Deterministic local reviews/trends | Heavy cloud analysis |
| AI | CORE remains fully usable; qualified LOCAL optional | CLOUD V1–V3 |
| Backup/export | Local backup/export | Cloud backup |

## Rules

Each feature declares `OFFLINE_FULL`, `OFFLINE_DEGRADED`, or `ONLINE_REQUIRED` with reason and fallback. No CORE feature is `ONLINE_REQUIRED`. UI tests prevent cloud-only labels from masquerading as CORE.

## Acceptance criteria

- The matrix maps to executable feature tests and release gates.
- Degraded states name missing freshness/capability without blocking local records.
- Adding a remote feature cannot regress existing offline coverage.
