# 33.09 — Network Detection

## Principle

Connectivity is an observed, uncertain capability—not a global online/offline boolean and never a prerequisite for local startup.

## States

Track local interface availability, internet reachability, captive portal, metered connection, and per-service reachability/authentication separately. A successful past check does not guarantee the next request; every remote operation handles failure.

## Rules

Use OS signals plus bounded service probes only when needed. Avoid continuous polling, privacy-invasive endpoints, and battery drain. Debounce flapping. User offline/data-saver settings override opportunistic work. Status shows `LOCAL_ONLY`, `CONNECTING`, `LIMITED`, `SERVICE_UNAVAILABLE`, or `AVAILABLE` with last check, not false certainty.

## Acceptance criteria

- Captive portal, DNS failure, service outage, VPN/proxy, metered, flapping, and false-positive tests pass.
- Network checks never block local UI/data commands.
- Remote errors update only relevant service state, not all connectivity.
