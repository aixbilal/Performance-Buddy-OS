# 33.01 — Offline-First Principle

## Definition

Offline-first means the application is designed around reliable local authority and later connectivity, not a cloud application with cached pages. The user can perform the essential product loop with network interfaces disabled.

## Mandatory properties

Local startup, identity/profile, domain records, goals/systems/actions, Today planning, sessions, trackers, academic calculations, knowledge links/search, deterministic analytics, money arithmetic, settings, approvals, undo/recovery, and export work without a remote dependency.

## Optional properties

Sync, cloud backup, remote AI, external handoffs, remote imports, and update checks may be unavailable. Their absence is shown without disabling unrelated local functions. Cached remote content is labeled with source/freshness and never presented as current merely because it exists.

## Acceptance criteria

- A documented offline test run starts from cold boot with network denied.
- No CORE path waits indefinitely for DNS, authentication, telemetry, or feature flags.
- Offline behavior is normal product behavior, not a generic error state.
