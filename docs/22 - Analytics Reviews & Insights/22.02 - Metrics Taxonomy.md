# Metrics Taxonomy

## Purpose

Classify metrics by meaning and evidence so incompatible values are not compared or aggregated carelessly.

## Types

`Count`, `Duration`, `Rate`, `Ratio`, `Distribution`, `Balance`, `Progress`, `Consistency`, `Quality/Evidence`, `Trend`, `Risk Signal`, `Friction Signal`, and `Scenario` are distinct. Each metric also identifies domain owner and descriptive/derived/scenario status.

## Definition contract

Stable metric ID; title; purpose; owner; unit; grain; population/scope; numerator/denominator; included/excluded states; timezone/window; source IDs; aggregation; precision/rounding; missing/late-data policy; privacy; formula version; confidence/limitations; and acceptance fixtures.

## Rules

Rates require visible denominators. Percentages never hide exclusions. Different units or semantic versions cannot combine without an approved mapping. Scenarios remain separate from actuals. Composite metrics require independently justified components and cannot become a universal score.

## Acceptance criteria

The catalog prevents duplicate definitions, formulas are testable, version changes preserve history, and users can open any metric’s calculation contract.
