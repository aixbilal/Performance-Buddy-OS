# Development Analytics

## Purpose

Describe progress through technical learning paths, projects, independent practice, debugging, and architecture evidence without rewarding code volume or AI dependence.

## Metrics

Module/path state; learn-practice-build balance; project milestone/evidence state; independent versus assisted work context; test/verification coverage as evidence references; debugging cycle outcomes; architecture practice; session allocation; blockers; maintenance/pause periods; and return after interruption.

## Rules

Commits, lines of code, tutorial hours, and generated output are activity indicators only. Project completion does not prove every linked skill. Repository privacy and source permissions apply. Framework comparisons require compatible contexts.

## Interpretation

Analytics can surface excessive passive learning, repeated unverified implementation, or neglected independent practice as review prompts—not accusations.

## Acceptance criteria

Every skill/progress view traces to Phase 18 evidence, assistance provenance is preserved, project and learning outcomes remain distinct, and no metric promotes a technology choice outside Phase 44.
