# Multi-Check Prayer Model

## Purpose

Specialize Phase 10 Multi-Check tracking for a user-defined daily set of prayers while preserving component-level truth and privacy.

## Structure

The daily occurrence contains stable component IDs, user-approved labels/order, optional schedule windows, and individual states. The parent day status is a transparent summary, not a statement about spiritual quality.

## Rules

Each component is recorded independently. Unchecked is `Unknown` until explicitly classified. Partial completion remains visible and is not collapsed into failure. Adding, removing, or renaming components creates an effective configuration version when meaning changes. Historical days render against their original version.

## Summary

The interface may show factual counts such as “3 recorded complete; 2 unknown” only within the user’s private view. Rest, maintenance, and competitive streak semantics are not imposed. Excused/not-applicable behavior follows the user’s configured religious context.

## Acceptance criteria

Parent summaries reproduce component records, no component satisfies another silently, private reasons are optional, and analytics cannot infer intention or rank faith.
