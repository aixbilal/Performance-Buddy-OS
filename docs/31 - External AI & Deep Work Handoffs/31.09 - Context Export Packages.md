# 31.09 — Context Export Packages

## Package contract

Every export contains package ID/version, creation/expiry, user-approved purpose, destination class, requested output, capability, included domains/categories, permission/consent references, source manifest/revisions, redaction report, data-zone results, instructions, output schema, integrity hashes, and re-import policy.

## Formats

Use human-readable Markdown/JSON manifests plus only necessary source files or excerpts. Filenames avoid sensitive metadata. Content is deterministic where possible, portable, bounded, and inspectable before release. Vendor-specific adapters may transform a copy but cannot change the authorized source set.

## Data rules

Never-AI and local-only data fail export. Ask-every-time categories require fresh destination-specific consent. Derived summaries inherit the strictest source classification. Packages contain no API keys, internal credentials, hidden prompts, or owner write commands.

## Lifecycle

Build locally; validate; preview; approve; mark released only after user action; record destination and package hash; expire; and support secure deletion. Export does not imply successful transfer.

## Acceptance criteria

- Deterministic fixtures verify manifest, redaction, hashes, and exact included files.
- Package tampering is detected during re-import/reference checks.
- Export logs use metadata/references rather than duplicating sensitive content.
