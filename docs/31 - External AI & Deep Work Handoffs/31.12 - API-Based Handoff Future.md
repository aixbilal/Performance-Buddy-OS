# 31.12 — API-Based Handoff Future

## Status

Automated API handoff is `FUTURE`; it is not committed baseline behavior. Exact providers, SDKs, models, authentication, pricing, quotas, regions, retention, and schemas are `RESEARCH REQUIRED` before an approved architecture decision.

## Promotion prerequisites

Stable manual package/import contracts; provider research and legal/privacy/security review; secret management; scoped OAuth/API credentials; destination allowlists; explicit consent; data minimization; idempotency; job state/cancellation; cost/rate limits; retries; audit; result authentication; deletion; incident response; evaluation; and lower-capability fallback.

## Boundary

Automation must not add sources, bypass previews for sensitive categories, silently fail over providers, write owner records, or expose secrets to models/logs. Credentials remain never-AI. Each request has a package hash, purpose, destination, expiry, and callback/import validation.

## Acceptance criteria

- A future ADR documents need, alternatives, threats, provider facts, migrations, and exit plan.
- Sandbox/chaos tests prove no duplicate transfer/write or hidden scope expansion.
- Until promotion, UI and documentation describe only manual handoff.
