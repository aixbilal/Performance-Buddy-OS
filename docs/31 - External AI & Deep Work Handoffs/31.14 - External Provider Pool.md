# 31.14 - External Provider Pool
## Purpose

Define approved external inference options used through the control plane, distinct from manual deep-work handoff products. The pool may include configured Gemini endpoints/projects, Groq, and future providers; local models remain the offline/private option.

Each entry records adapter, models/capabilities, region/retention, account/project, credential reference, allowed data classes, budgets, health, evaluation status, and replacement state. API keys remain secret-store credentials, not agents. Multiple endpoints do not create companion identities.

Selection follows Phase 29 routing and Phase 30 permissions. Exported context is minimized, disclosed, provenance-tagged, and re-imported as untrusted AI output requiring schema and rule validation.

## Acceptance criteria

- External outage cannot disable deterministic core functions.
- Pool entries can be disabled without deleting agents or memory.
- No quota-circumvention or silent remote exposure is implemented.
