# 31.05 — NotebookLM Handoff

## Intended use

NotebookLM may be evaluated as a destination for source-centered study and synthesis when the user wants to work from a bounded collection of permitted materials. This is a design target, not a guarantee of current features.

## Package profile

Prefer a source inventory, clean documents, stable titles/IDs, citation map, study objective, coverage gaps, glossary, requested questions/outputs, and explicit instruction to separate source claims from inference. Split packages by course/path and permission zone rather than creating one life-wide notebook.

## Verification requirement

Supported formats, source limits, citation behavior, account eligibility, regional access, retention, training/data controls, sharing, and deletion are `RESEARCH REQUIRED` from current primary Google documentation before each implementation decision.

## Boundaries

No never-AI/local-only material, credentials, automatic vault sync, or private cross-domain aggregation. Notebook-generated summaries/questions remain derived drafts and cannot update knowledge confidence or academic records automatically.

## Acceptance criteria

- Sources in the package are rights/permission checked and individually removable.
- Imported citations resolve to original local sources, not only external notebook identifiers.
- Unsupported or uncertain controls lead to a local study pack instead.
