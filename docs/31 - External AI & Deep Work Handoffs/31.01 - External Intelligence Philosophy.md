# 31.01 — External Intelligence Philosophy

## Principle

Use external intelligence when a user deliberately wants a different workspace, source-grounded notebook, long-form model, or specialized capability—not because Performance Buddy OS silently exports context or avoids its own governance.

## Division of responsibility

Performance Buddy OS selects and minimizes approved evidence, explains exposure, creates a reproducible task package, and validates any returned claims/actions. The external tool processes only what the user transfers under that tool's terms and controls. The user decides what to send and what to bring back.

## Invariants

- External convenience never bypasses Phase 30 data zones.
- A polished answer remains non-authoritative.
- Official facts and CORE calculations are verified after return.
- External conversation memory is not Performance Buddy OS memory.
- No external tool can commit plans, marks, trackers, money, routines, or permissions.
- Manual/offline work remains available.

External tools are interchangeable destinations behind a common package contract. Tool names do not become architecture dependencies.

## Acceptance criteria

- Every handoff declares purpose, destination, data, expected output, and re-import path.
- The user can complete or abandon a handoff without damaging local state.
- Product language avoids implying partnership, endorsement, or guaranteed capability.
