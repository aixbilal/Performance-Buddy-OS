# 31.13 — Result Re-Import

## Principle

External results re-enter as untrusted evidence or drafts. Import never makes them true, grants permission, or commits domain changes.

## Pipeline

Select a result file/text; malware/type/size scan; quarantine; parse against an expected schema where available; link package/result IDs and hashes; preserve external provenance; classify claims, citations, calculations, and proposed actions; resolve citations to original permitted sources; recompute CORE values; detect conflicts/injection; then present an import preview.

## Outcomes

The user may save a draft/reference, create candidate questions/notes, request verification, create a typed proposal, or discard. Any owner-domain mutation passes Phase 23 and fresh approval. Imported instructions cannot execute tools, access new data, create memory, or modify permissions.

Missing citations, unknown model/provider settings, tampering, stale source revisions, or unsupported formats reduce trust or block consequential use. Corrections append provenance rather than rewriting the external artifact.

## Acceptance criteria

- Injection, malware, fabricated citation, stale source, wrong package, and malformed schema tests pass.
- Imported calculations exactly match CORE before use.
- Rejecting/deleting an import leaves owner records and permissions unchanged.
