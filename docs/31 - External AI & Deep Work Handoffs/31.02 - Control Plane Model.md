# 31.02 — Control Plane Model

## Model

Performance Buddy OS remains the control plane while external tools act as isolated work planes.

`owner sources → permission/data-zone filter → package builder → user preview/approval → external work plane → user-selected export → quarantine/import validation → owner command approval`

## Control-plane responsibilities

Identify task and destination; validate user/domain permissions; exclude never-AI/local-only data; minimize and redact; preserve citations/provenance; generate instructions and output schema; hash/version the package; disclose provider exposure; record approval; quarantine returned content; verify sources/entities/calculations; and route proposals through Phase 23 and human approval.

## Separation

The work plane receives no live database access, credentials, hidden tool authority, standing sync, or automatic callback in baseline. Package transfer does not delegate control. External outputs cannot alter the package manifest or assert new permissions.

## Acceptance criteria

- Threat tests prove exported instructions cannot grant external write authority.
- Every boundary crossing is explicit, attributable, and auditable.
- A compromised or incorrect external result is contained as untrusted import data.
