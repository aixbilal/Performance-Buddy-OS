# End-to-End Testing

## Journeys

End-to-end suites cover first launch, local setup, Today planning, quick capture, session lifecycle, trackers, academic record/mark entry, GPA explanation, knowledge linking/search, development/fitness/routine/money entries, review, approval, backup/restore, import/export, and optional AI/sync degraded states.

## Method

Run through accessible user interfaces on representative supported desktop/mobile environments with seeded versioned data. Assert visible outcome and persisted canonical state—not screenshots alone. Journeys include restart, interruption, back/forward, unsaved work, keyboard use, denied permission, offline mode, provider failure, undo, and recovery.

Keep tests independent and stable through semantic roles, command IDs, and controlled time. Visual checks complement behavior and accessibility assertions. Production-like packages validate installer, upgrade, deep link, notification, tray, and background lifecycle where relevant.

## Acceptance criteria

- Primary journeys complete with AI/cloud disabled.
- No UI success state appears before durable commit.
- Failures provide a truthful recovery path without silent data loss.
