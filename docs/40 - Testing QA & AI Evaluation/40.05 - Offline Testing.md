# Offline Testing

## Matrix

Every feature is tested against its declared `OFFLINE_FULL`, `OFFLINE_DEGRADED`, or `ONLINE_REQUIRED` status. No CORE feature may require network. Tests cover clean offline launch, network loss before/during/after action, flapping connectivity, DNS/TLS failure, captive behavior, stale credentials, and long-offline use.

## Fault injection

Inject database lock/corruption, disk-full/read-only, migration interruption, missing files, permission loss, corrupt cache/index, clock/timezone change, duplicate scheduler trigger, local-model failure, queue growth/corruption, and shutdown/sleep at critical transitions.

Assert local commands commit atomically, drafts survive, queues remain inspectable, retries are bounded/idempotent, stale state is labeled, and optional services can be killed without damaging CORE. The app never creates a blank database, discards queued work, or claims freshness/completion falsely.

## Acceptance criteria

- Airplane-mode journeys cover every committed local capture and calculation.
- Recovery proves no silent loss, duplicate effect, or privacy downgrade.
- Reconnection tests begin from each supported offline state.
