# AI Structured Output Tests

## Scope

Evaluate schema adherence separately from semantic correctness. Test every AI application, provider/model, prompt, schema, tool set, streaming mode, retry path, and capability version against valid, boundary, adversarial, truncated, and malformed responses.

## Assertions

Validate required/optional fields, types, enums, bounds, units, IDs, citations, reason codes, unknown handling, additional-field policy, Unicode, large values, partial streams, refusal, cancellation, and provider error normalization. Parsing never executes content or repairs consequential meaning silently.

Tool calls validate tool identity, arguments, permissions, entity revisions, idempotency keys, and approval level. Duplicate or retried generations cannot duplicate side effects. Structured success still passes domain and deterministic validation.

Track exact-valid rate, repair rate, unrecoverable rate, semantic-invalid rate, latency, and token/cost distribution. Repair prompts and parsers are versioned parts of the evaluation.

## Acceptance criteria

- Invalid output cannot reach a commit path.
- Consequence-specific schema thresholds are set before final evaluation.
- Provider/model changes rerun the full contract and regression suite.
