# Performance Tests

## Budgets

Define measurable budgets for cold/warm startup, navigation/input response, database commands/queries, Today rendering, search/indexing, import/export, backup/restore, sync batches, background jobs, local AI, memory, CPU, disk, battery, package size, and network/token cost.

`RESEARCH REQUIRED`: approve numeric thresholds using minimum and representative supported hardware, realistic datasets, supported OS versions, and accessibility settings.

## Method

Test empty, typical, large, and pathological authorized datasets; cold and warm caches; offline and degraded networks; concurrent timer/index/sync/AI work; low disk/memory; battery and thermal pressure; long-running sessions; and migration/restore. Record distributions and tail latency, not averages alone.

CORE responsiveness has priority. Optional indexing, sync, animation, and AI must pause, throttle, cancel, or isolate under resource pressure. Tests also check integrity, privacy, and correctness—faster wrong results do not pass.

## Acceptance criteria

- Results are reproducible with environment and dataset versions.
- Regressions beyond approved budgets block release or receive expiring disposition.
- Stress/soak tests show bounded resources and no data corruption or retry storms.
