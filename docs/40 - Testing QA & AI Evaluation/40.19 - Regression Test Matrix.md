# Regression Test Matrix

## Matrix dimensions

Track phase/requirement, risk, capability, domain, surface, test level, supported OS/device, offline/online state, schema/rule/policy version, migration path, provider/model, permission/data zone, fixture, expected result, owner, automation status, last result, and release gate.

## Required slices

The matrix covers CORE with all optional services disabled; desktop and mobile where applicable; fresh install and every supported upgrade; normal and failure paths; local/cloud AI; sync concurrency; academic policy versions; import/export/restore; accessibility; security/privacy; and representative performance tiers.

Every fixed defect adds a regression case linked to root cause. Deprecated behavior remains until compatibility support ends through an approved process. Tests may be retired only with the requirement, risk, replacement evidence, and version boundary documented.

Release reports distinguish pass, fail, blocked, not applicable, quarantined flaky, and waived. Only genuine passes satisfy gates. Waivers identify owner, rationale, scope, compensation, expiry, and rollback.

## Acceptance criteria

- Queries identify uncovered high-risk requirements and unsupported combinations.
- No flaky, skipped, blocked, or waived test is counted as passed.
- The shipped artifact maps to an immutable matrix snapshot and evidence set.
