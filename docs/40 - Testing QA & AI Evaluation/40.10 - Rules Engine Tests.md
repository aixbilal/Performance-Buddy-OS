# Rules Engine Tests

## Coverage

Test rule registration, priority, protected constraints, applicability, effective versions, conflicts, reason codes, user overrides, validation order, recommendation validation, and deterministic traces.

Each command fixture exercises authentication/context, authorization, schema/units/bounds, identity/source/version resolution, immutable snapshot, hard constraints, domain invariants, soft warnings, approval determination, and separate idempotent commit.

Use decision tables for combinations and property tests for determinism, invariant preservation, stable ordering, and no mutation on rejection. Generate explicit conflicts among sleep, fixed commitments, scheduling, academic, budget, and user rules. Overrides cannot bypass non-overridable safety or source requirements.

Rule updates retain historical versions and regression fixtures. Unknown rule/version or missing dependency fails visibly; it never selects a convenient default.

## Acceptance criteria

- Phase 23 independently reproduces every consequential result and explanation.
- Rejected commands produce no domain, audit, event, or queue write.
- Conflicts and overrides retain actor, reason, scope, version, and expiry.
