# Model Comparison Benchmarks

## Purpose

Compare local and remote models for a specific AI application; do not produce a universal leaderboard. A model is eligible only if it satisfies that application's capability, privacy, safety, reliability, hardware, latency, and cost gates.

## Protocol

Freeze dataset split, prompt/schema/tools/policies, retrieval snapshot, parameters, retry policy, hardware/runtime, provider region, and evaluation code. Record model identifier/revision, quantization, adapter, context limits, temperatures/seeds where supported, warm/cold state, and run date.

Measure structured validity, grounding, recommendation rubric, safety, calibration, tool accuracy, latency distributions, throughput, memory/storage/thermal/battery use for local models, tokens/cost/rate limits for remote models, and failure/abstention behavior. Report confidence intervals and repeated runs where stochastic.

Avoid benchmark contamination and tune only on development data. Compare against deterministic, no-AI, and simpler-model baselines. Quality gates precede price/speed optimization.

## Acceptance criteria

- Results are reproducible enough to explain selection and limitations.
- Switching models triggers regression and permission/disclosure review.
- No model is promoted solely for average score when critical cases fail.
