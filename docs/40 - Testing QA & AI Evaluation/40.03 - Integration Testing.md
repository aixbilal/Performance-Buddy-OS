# Integration Testing

## Scope

Integration tests verify application services with real or production-compatible databases, migrations, repositories, files, queues, schedulers, IPC/API contracts, provider adapters, encryption, import/export, and backup/restore boundaries.

## Test design

Use isolated temporary stores and deterministic fakes for remote providers plus controlled contract tests against approved sandboxes. Verify transactions, constraints, revisions, audit/outbox atomicity, idempotency, retries, timeouts, cancellation, permission revocation, schema negotiation, and structured failure mapping.

File tests cover path traversal, link escape, encoding, rename, external edit, watcher overflow, and permission loss. Database tests cover locks, disk-full, power interruption simulation, migration failure, encryption keys, and corruption handling. Provider tests prohibit vendor fields crossing normalized ports.

## Data safety

Tests never target production accounts or user directories. Credentials are scoped test secrets and cleaned. Failure artifacts are redacted.

## Acceptance criteria

- Every infrastructure adapter passes a common contract suite.
- Failed integrations leave canonical data valid and recoverable.
- Tests prove cleanup and isolation under parallel execution.
