# Unit Testing

## Scope

Unit tests verify pure domain rules, value objects, validation, calculations, state machines, mappings, reason codes, redaction, permission decisions, and serialization without real network, filesystem, clock, random source, database, or model dependencies.

## Techniques

Use example, boundary, equivalence, table-driven, property-based, mutation, and state-transition tests. Inject clock, timezone, locale, random seed, ID generator, and policy versions. Decimal arithmetic receives exact expectations; missing, zero, unknown, pending, partial, rest, excused, deleted, and conflicted states remain distinct.

Rejected inputs assert both structured errors and absence of mutation. Property tests cover idempotency, monotonic revisions, bounded results, round trips, invariant preservation, and order independence only where semantics promise it.

Test names describe rule and outcome. Fixtures remain small, readable, immutable, and versioned. Mocking internal implementation details is avoided because it hides design drift.

## Acceptance criteria

- Every consequential branch and boundary has direct tests.
- Mutation testing or equivalent review identifies weak assertions in critical rules.
- Unit tests run deterministically and independently in any order.
