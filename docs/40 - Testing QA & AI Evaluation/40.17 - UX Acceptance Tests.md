# UX Acceptance Tests

## Coverage

Validate navigation, Today, focus sessions, capture, forms, approvals, explanations, search, tables/charts, settings, offline/sync state, conflicts, notifications, recovery, desktop large-monitor behavior, and mobile one-handed capture.

## Methods

Combine requirement-based automated tests, keyboard-only journeys, screen-reader checks, scalable text/zoom, contrast and focus inspection, reduced motion, touch target checks, usability sessions, interruption testing, and supported platform/browser-webview matrices.

Assert current location, visible system state, durable-save versus sync distinction, safe defaults, error recovery, undo, confirmation, focus return, no traps, non-drag alternatives, and accessible names/status announcements. Background refresh cannot reset focus or overwrite unsaved input.

Test loading, empty, stale, degraded, denied, blocked, conflict, and partial-success states with realistic content lengths and localization. Screenshots support review but cannot replace semantic/accessibility assertions.

## Acceptance criteria

- Primary journeys have no pointer-only or inaccessible step.
- Consequential actions expose effect, authority, and recovery.
- Usability findings have severity, owner, evidence, and release disposition.
