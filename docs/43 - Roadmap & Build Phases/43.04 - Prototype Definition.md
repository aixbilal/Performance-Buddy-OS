# Prototype Definition

## Purpose

The prototype is a learning artifact that proves product flow and architecture seams. It is not a production release, full CORE, or evidence that later AI/cloud/mobile capability is safe.

## Required slice

Provide a desktop-first local workflow with: application shell; Today view; one goal/action path; one session or tracker lifecycle; durable local database; deterministic validation/reason codes; basic navigation and keyboard access; offline startup; restart recovery; minimal export/backup; and automated unit/integration/end-to-end tests.

The slice uses stable IDs, revisions, timestamps/timezones, provenance where applicable, repository/application/domain separation, and migrations. UI success follows durable commit. Errors name safe state and recovery.

## Deliberate omissions

No cloud account, sync, mobile app, production AI, official CUI policy assumptions, comprehensive design system, or broad domain parity. Stubs/fakes are labeled and cannot masquerade as completed capability.

## Exit decision

Review usability, architecture complexity, learning, testability, performance, data integrity, and next risk. Prototype code may be retained, rewritten, or discarded; data compatibility matters only if explicitly promoted.

## Acceptance criteria

- A scripted demo works offline from clean setup through review.
- Known gaps and non-production shortcuts are documented.
- Prototype status is never shown as AVAILABLE capability.
