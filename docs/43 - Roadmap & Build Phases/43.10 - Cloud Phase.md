# Cloud Phase

## Status and outcome

`CLOUD` is optional/deferred. If promoted, it supplies secure multi-device sync, optional remote AI/service adapters, and possibly protected cloud backup without making CORE account- or network-dependent.

## Entry criteria

Stable schema/revisions/events, device metadata, operation log, conflict/tombstone rules, offline queue, data zones/consent, cloud threat model, encryption/key design, provider evaluation/exit plan, local export/backup, and cross-version protocol tests.

## Build sequence

Prototype transport with synthetic data; implement registration/revocation, authentication, encrypted envelopes, idempotent push/pull, cursors, conflicts, and resnapshot; test multi-device/offline failure; then consider remote providers and cloud backup as separate permissions/services.

The server coordinates delivery and access, not semantic truth. Sync is not backup. Provider lock-in, regions, retention, deletion, costs, outage, and incident recovery are disclosed and tested.

## Exit gates

Security, privacy, convergence, conflict, portability, deletion, recovery, performance/cost, and degraded-operation evidence pass.

## Acceptance criteria

- Local commits remain immediate and valid during cloud outage.
- Revoked/stale devices cannot overwrite or resurrect records silently.
- Cloud can be disabled/exported/deleted without locking local data.
