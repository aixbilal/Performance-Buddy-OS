# Mobile Phase

## Status and outcome

`MOBILE` is an optional/deferred companion for quick capture, lightweight review, notifications, and university use. It does not promise desktop parity or become a second semantic authority.

## Entry criteria

Stable shared domain/internal API contracts, device identity, encrypted sync or approved transfer, conflict/tombstone behavior, mobile offline store and migrations, data zones, threat model, framework evaluation, accessibility prototypes, and release/support plan.

## Build sequence

Start with one offline capture and reconciliation slice. Expand to quick study sessions, lecture logs, marks drafts, assignments/deadlines, routines, expenses, quick tests, University Mode, and notifications only after each owner contract passes. Camera/voice/OCR/AI creates drafts only.

Desktop retains complex configuration, deep analysis, bulk editing, and command-center ownership. Mobile local save and sync status remain distinct. Store/background limitations cannot change schedule or data truth.

## Exit gates

Offline capture, restart, migration, security, privacy, accessibility, battery/performance, sync conflict, revocation, store release, and portability tests pass on supported devices.

## Acceptance criteria

- Acknowledged capture survives offline termination.
- Mobile cannot redefine formulas, permissions, evidence, or statuses.
- Desktop CORE remains useful without mobile enrollment.
