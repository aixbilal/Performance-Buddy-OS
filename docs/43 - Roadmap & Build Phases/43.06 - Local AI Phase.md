# Local AI Phase

## Outcome

`LOCAL` adds qualified on-device classification, extraction, command parsing, and retrieval without transferring deterministic authority or making CORE hardware-dependent.

## Entry criteria

Stable CORE schemas/ports, data zones and permissions, structured-output contracts, local runtime isolation, benchmark harness, representative devices, model supply-chain policy, and explicit fallback behavior.

## Build sequence

Prototype the lowest-consequence use case; benchmark model/runtime options; implement supervised worker/sidecar, cancellation, budgets, provenance, and schema validation; test local-only egress; then expand only where value exceeds deterministic/manual baseline.

Hardware qualification records CPU/GPU/memory/storage/thermal/battery. CORE preempts AI under pressure. Unsupported devices receive a clear fallback. Model downloads disclose size, resource expectation, license, and removal.

## Exit gates

Application-specific quality, structured validity, safety, privacy, latency/resource, failure, and regression thresholds pass. Killing the runtime leaves CORE responsive and data intact.

## Acceptance criteria

- No local model output commits meaningful changes directly.
- Local-only data never leaves approved device boundaries.
- Model/runtime updates rerun benchmarks and evaluation.
