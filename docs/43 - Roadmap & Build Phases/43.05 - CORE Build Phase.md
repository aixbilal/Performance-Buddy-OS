# CORE Build Phase

## Outcome

CORE delivers a dependable offline-first personal command center with deterministic rules and no required AI, cloud, or mobile service.

## Scope sequence

1. Platform shell, canonical schemas, repositories, migrations, permissions, audit/events, backup/export/restore.
2. Goals/actions, Today planning, sessions, trackers/routines, deterministic rules and explanations.
3. Academic curriculum/attempt/assessment/marks/GPA with verified policy boundaries.
4. Knowledge/Obsidian lexical integration, development, fitness/recovery, language/routines, bounded money, reviews/analytics.
5. Security, accessibility, performance, packaging, updates, and release operations.

Vertical slices should complete data, domain, UI, testing, recovery, and documentation before the next broad area. Domain order may adapt to value/dependencies but cannot skip shared integrity foundations.

## Exit gates

Primary workflows operate offline, calculations reproduce, data is portable/recoverable, protected constraints hold, accessibility and performance budgets pass, security review closes, and a signed desktop release satisfies Phase 42.

## Acceptance criteria

- All committed CORE features are useful with optional capabilities disabled.
- No unresolved critical data, permission, security, calculation, migration, or recovery defect remains.
- The owner can explain architecture and consequential rules.
