# V1 Build Phase

## Outcome

`V1` provides a Smart Assistant for natural-language commands, read operations, explanations/tutoring, tests, and proposed plan/habit/academic changes with human approval.

## Entry criteria

Stable CORE application APIs and validation pipeline; structured AI contracts; provider/local routing; permissions/data zones; source-grounded retrieval; tool registry; approval/audit UI; AI run lifecycle; and versioned evaluation suites.

## Build sequence

Start with read/explanation tasks, then constrained proposal-only tools, approval flow, stale-proposal/conflict handling, idempotent commit, and rejection/undo evidence. Add domains only after their source and safety boundaries pass.

Remote use is optional and disclosed; local/manual fallback remains. V1 cannot invent facts, mark completion, change protected constraints, or silently execute meaningful writes. Provider failure produces truthful failure.

## Exit gates

Schema, grounding, citation, hallucination, tool, permission, approval, injection, safety, latency/cost, accessibility, and regression thresholds pass with signed evaluation evidence.

## Acceptance criteria

- Users distinguish response, proposal, approval, and completed write.
- Every consequential claim/action resolves to evidence and deterministic validation.
- Critical hallucination, secret, approval, or integrity failures block release.
