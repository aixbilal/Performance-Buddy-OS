# 30–60 Hour Initial Build Strategy

## Objective

Use a bounded 30–60 focused-hour experiment to prove one meaningful local vertical slice and expose architecture risks. The range is a planning constraint, not a promise of production readiness.

## Suggested allocation

| Work | Approximate share |
|---|---:|
| Decisions, setup, skeleton | 10–15% |
| Local schema/repository/migration | 15–20% |
| Domain commands and rules | 20–25% |
| Desktop Today/capture/session UI | 20–25% |
| Tests, offline/restart, backup/export | 15–20% |
| Review, profiling, documentation | 10–15% |

The slice should create an action, place it in Today, execute a session or tracker record, reconcile actual evidence, persist across restart/offline use, and show a simple review. Include at least one migration, export/backup check, keyboard path, and structured error.

Exclude cloud, mobile, multi-agent AI, broad analytics, exhaustive domains, polished motion, and complex customization. Use real architecture seams but minimal implementation.

## Stop conditions

At the timebox, demonstrate evidence, list gaps/debt, and decide continue, revise architecture, narrow, or discard. Do not hide incomplete integrity/security work behind visuals.

## Acceptance criteria

- The owner can explain and modify the slice without blind AI dependence.
- Data survives restart and failure tests.
- The retrospective identifies proven and unproven assumptions.
