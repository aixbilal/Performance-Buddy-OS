# Definition of Done

## Done checklist

A work item is done only when:

- approved behavior and non-goals are implemented through owning application/domain contracts;
- schema, migration, revision, provenance, permissions, offline/degraded, error, undo/recovery, and compatibility paths work;
- UX states, keyboard/accessibility, responsive/platform behavior, and explainability meet requirements;
- unit, integration, E2E, fault, security/privacy, performance, migration/restore, and AI evaluation suites pass as applicable;
- no unresolved critical/high data-integrity, permission, secret, safety, calculation, migration, or recovery defect remains;
- documentation, ADRs, capability registry/status, tests, support/runbooks, change/release notes, and evidence are updated;
- packaged artifact is reviewed and acceptance criteria are demonstrated.

Passing code review, compiling, a successful demo, or generated documentation alone is not done. Skipped/flaky/blocked tests are not passes. Waivers require authorized scope, compensation, owner, expiry, and rollback and cannot bypass invariants.

## Acceptance criteria

- Done evidence is reproducible against an immutable artifact/version.
- The owner can explain consequential implementation and trade-offs.
- Optional feature removal leaves lower-level data/workflows usable.
