# Master Roadmap

## Sequence

| Stage | Outcome | Advancement evidence |
|---|---|---|
| Prototype | One local vertical slice proves architecture and UX | Demonstrable workflow, tests, learning review |
| CORE | Trustworthy offline command center and owned domains | Release-quality deterministic, recovery, UX gates |
| LOCAL | Qualified on-device intelligence | Hardware, privacy, quality, fallback evidence |
| V1 | Smart assistant proposes/explains with approval | Structured, grounded, tool and governance gates |
| V2 | Historical adaptive coach | Sufficient evidence history and outcome evaluation |
| V3 | Cross-domain performance intelligence | Mature data/rules, specialist evaluation, safety |
| CLOUD | Optional multi-device/service capabilities | Opt-in security, sync, portability, recovery |
| MOBILE | Optional low-friction companion | Stable shared schemas, offline capture, secure sync |

Stages are dependency order, not promised dates. CLOUD/MOBILE may be researched in parallel but cannot weaken or block CORE. A higher stage may be deferred indefinitely if simpler behavior provides sufficient value.

## Governance

Each stage has scope, owner, entry/exit criteria, risks, ADRs, test/evaluation plan, data/permission impact, compatibility, fallback, release evidence, and retrospective. Status uses Phase 02 values.

## Acceptance criteria

- Roadmap status distinguishes proposed, planned, developing, evaluating, available, and deferred.
- Advancement follows capability promotion and release gates.
- Demotion/rollback preserves interpretable data and lower-level usefulness.
