# Planned vs Unplanned Sessions

## Distinction

A planned session originates from a plan item and preserves that immutable origin reference. An unplanned session begins independently and records its actual context. Both are valid; the interface must not punish necessary adaptation.

## Planned execution

Starting from a plan copies the planned target, duration, context, and constraints into an execution snapshot. Later changes to the plan do not rewrite that snapshot. On completion, actual duration, outcome, and evidence are attached and Phase 08 reconciliation updates the plan through its defined rules.

## Unplanned execution

Quick start requires only a primary type or `Other`. The user may link the session to an existing plan item during or after completion. Linking preserves the original unplanned origin and records the reconciliation action.

## Conflict handling

If an unplanned session overlaps a fixed commitment, protected recovery, or another recorded session, the system flags the conflict and requests correction or acknowledgment. It does not silently delete either record. Productive unplanned work may explain a missed plan but does not automatically mark the planned item complete.

## Analytics

Reports show planned adherence, useful adaptation, and unallocated work separately. They avoid moral labels. `CORE` performs matching through explicit links and deterministic rules; intelligence may suggest a likely match but needs confirmation.
