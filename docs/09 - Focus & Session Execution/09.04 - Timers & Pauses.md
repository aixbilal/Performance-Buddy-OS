# Timers & Pauses

## Timer model

The system records both wall-clock span and accumulated active duration. Active duration is the sum of explicit active intervals; paused and interrupted intervals are retained separately. Device sleep, clock changes, or application restarts must not create fabricated active time.

## Timer modes

- open-ended elapsed timer;
- target-duration countdown;
- interval structure such as work and break blocks;
- no-visible-timer mode while timestamps are recorded.

Timer mode is a presentation and pacing choice, not evidence of achievement.

## Pause behavior

Pause is immediate, reversible, and available offline. An optional reason may be captured after the pause without blocking it. Breaks inside an interval routine and external interruptions remain distinguishable. Automatic pause may be offered after detected inactivity, but the user confirms any correction.

## Time corrections

Users may edit start, end, and intervals with a reason when the change materially affects history. The application preserves original values in revision history. Overlaps, negative duration, implausible spans, and cross-device conflicts are flagged before acceptance.

## Failure handling

Timer state is checkpointed locally. If the app closes unexpectedly, recovery presents the last reliable interval and asks whether time after that point was active, paused, or unknown. Unknown time must never default to productive time.

## Capability

Timer calculation and validation are deterministic `CORE`; prediction and automatic categorization are optional proposals only.
