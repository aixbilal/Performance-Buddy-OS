# Session Types

## Shared taxonomy

A session has one primary type and optional tags. Baseline primary types are `Study`, `Development`, `Fitness`, `Routine`, `Language`, `Reading`, `Planning`, `Review`, and `Other`. Types organize capture and reporting; they do not determine success by themselves.

## Type contract

Every type defines:

- permitted context links;
- a suggested evidence shape;
- optional prompts and controls;
- applicable domain constraints;
- a neutral fallback when details are unknown.

Study may link course, topic, assessment, and knowledge item. Development may link project, issue, repository, or learning path. Fitness may link workout, exercise, distance, or recovery plan. Language may link language path, skill focus, and practical situation.

## Customization

Users may create tags and saved session templates without changing the canonical primary taxonomy. A custom template inherits a primary type so analytics remains comparable. Renaming a template must not rewrite historical labels.

## Classification authority

The user is authoritative for intent. Deterministic context may preselect a type. AI may propose classification with an explanation and confidence cue, but cannot silently move a session between domains.

## Version rule

All types above are `CORE`. AI-generated session structures belong to their declared intelligence label and must degrade to manual selection when unavailable.
