# Performance Domain

## Purpose

Define the coordination domain that turns goals into feasible plans, execution records, reconciliation, and next actions.

## Responsibilities

The Performance domain owns goals/systems/actions coordination, daily plan state, plan items, priority inputs, fixed commitments, protected constraints, execution linkage, planned-versus-actual reconciliation, day closure, and reasoned adjustment.

It consumes domain requirements such as academic deadlines, development paths, fitness recovery needs, and routine commitments. It does not own their specialist meaning.

## Core entities

Goal reference, system reference, action, plan, plan item, constraint, commitment, priority context, session reference, completion state, reconciliation record, adjustment, and reason code. Exact schemas belong to Phase 32.

## Invariants

- Historical plans and actual results remain distinguishable.
- Protected constraints are validated before optional allocation.
- Priority is contextual, not a fixed “academics always win” rule.
- Completion requires an explicit state and may reference evidence.
- AI recommendations are proposals; approved owner commands perform writes.

## Interactions

Academic supplies deadlines/risk, Fitness supplies load/recovery context, Routine supplies fixed/flexible commitments, and Analytics supplies derived history. Intelligence may recommend changes after permission and validation.

## Non-goals

The domain does not calculate CGPA, diagnose health, judge spiritual quality, optimize finances, or replace domain-specific learning paths.

## Acceptance criteria

The plan remains useful offline, changes are attributable and explainable, conflicting demands expose trade-offs, and domain records are referenced rather than duplicated.
