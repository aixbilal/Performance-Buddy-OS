# Intelligence Domain

## Purpose

Define AI context, runs, outputs, tools, recommendations, approvals, and evaluation while preserving deterministic and human authority.

## Responsibilities

Intelligence owns context construction, model/provider abstraction, prompts, tool calls, structured outputs, AI runs, retrieval, recommendation records, explanations, approval/rejection outcomes, evaluation, routing, and orchestration within capability levels.

## Capability progression

`LOCAL` performs bounded on-device transformations. `V1` reacts to user requests. `V2` analyzes historical evidence. `V3` reasons across domains and horizons. `CLOUD` may host optional providers. None is part of CORE merely because an API exists.

## Contract

Domain owners expose permission-scoped read/tools and validated commands. AI outputs record capability, context provenance, model/provider/version, uncertainty, tool results, validation, and approval state. A proposal cannot write directly to domain state.

## Invariants

Deterministic math, policy, permissions, constraints, and final validation stay outside LLM authority. Meaningful writes require human approval. Source text, inference, and recommendation remain distinguishable. Provider failure leaves confirmed data unchanged.

## Complexity boundary

Use the simplest reliable call or native sequential orchestration. Multi-agent/specialist architecture requires evaluation evidence, not aesthetic preference.

## Acceptance criteria

Outputs are traceable, testable, permission-aware, explainable, and safely degradable. Disabling AI preserves CORE. Rejected or invalid proposals cannot mutate owner records.
