# Domain Map

## Purpose

Provide the canonical relationship map among product domains and the phases that refine them.

## Map

```text
Personal configuration and goals
              ↓
        PERFORMANCE DOMAIN
     plan → action → evidence
       ↙      ↓       ↘
ACADEMIC  DEVELOPMENT  FITNESS/RECOVERY
    ↕          ↕             ↕
KNOWLEDGE   ROUTINE/SPIRITUAL   MONEY
       \       |        /
          ANALYTICS
              ↓
         INTELLIGENCE
  proposal → validation → approval
              ↓
           PLATFORM
 local data, security, offline, surfaces
```

Arrows mean controlled information flow, not transferred ownership. Platform supports every domain but does not decide business meaning. Intelligence consumes context but cannot become authoritative for facts or deterministic rules. Analytics derives views but does not rewrite source records.

## Phase alignment

- Performance: Phases 08–11 and 23.
- Academic: Phases 12–14 and 17.
- Knowledge: Phases 15–17.
- Development: Phase 18.
- Fitness/recovery: Phase 19.
- Routine/spiritual: Phase 20.
- Money: Phase 21.
- Analytics: Phase 22.
- Intelligence: Phases 24–31.
- Platform: Phases 32–42.

## Shared concepts

Stable identity, provenance, time, evidence, completion, approval, and capability labels cross domains. Their shared technical representation belongs to data/platform phases; semantic meaning remains with the domain owner.

## Boundary test

If a change alters what an entity means or which states are valid, the domain owner approves it. If it alters storage, delivery, or rendering without changing meaning, the platform/surface owner implements against the domain contract.
