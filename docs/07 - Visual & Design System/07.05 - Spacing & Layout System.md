# Spacing & Layout System

## Purpose

Define a consistent spacing rhythm, content widths, density modes, and responsive layout behavior.

## Spacing scale

Use named tokens based on a small base rhythm: `space.0`, `space.1`, `space.2`, through larger section/layout intervals. Exact values are provisional until prototypes are tested. Components must not introduce arbitrary spacing values without documented exception.

## Layout layers

- Canvas and application shell.
- Primary navigation region.
- Context header and global utilities.
- Main workspace with bounded reading/form widths.
- Optional supporting panels.
- Overlays, dialogs, and transient feedback.

## Density

Default density balances sustained use and scanability. Compact density may support tables, schedules, or experienced workflows but cannot reduce target size, focus visibility, or readability below accessibility requirements. Spacious density is not a substitute for hierarchy.

## Responsive rules

Reflow before truncating. Collapse supporting panels before primary content. Preserve action order and focus order. At narrow widths, convert multi-column context into staged sections or drawers without losing canonical ownership.

## Alignment

Align related labels/values and repeated rows. Use whitespace to express grouping before adding borders or cards. Maintain stable alignment when state badges or optional actions appear.

## Acceptance criteria

Representative pages share a rhythm, handle long/error/empty content, remain usable at supported zoom and window sizes, and avoid horizontal scrolling except for intrinsically wide data with an accessible alternative.
