# Iconography

## Purpose

Define icon semantics, sizing, accessibility, and library-selection constraints.

## Status

Icon usage rules are approved. The icon library is `RESEARCH REQUIRED` pending licensing, coverage, consistency, bundle size, and platform rendering review.

## Principles

Icons clarify known actions, objects, status, and navigation. They do not replace text for unfamiliar or consequential actions. Use one coherent family with consistent stroke/fill, optical size, and corner character.

## Categories

Navigation, action, entity/domain, status, source/provenance, capability/AI, platform/sync, and data-visualization symbols. Domain icons identify but do not encode complete meaning.

## Rules

- Provide accessible names for icon-only controls; decorative icons are hidden from assistive technology.
- Pair critical, error, warning, AI-proposed, and privacy states with text.
- Avoid ambiguous metaphors for save/sync/cloud authority.
- Destructive icons require explicit labels in confirmation contexts.
- Directional icons adapt correctly for locale/direction if localization expands.
- Custom icons must meet the same grid and stroke rules.

## Sizing

Use semantic size tokens and adequate control targets. Do not shrink icons until details become indistinguishable. Badge overlays are limited and never obscure the base symbol.

## Acceptance criteria

Icon comprehension is tested in context, all interactive icons are keyboard/focus accessible, and the application remains understandable if icons fail to load.
