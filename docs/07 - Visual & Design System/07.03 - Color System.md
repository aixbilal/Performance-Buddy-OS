# Color System

## Purpose

Define semantic color roles, contrast rules, state combinations, and palette governance without prematurely locking raw values.

## Status

Semantic roles are approved. Exact color values are `PROVISIONAL` pending reference review, display testing, dark/light evaluation, and accessibility verification.

## Token families

- `color.canvas.*`: application backgrounds.
- `color.surface.*`: raised, inset, selected, and overlay surfaces.
- `color.text.*`: primary, secondary, muted, inverse, disabled.
- `color.border.*`: subtle, strong, focus, selected.
- `color.action.*`: primary, secondary, destructive, disabled.
- `color.status.*`: success, warning, danger, information, neutral.
- `color.data.*`: chart series designed for distinguishability.
- `color.domain.*`: optional restrained identifiers, never sole meaning.
- `color.ai.*`: proposal/inference identity distinct from confirmed state.

## Rules

Text and essential controls must pass the approved accessibility contrast target once locked. State uses label/icon/pattern in addition to color. Red is reserved for danger/error, not low productivity. Green indicates confirmed success, not moral worth. AI accent must not imply authority. Domain accents remain subordinate to semantic status.

## Dark theme

Use layered dark neutrals with readable text and restrained accents. Avoid large pure-black/white extremes where they cause glare. Disabled content remains legible but clearly inactive.

## Charts

Series remain distinguishable under common color-vision variations and grayscale. Sequential/diverging palettes match data meaning; never use red-green alone.

## Acceptance criteria

Token combinations are tested across default, hover, focus, selected, disabled, loading, error, and high-density states; no raw product color bypasses tokens.
