# Phase 07 — Visual & Design System

## Purpose

Define a coherent, accessible, token-driven visual system for Performance Buddy OS across desktop CORE and future mobile surfaces.

## Phase responsibility

Phase 07 owns visual direction, semantic color, typography roles, spacing, grids, surfaces, borders/elevation, icons, charts, motion tokens, Focus Mode language, reusable patterns, component taxonomy, tokens, and design acceptance. Phase 05 owns information hierarchy; Phase 06 owns interaction behavior.

## Direction

The intended experience is a calm, serious command center: dark-first, restrained, high-clarity, and suitable for sustained desktop use. Matte or near-black surfaces, limited depth, disciplined typography, and purposeful data visualization may express this direction. Reference images guide mood, not literal layout.

## Decision status

The semantic system and accessibility constraints are approved. Exact color values, font families, icon library, component library, chart library, and implementation technology are `PROVISIONAL / RESEARCH REQUIRED` until visual references, licensing, platform rendering, accessibility tests, and Phase 44 decisions support approval.

## System rules

- Use semantic tokens rather than raw values in product components.
- Facts, projections, inference, AI proposals, warnings, and confirmed states must be distinguishable beyond color.
- Density is purposeful; large monitors add context, not card clutter.
- Motion supports continuity and respects reduced-motion settings.
- CORE visual behavior does not depend on cloud assets.
- Mobile adapts patterns rather than shrinking desktop layouts.

## Acceptance criteria

Representative screens are consistent, keyboard/focus states are visible, contrast and scaling pass accessibility review, tokens cover all states, reference influence remains buildable, and no visual treatment weakens human control or domain meaning.
