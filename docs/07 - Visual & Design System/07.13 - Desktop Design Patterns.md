# Desktop Design Patterns

## Purpose

Define reusable desktop visual patterns for the command center, navigation, entity work, planning, and reviews.

## Shell patterns

Stable primary navigation, context header, main workspace, optional context panel, global search/palette, and scoped status area. Exact shell layout is responsive and token-driven.

## Content patterns

- Command-center operational summary.
- Entity header and detail sections.
- Master/detail collection for courses, paths, or records.
- Plan/timeline and session execution.
- Data table with filters and accessible summary.
- Review view with metric explanation and drill-down.
- Proposal comparison with evidence and approval.
- Settings and permission panels.
- Empty/error/recovery views.

## Pattern rules

Primary actions remain limited and consistently placed. Secondary panels inspect but do not duplicate edits. Dense tables can use compact tokens but retain target/focus accessibility. Sticky elements must not hide content at zoom. Resizable areas provide defaults, constraints, reset, and keyboard alternatives.

## Large monitors

Use additional space for evidence, relationships, or comparison. Limit simultaneous columns and preserve bounded reading width. Privacy-sensitive panels can be concealed quickly.

## Capability states

AI suggestions, sync, indexing, and background jobs use scoped status patterns. Optional failures do not create global visual shutdown.

## Acceptance criteria

Patterns cover common CORE flows, maintain one canonical editor, handle long/empty/error/loading data, and remain coherent from minimum desktop size through large displays.
