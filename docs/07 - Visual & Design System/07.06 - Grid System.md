# Grid System

## Purpose

Define adaptive grids for desktop command-center, entity, review, and future mobile layouts.

## Grid model

Use an adaptive grid with named layout regions rather than a fixed universal column count. Exact columns, gutters, and breakpoints are `PROVISIONAL` until desktop and mobile prototypes are measured.

## Desktop regions

- Shell/navigation rail or region.
- Primary workspace.
- Optional secondary context.
- Optional tertiary inspector only on sufficiently large displays.

Primary reading and editing retain bounded width even when the canvas is wide. Dashboards may use modular columns, but component span follows information importance rather than symmetry.

## Breakpoint behavior

Breakpoints respond to content stress, not device brands. When space contracts: reduce peripheral padding, collapse tertiary context, move secondary context behind an explicit control, stack content, then simplify navigation. Critical actions and status remain visible.

## Mobile

Mobile uses a single primary flow with occasional full-width sheets or focused overlays. It does not inherit desktop multi-panel density.

## Data layouts

Tables use alignment and horizontal containment deliberately. Timelines and schedules provide list alternatives. Charts align with accompanying summary and controls.

## Acceptance criteria

Grid tests cover minimum desktop, common laptop, large monitor, zoom, long labels, empty/error states, and future mobile widths without overlap or broken focus order.
