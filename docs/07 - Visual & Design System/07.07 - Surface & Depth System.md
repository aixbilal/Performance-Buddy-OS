# Surface & Depth System

## Purpose

Define visual grouping and layering through restrained surfaces and explicit interaction depth.

## Depth levels

| Level | Purpose |
|---|---|
| Canvas | Application background |
| Base surface | Primary workspace/sections |
| Raised surface | Menus, cards needing separation, side context |
| Overlay | Dialog, popover, command/search layer |
| Critical overlay | Rare blocking safety or destructive confirmation |

## Rules

Use whitespace and hierarchy before adding a new surface. Cards are not the default container for every paragraph. A raised surface must represent grouping, interaction, or layering—not decoration. Nested card depth is limited.

Dark surfaces use subtle tonal separation and borders; shadows are restrained because heavy shadow/glow reduces calmness and can blur boundaries. Overlay scrims preserve context while ensuring focus and readability.

## Interaction state

Hover, focus, selected, pressed, disabled, and drag states are distinct. Focus is not represented only through elevation. Selected state does not resemble a primary action. AI proposal surfaces are visually identifiable but not more authoritative than confirmed content.

## Privacy

Sensitive surfaces can support quick concealment and avoid translucent treatments that leak underlying text. Screenshots/notifications are addressed by platform/privacy phases.

## Acceptance criteria

Users can infer grouping and active layer without excessive borders/shadows; focus traps and z-order are correct; and depth remains understandable with motion disabled.
