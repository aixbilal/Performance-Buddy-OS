# Typography System

## Purpose

Define typographic roles, readability, scaling, numeric treatment, and font-selection constraints.

## Status

Roles and behavior are approved. Font families are `RESEARCH REQUIRED` pending licensing, platform rendering, language coverage, performance, and accessibility testing.

## Roles

| Role | Use |
|---|---|
| Display | Rare product/empty-state moments |
| Page title | Current destination/entity |
| Section heading | Major content groups |
| Subheading | Nested groups and cards |
| Body | Explanations and primary reading |
| UI label | Controls, navigation, metadata labels |
| Caption | Provenance, freshness, secondary metadata |
| Numeric | Marks, time, money, metrics, tables |
| Code/mono | IDs, commands, formulas, technical traces only |

## Rules

Use a limited type scale with clear weight/size/spacing hierarchy. Body text retains comfortable line length and line height. All caps is limited to short labels. Tabular numerals support comparison where available. Academic grades, money, and timers must not rely on stylized glyph ambiguity.

## Scaling and language

Text responds to user/OS scaling and zoom without clipping. Layout supports long names, localization expansion, German/Italian characters, mathematical notation, and mixed numeric content. Truncation provides accessible full text and is not used for critical data.

## Performance

Fonts must be bundled or locally reliable for offline CORE, with deliberate fallbacks and no mandatory remote download.

## Acceptance criteria

Hierarchy survives zoom, long content, high-density tables, and fallback fonts; labels remain readable; and typography never substitutes for semantic structure.
