# Motion System

## Purpose

Define tokenized motion roles, reduced-motion behavior, and performance constraints.

## Status

Motion roles are approved. Exact durations, easing curves, and spring values are `PROVISIONAL` pending prototype and target-hardware testing.

## Roles

- Immediate feedback: press, toggle, focus confirmation.
- State transition: expand/collapse, insertion/removal, status change.
- Spatial navigation: panel, detail, or route continuity.
- Overlay: dialog, menu, palette, tooltip.
- Progress: determinate or indeterminate work.
- Attention: rare nonrepeating signal for relevant change.

## Rules

Motion begins from user/system cause, ends in the true persisted state, and never blocks input unnecessarily. Avoid simultaneous unrelated animations. Do not animate continuously for ambient dashboards or use celebration to judge behavior.

## Reduced motion

Provide a complete reduced-motion mode using instant changes, fades, or simple emphasis without spatial movement. No workflow, hierarchy, chart meaning, or confirmation depends on animation.

## Performance

Prefer compositor-friendly properties where implementation allows, but technology selection remains open. Animation must not cause layout instability, excessive resource use, or lost focus.

## Token model

`motion.duration.*`, `motion.easing.*`, `motion.distance.*`, `motion.opacity.*`, and `motion.reduced.*`. Components consume role tokens rather than raw timing.

## Acceptance criteria

Motion is tested at target performance, reduced-motion preference is honored, interrupted transitions settle correctly, and persistence failures do not display successful completion.
