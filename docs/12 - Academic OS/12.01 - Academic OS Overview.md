# Academic OS Overview

## Purpose

Academic OS is the domain source of truth for the user’s university structure and academic history. It turns verified curriculum data and personal records into stable entities that planning, calculations, knowledge, analytics, and intelligence can safely reference.

## Core model

`University → Program → Curriculum Version → Semester Placement → Course → Course Attempt`

Prerequisites link versioned courses. Enrollment links the user to offerings and attempts. Assessments and calculations extend this model in Phase 13.

## Responsibilities

Phase 12 owns identity, source provenance, version applicability, course structure, credit hours, attempts, outcomes, prerequisites, enrollment, imports, and dashboard projections. It emits validated academic facts and risk inputs without owning daily schedules or learning mastery.

## Capability

Manual creation, import review, validation, local storage, graph traversal, and factual views are `CORE`. `LOCAL` or `V1` may extract candidate fields; `V2` may identify patterns; all policy-dependent claims still require authoritative sources and deterministic validation.

## Failure behavior

Missing or contradictory sources produce `UNRESOLVED` records and block dependent official calculations. The system preserves both conflicting claims and never selects the more convenient one silently.

## Acceptance criteria

Every academic entity is version-aware, source-linked, auditable, privacy-controlled, and usable offline; projections are labeled and never presented as official university decisions.
