# University & Program Model

## Purpose

Define stable identity and applicability for an institution and an enrolled academic program without hard-coding unverified CUI facts.

## University entity

Fields include stable ID, official name, recognized abbreviations, campus or location when policy-relevant, official source references, and effective dates. Names from imported records are aliases until matched and confirmed.

## Program entity

Fields include stable ID, university ID, official program name, credential type, department, campus, delivery mode where relevant, admission cohort or intake, expected duration as sourced, status, and linked curriculum versions.

## Applicability

Program policy may vary by campus, cohort, admission term, or effective date. The model stores these dimensions explicitly and never assumes that a similarly named program uses the same curriculum.

## User relationship

Enrollment in a program is a personal record with student-specific dates and status. It does not modify the official program definition. Sensitive identifiers should be minimized, encrypted according to platform policy, and excluded from routine UI.

## Acceptance criteria

Duplicate institutions and programs can be detected without destructive merging; applicable sources are traceable; unknown cohort/campus remains visible; and one user can retain historical program relationships.
