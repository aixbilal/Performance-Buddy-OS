# Vector Search Research

## Decision

Select vector index/storage and retrieval architecture only if embedding evaluation proves material value beyond CORE lexical search.

## Options and criteria

Compare in-process libraries, database extensions, local vector stores, and optional remote services. Evaluate offline support, index algorithms, filtering/permission partitions, updates/deletes, durability versus rebuildability, metadata, hybrid search, scale, memory/disk, startup/query/build latency, encryption, backup, licensing, packaging, observability, and portability.

## Prototype

Build representative vault and knowledge indexes; test incremental changes, rename/delete/revocation, corrupt index, rebuild, mixed generations, filters, concurrent queries, large corpus, low resource, and exact source citation. Index remains disposable and never outranks files.

Remote vector service is `CLOUD`, requires separate consent, and cannot receive local-only content. Provider-specific IDs stay behind adapters.

## Research status

`RESEARCH REQUIRED`: no library/store/algorithm/hybrid strategy is approved.

## Acceptance criteria

- Permission filtering is enforced during ingestion and query.
- Index loss recovers from authorized sources.
- The ADR documents data export and replacement cost.
