# Orchestration Framework Research

## Decision

Determine whether V2/V3 orchestration needs a framework or should remain an application-owned state machine. Native/simple orchestration is the baseline comparator.

## Criteria

Evaluate explicit state, typed context, checkpoints/resume, cancellation, retries/idempotency, human approval, tool permissions, specialist routing, observability, test determinism, local/cloud provider portability, persistence, failure recovery, security, versioning, learning/maintenance cost, and framework exit.

## Prototype

Implement one sequential specialist flow with context selection, pause/approval, failure, restart/resume, stale source, cancellation, retry, and audit using both simple native code and finalist frameworks. Measure correctness, debuggability, code/operational complexity, latency, and lock-in.

Do not adopt a graph/multi-agent framework for a linear V1 flow or because a demo is visually impressive. Framework state cannot become canonical domain truth.

## Research status

`RESEARCH REQUIRED`: orchestration remains `FUTURE`; no framework, including LangGraph, is approved.

## Acceptance criteria

- The need exceeds what the native baseline handles safely.
- Approval/resume tests prove no duplicate commits.
- The ADR includes framework-removal and state-migration plans.
