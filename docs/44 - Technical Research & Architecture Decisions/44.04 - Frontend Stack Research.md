# Frontend Stack Research

## Decision

Select the UI language/framework, build tooling, state/query/form approach, routing, validation, testing, and styling integration used inside approved desktop/mobile shells.

## Criteria

Evaluate type safety, accessibility primitives, keyboard/focus behavior, error boundaries, rendering performance, large lists/charts, offline state, form validation, testability, developer tooling, bundle/build speed, ecosystem/security, long-term maintenance, interoperability with desktop framework, and ability to keep domain logic outside UI state.

## Prototype

Build Today navigation, contextual panels, a complex validated mark form, session timer, command palette, virtualized accessible list, offline/error states, approval dialog, theme tokens, and state restoration. Measure interaction latency, bundle size, accessibility, test complexity, and failure isolation.

Avoid selecting multiple overlapping state systems without demonstrated need. SSR/web hosting features have low weight unless a later approved surface requires them.

## Research status

`RESEARCH REQUIRED`: framework, versions, build tool, router, form/state/query libraries, and styling method.

## Acceptance criteria

- The choice preserves application/domain separation.
- Accessibility and desktop integration are tested, not assumed.
- Migration and dependency-reduction paths are documented.
