# Encryption Research

## Decision

Select vetted designs/libraries for database encryption, file/backup encryption, sync transport/at-rest protection, optional end-to-end encryption, and key generation/storage/rotation/recovery.

## Criteria

Threat model assets and attackers first. Evaluate maintained audited libraries, algorithms/modes and parameters, platform crypto/secret stores, password KDF, key hierarchy/wrapping, metadata leakage, streaming, atomic writes, performance, platform interoperability, backup/recovery, rotation/revocation, device enrollment, E2EE feature trade-offs, licensing, and migration.

## Prototype and review

Test wrong/missing key, tamper, interrupted write/rotation, restore, device loss, cross-version/platform, large files, low storage, revoked device, and compromised credential procedures. Seek specialist review before consequential deployment.

No custom cryptographic algorithm or format is permitted. Encryption does not replace authorization, sandboxing, secure deletion limitations, or device security.

## Research status

`RESEARCH REQUIRED`: no library, algorithm set, key store/hierarchy, or E2EE boundary is approved.

## Acceptance criteria

- The ADR maps controls to threats and recovery realities.
- Keys never appear in ordinary records, logs, AI, or artifacts.
- Rotation/recovery tests preserve valid data without weakening access.
