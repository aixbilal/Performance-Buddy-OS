# UI Library Research

## Decision

Select component primitives/library compatible with the chosen frontend/desktop stack and Phase 07 design tokens without surrendering accessibility or product-specific behavior.

## Criteria

Evaluate semantic/accessibility quality, keyboard/focus, dialogs/menus/comboboxes/tables, high contrast and reduced motion, theming/tokens, styling control, density, bundle/performance, virtualization, form integration, platform feel, testing, SSR only if relevant, documentation, maintenance/security, licensing, version churn, and component escape hatches.

## Prototype

Build navigation, command palette, quick capture, complex mark form, date/time/timezone input, approval dialog, data table, toast/notification center, focus mode, error/empty/loading states, and large-text/keyboard/screen-reader scenarios with realistic content.

Visual similarity alone is insufficient. Generated DOM/accessibility and focus recovery are inspected. Custom components remain possible where the library cannot meet a requirement.

## Research status

`RESEARCH REQUIRED`: no UI component library is approved.

## Acceptance criteria

- Primary journeys have no pointer-only or focus-trap defects.
- Tokens can be applied without fragile overrides.
- The ADR includes replacement and upgrade risk.
