# Desktop Framework Research

## Decision

Select the desktop runtime/framework and required plugins for the primary offline command center. Electron and Tauri are initial candidates; credible alternatives and a simpler baseline may be included.

## Criteria

Compare OS/architecture support, renderer/process security, privileged bridge, filesystem/database/native integration, background work, tray/notifications/shortcuts, windows, accessibility, local AI sidecars, updater/signing, package/startup/memory/battery, testing/debugging, ecosystem maintenance, licensing, developer learning, and migration/exit cost.

## Prototypes

Run equivalent cold start; database-heavy Today; vault indexing; timer across sleep/resume; tray capture; notification action; local-AI worker crash; multiple instances; signed install/update; migration/recovery; and keyboard/screen-reader journeys on proposed platforms.

Security blockers cannot be offset by smaller packages or familiarity. Benchmark versions, hardware, data, configuration, native dependencies, and known gaps.

## Research status

`RESEARCH REQUIRED`: no framework, plugin, updater, or support matrix is selected.

## Acceptance criteria

- Equivalent prototypes and threat models exist for finalists.
- Framework-specific code is confined behind declared boundaries.
- The ADR includes dependency patching and exit strategy.
