# AI SDK Research

## Decision

Select whether to use provider SDKs, a provider-neutral SDK, or thin internal adapters for AI streaming, structured output, tools, usage, errors, and cancellation.

## Criteria

Evaluate provider coverage, type/schema support, tool semantics, streaming/cancellation, retries/idempotency, error normalization, telemetry defaults, data handling, version churn, bundling/runtime compatibility, local-model support, testing/fakes, observability, security/supply chain, licensing, maintenance, and escape hatches.

## Prototype

Implement the same AI run across at least one local and candidate remote adapter: authorization, streaming structured output, bounded tool call, cancellation, retry/rate failure, usage/cost, validation, and redacted tracing. Confirm provider-specific fields terminate at adapters.

An SDK cannot own domain tools, permissions, memory, approval, or deterministic validation. Convenience wrappers must not hide data destinations or retries.

## Research status

`RESEARCH REQUIRED`: no SDK or abstraction package is approved.

## Acceptance criteria

- Contract tests work with deterministic fake and every adapter.
- SDK removal/replacement is feasible without domain rewrite.
- The ADR records telemetry, lock-in, and update risks.
