# Manual Backup

## Purpose

Manual backup lets the user create an immediate verified recovery point before travel, migration, repair, experimentation, or other consequential work.

## Workflow

The user selects a safe destination and optional approved scope. The application shows estimated size, included/excluded data, encryption state, key/recovery implications, available space, and whether the destination is inside the live-data or sync folder. Unsafe same-location choices trigger clear warnings or blocking policy.

The application creates a consistent snapshot, writes to a new artifact, records a manifest and checksums, encrypts as configured, verifies readability/decryptability, and reports exact location and result. It never overwrites an existing backup silently. Cancellation preserves the source and removes or labels partial output.

Manual backup does not pause or disable the automatic strategy. Copying the database file through a file manager while it is live is not an approved backup procedure.

## Acceptance criteria

- The user receives an unambiguous verified or failed result.
- Existing artifacts and canonical data remain unchanged on failure.
- A created manual artifact passes the same restore validation as automatic backups.
