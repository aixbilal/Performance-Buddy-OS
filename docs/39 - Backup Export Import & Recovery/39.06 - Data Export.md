# Data Export

## Purpose

Data export provides user-controlled portability, inspection, and transfer without requiring cloud access.

## Scope selection

The user chooses domains/entities, date range, attachments, deleted history where authorized, provenance, derived data, privacy redaction, and encryption. The preview states included/excluded categories, estimated size, format/version, destination, sensitivity, and known round-trip limits.

## Artifact

Use documented, versioned, non-proprietary formats where practical. Include a manifest, schema versions, stable IDs, revisions, timestamps/timezones, units/currencies, enums and unknown states, relationships, checksums, provenance where permitted, and explicit exclusions. Human-readable and machine-readable representations may coexist.

Passwords, tokens, private keys, recovery codes, and other mandatory `NEVER_AI` secrets are excluded. Sensitive exports warn about destination and use optional or required encryption by policy. Temporary output is minimized and atomically promoted after verification.

## Acceptance criteria

- Export works fully offline and does not mutate source records.
- Deterministic repeated exports of the same snapshot are explainably comparable.
- Round-trip tests preserve all declared supported meaning.
