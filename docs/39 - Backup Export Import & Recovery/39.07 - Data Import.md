# Data Import

## Pipeline

Import detects declared format/version, enforces type and size limits, scans/parses in isolation, validates structure and checksums, records source provenance, maps raw to normalized fields, and creates a candidate workspace. No untrusted file, macro, formula, script, or embedded command executes.

The preview reports entity counts, mappings, unknowns, duplicates, conflicts, unsupported fields, destructive implications, and atomicity boundaries. The user confirms before application. Domain commands validate every record transactionally; failure leaves approved records unchanged.

## Identity and replay

Imported stable IDs are mapped explicitly and never overwrite local identity accidentally. Re-import uses source identity/checksum, importer version, mapping decisions, and idempotency keys. Missing, zero, unknown, pending, deleted, and excused values remain distinct.

Partial imports commit only at documented boundaries and produce a complete result/reconciliation report. Original source artifacts remain read-only and retained according to permission and policy.

## Acceptance criteria

- Malformed, hostile, duplicate, interrupted, and version-mismatch tests pass.
- No record commits without provenance, preview, validation, and confirmation.
- Unsupported content is reported rather than silently dropped.
