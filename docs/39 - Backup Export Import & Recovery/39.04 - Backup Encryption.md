# Backup Encryption

## Requirement

Backups containing protected data use an approved authenticated-encryption format independent of live database encryption. Copying an encrypted database may not protect attachments, manifests, configuration, or metadata and is insufficient by itself.

## Key lifecycle

Keys or passphrases are generated/derived through vetted libraries and stored, wrapped, or communicated under Phase 38 controls. The artifact stores format, version, algorithm identifier, parameters, key reference—not secret key material—classification, and authenticated integrity metadata.

Recovery design balances confidentiality with realistic key loss. Recovery material is separated from the backup where practical and never placed in logs, AI context, ordinary exports, or the same unprotected directory. Rotation creates new verified artifacts before retiring old key access.

Metadata leakage through filenames, sizes, timestamps, and directory names is minimized and disclosed. Decryption uses bounded plaintext lifetime and never overwrites the source artifact.

`RESEARCH REQUIRED`: select format, libraries, algorithms, KDF, key wrapping, recovery UX, and cross-platform compatibility. No custom cryptography.

## Acceptance criteria

- Wrong-key, tamper, rotation, lost-key, and cross-version restore tests fail safely.
- Secrets are absent from artifacts, manifests, logs, and diagnostics.
- Encryption claims match the complete artifact boundary.
