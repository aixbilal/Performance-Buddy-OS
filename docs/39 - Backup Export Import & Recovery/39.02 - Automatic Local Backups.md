# Automatic Local Backups

## Trigger model

Automatic local backups run on a persistent Phase 33 job schedule and before qualifying migrations or risky maintenance. Exact frequency and retention are `RESEARCH REQUIRED` and configurable within safe policy bounds.

## Execution

The job checks destination, available space, key access, database integrity, active migration/write state, and retention policy. It obtains a transactionally consistent snapshot or approved database-native backup without copying a live database unsafely. Output is written to a unique temporary artifact, encrypted where required, verified, and atomically promoted.

Each artifact includes backup ID, creation and source times, application/schema versions, source database identity/revision checkpoint, included assets, exclusions, encryption format/key reference, checksums, size, and verification result. Retention cleanup is deterministic and never deletes the last verified recovery point accidentally.

## Failure behavior

Failures are visible, retry-bounded, privacy-safe, and do not block ordinary CORE work unless storage integrity is at risk. Sleep, shutdown, disk-full, locked destination, and interrupted jobs resume or restart safely.

## Acceptance criteria

- Crash, disk-full, concurrent-write, duplicate trigger, and cleanup tests pass.
- Only verified artifacts count as successful backups.
- Users can inspect last success, location, age, coverage, and failure reason.
