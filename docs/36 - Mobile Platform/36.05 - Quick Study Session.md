# Quick Study Session

## Purpose

Quick Study Session starts or records study with minimal setup while preserving the Phase 09 session lifecycle and Phase 14 evidence rules.

## Minimum flow

The user selects a course/topic or an unclassified study context, chooses planned or unplanned status, and starts a timer or enters an actual duration. The record stores stable session ID, event times, capture source, associated action where known, lifecycle state, and revision.

Pause, resume, finish, abandon, and interruption remain distinct. Timer state persists across screen change, backgrounding, process termination where supported, and connectivity loss. OS timers are delivery aids; elapsed-time truth uses durable timestamps and monotonic timing where available.

## Evidence boundary

Elapsed time is execution evidence, not proof of coverage or mastery. Optional notes, topics, materials, difficulty, and outcome may be added at closure or later. A notification action revalidates current session state before changing it.

## Acceptance criteria

- Duplicate taps cannot create duplicate active sessions.
- Restart and offline tests preserve timer state and local completion.
- Planned versus actual time and evidence meaning remain distinct.
