# Capture Device Principle

## Principle

Mobile is optimized to capture truthful minimum data now and enrich it later. Speed reduces friction but never removes validation, provenance, uncertainty, or correction.

## Capture sequence

1. Select or safely infer a bounded record type.
2. Prefill non-authoritative context such as current time or explicitly selected course.
3. Request only required fields.
4. Validate locally through the owning domain command.
5. Commit durably and confirm local save.
6. Display pending/sync state separately.
7. Offer undo, correction, or later enrichment.

An incomplete or interrupted input becomes a labeled local draft, not a submitted record. Camera, voice, barcode, document scan, or AI extraction preserves original evidence where permitted and produces candidates for review.

## Truth safeguards

Defaults cannot assert attendance, completion, marks, mastery, expense category, or deadline source. Timestamps distinguish event time, capture time, and later edit time.

## Acceptance criteria

- Local-save success is never confused with remote sync.
- Interrupted captures remain recoverable without false submission.
- Provenance and uncertainty survive later desktop enrichment.
