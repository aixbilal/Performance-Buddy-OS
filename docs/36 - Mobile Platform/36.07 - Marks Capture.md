# Marks Capture

## Purpose

Marks Capture provides a fast, privacy-aware draft path into the Phase 13 marks-entry contract. It never treats an unverified screen, message, photograph, OCR result, or AI extraction as an official mark.

## Required data

Capture assessment item and course attempt, earned marks, maximum marks where known, status, source reference/class, assessed and capture dates, actor, note, verification state, and revision. Zero is a value; missing is `UNKNOWN`. Pending, absent, excused, and not held remain distinct.

## Workflow

Manual input or extraction creates a draft. Local validation checks numeric format, bounds, item identity, duplicates, and scheme applicability. The user reviews warnings and context before publication. Corrections create new revisions rather than overwriting history.

Marks are sensitive. Camera and notification previews minimize disclosure; external OCR or AI requires explicit scoped permission.

## Acceptance criteria

- A published mark is locally durable, traceable, and reversible.
- OCR/AI cannot publish or calculate official results independently.
- Save or sync failure cannot display an unpersisted value as committed.
