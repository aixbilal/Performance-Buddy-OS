# Mobile Offline Requirements

## Required offline behavior

Committed mobile capture supports sessions, lecture logs, marks drafts, deadlines, routine actions, expenses, and eligible quick tests without network. Each local record receives a stable ID, revision, event and capture times, provenance, actor/device context, and sync eligibility/state.

## Local durability

The mobile store uses transactional writes, schema constraints, migration and crash recovery, encryption/key integration, corruption detection, and safe export/recovery appropriate to the platform. An acknowledged save means durable local commit, never merely an in-memory queue.

## Degraded state

Remote official-source refresh, cloud AI, cross-device updates, and new remote test generation may be unavailable. The UI names the missing freshness or capability without blocking unrelated capture. Cached sensitive data follows device lock, retention, redaction, and sign-out policy.

Background suspension, forced termination, disk pressure, clock/timezone change, and long offline periods preserve drafts and queued operations. The app never creates a blank store silently after open or migration failure.

## Acceptance criteria

- Airplane-mode end-to-end tests cover every committed capture flow.
- Restart and storage-failure tests preserve truthful status.
- No CORE-derived mobile capture is falsely marked online-required.
