# Mobile Framework Evaluation

## Decision scope

The framework must implement approved mobile contracts rather than redefine them. Native, cross-platform, and shared-code candidates are evaluated with equivalent prototypes and current primary evidence.

## Evaluation criteria

Compare supported OS versions and devices, accessibility, secure storage, local database and migrations, offline reliability, background transfer, notifications, deep links, camera/microphone/files, biometrics, encryption, performance, battery, startup, package size, testing, debugging, ecosystem health, dependency security, release tooling, app-store compliance, developer productivity, and long-term maintenance.

Prototype airplane-mode captures, interrupted drafts, database migration, camera/OCR draft, active session across backgrounding, push/local notification action, encrypted sync and conflict, revoked device, deep link, accessibility scaling, and low-storage recovery.

## Decision governance

Record candidate versions, benchmark devices, measurements, platform gaps, native escape hatches, costs, rejected alternatives, and migration/exit risk in an approved architecture decision record.

`RESEARCH REQUIRED`: framework, state/data libraries, secure-storage adapter, sync transport, notification service, support matrix, and release pipeline.

## Acceptance criteria

- Risk-focused prototypes run on every proposed supported platform.
- Offline, security, and accessibility blockers outweigh code-sharing convenience.
- The decision preserves shared domain contracts and a practical exit path.
