# Mobile Sync

## Role

Mobile synchronization is an optional `CLOUD` dependency used by the `MOBILE` surface. Local capture remains valid without it. Phase 34 is authoritative for device registration, encryption, changes, cursors, conflicts, tombstones, retries, and provider selection.

## Reconciliation

The client validates account, device, consent, permission, protocol, and schema; uploads eligible operations idempotently; obtains durable acknowledgement; pulls after the last verified cursor; verifies integrity and causal dependencies; applies valid changes transactionally; preserves conflicts; and advances only safe checkpoints.

Sync state is visible per item: local-only, queued, transferring, synchronized, conflict, blocked, error, or tombstoned as applicable. A global badge cannot hide partial failure. Arrival time and device clocks do not justify last-write-wins.

Mobile background-transfer APIs are best-effort. Suspension or OS limits delay delivery without changing local truth. Revoked devices cannot resume; stale devices cannot resurrect tombstoned records.

## Acceptance criteria

- Repeated retry and reconnection create no duplicate domain effects.
- Concurrent edit and edit/delete conflicts preserve both branches.
- Local-save and remote-sync confirmations are visually distinct.
