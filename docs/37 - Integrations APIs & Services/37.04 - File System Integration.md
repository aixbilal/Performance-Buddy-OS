# File System Integration

## Boundary

Filesystem integration uses explicit user-selected files or roots and a privileged allowlisted adapter. Every access canonicalizes the path and verifies it remains inside the approved scope.

## Safety

Reject traversal, symlink/junction escape, alternate streams where applicable, device paths, unsupported extensions, and size-policy violations. Do not execute imported files, scripts, macros, embedded commands, or active content. Logs use redacted paths or stable IDs and exclude file content.

## Reading and watching

Reads record identity, size, modification marker, encoding, checksum where useful, and provenance. Bounded retries handle transient locks. Watchers are hints: reconciliation scans detect overflow, missed events, rename, external edit, deletion, permission loss, and removable-drive changes.

## Writing

Read-only is the default. Any approved write requires explicit scope, exact preview, compare-before-write, conflict detection, same-directory atomic replacement where supported, encoding preservation, backup/recovery, and audit trail.

## Acceptance criteria

- Security tests cover traversal and link escape on supported platforms.
- Concurrent external edits are never silently overwritten.
- Permission loss stops access without broadening scope or deleting sources.
