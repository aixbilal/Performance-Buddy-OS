# Calendar Integration

## Scope

Calendar integration may import selected calendars and, if separately approved, publish selected commitments. It is optional and cannot replace the canonical plan, academic source records, or user approval.

## Mapping

An external event retains provider/calendar IDs, recurrence identity, title and permitted details, start/end/timezone, all-day status, location, attendees only if authorized, source revision/etag, retrieval time, privacy, and provenance. Raw and normalized values remain linked.

## Authority and conflicts

Imported events are external commitments or candidates according to configured source class. Calendar changes do not prove university authority. Recurrence exceptions, cancellation, timezone changes, duplicates, and local edits are preserved. Bidirectional write requires explicit field ownership, compare-before-write, idempotency, conflict preview, and undo/recovery.

## Offline behavior

Cached verified events remain viewable with as-of status. Local plan work continues offline; outbound changes queue only when permitted. Staleness is visible.

`RESEARCH REQUIRED`: providers, authentication, webhook/poll strategy, mapping, and whether write-back is supported.

## Acceptance criteria

- Timezone, recurrence, cancellation, duplicate, and stale-cache tests pass.
- Calendar data cannot silently overwrite protected commitments.
- Disconnecting a provider does not erase unrelated local plans.
