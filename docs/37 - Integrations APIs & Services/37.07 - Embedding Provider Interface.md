# Embedding Provider Interface

## Purpose

The embedding interface creates versioned vector projections for permitted content without treating similarity as truth or allowing an index to outrank its source.

## Contract

Adapters declare model and revision, locality/provider/region, dimensions, token and batch limits, supported inputs, normalization, rate/cost limits, retention policy, and deterministic expectations. Requests include stable source/chunk IDs, exact source revisions, minimized permitted text, purpose, data zone, model target, and idempotency key.

Stored projections retain embedding model/adapter versions, input hash, chunker/parser versions, source revision, created time, permission scope, and invalidation status. Vectors are disposable and rebuildable; they do not duplicate unrestricted source text.

Local embeddings are `LOCAL`. Remote embeddings are optional `CLOUD`, require scoped consent, and never receive local-only or revoked content. Model or chunking changes create a new index generation and controlled rebuild.

## Acceptance criteria

- Corrected, deleted, or permission-revoked sources invalidate dependent vectors.
- Mixed model generations cannot be queried as one comparable space accidentally.
- Retrieval results cite the authorized source rather than the vector record.
