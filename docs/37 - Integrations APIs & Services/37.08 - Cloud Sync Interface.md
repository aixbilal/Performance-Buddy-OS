# Cloud Sync Interface

## Scope

The cloud sync interface is a `CLOUD` transport boundary implementing Phase 34. It does not become semantic authority and is never required for local CORE commits.

## Operations

The port supports device registration and revocation, capability/schema negotiation, idempotent push, durable acknowledgement, incremental pull by cursor, resnapshot, conflict transport, tombstones, health, quota, and account deletion/export status.

Change envelopes carry stable operation and entity IDs, base/result revisions, origin device/installation, causal or logical ordering, schema/protocol versions, operation kind, payload hash, permission/consent context, and processing state. Authentication and encryption are mandatory; provider fields stay inside the adapter.

## Failure semantics

Normalized outcomes distinguish transient network/provider failure, authentication, authorization, revocation, quota/rate limit, incompatible version, integrity failure, cursor invalidation, partial acknowledgement, and conflict. No response marks data synchronized without verified durability.

## Acceptance criteria

- Replay, reorder, interruption, partial batch, and duplicate-delivery tests converge safely.
- Concurrent revisions and tombstones remain recoverable.
- Replacing the provider does not change canonical entity meaning.
