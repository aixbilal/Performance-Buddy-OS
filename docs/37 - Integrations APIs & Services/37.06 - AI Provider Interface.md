# AI Provider Interface

## Purpose

The AI provider interface normalizes local and remote model execution while preserving Phase 24 architecture and Phase 30 governance.

## Capability declaration

Adapters declare provider/model identity and revision, locality and region, modalities, context/output limits, structured-output guarantees, tool calling, streaming, retention/training controls, safety signals, cost metadata, and rate-limit semantics. Unsupported capability fails clearly or uses an approved disclosed fallback.

## Request and response

Requests contain a run ID, AI application and prompt versions, authorized minimized context references, tools, schema, parameters, timeout, cancellation, and data-zone policy. Responses normalize content, structured data, tool calls, usage, finish reason, safety signals, latency, and provider errors.

Secrets stay in a credential boundary. Provider-specific fields terminate at the adapter. Output is untrusted until schema, citation, permission, deterministic-rule, and approval validation. Retries never duplicate tool side effects.

## Acceptance criteria

- Contract tests run against every adapter and a deterministic fake.
- Provider switching cannot change write authority or approval rules.
- Run records reproduce the disclosed provider/model/adapter context.
