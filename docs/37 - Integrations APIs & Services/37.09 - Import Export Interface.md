# Import Export Interface

## Purpose

Import/export provides portable, reviewable movement of user data without bypassing canonical schemas, provenance, privacy, or migration rules.

## Import pipeline

Detect declared format and version; enforce size/type limits; parse in isolation; validate structure; map raw to normalized fields; create provenance; preview counts, warnings, duplicates, conflicts, and unsupported values; obtain confirmation; apply through domain commands transactionally; and produce a result report. Partial import uses explicit atomicity boundaries.

Unknown, missing, zero, pending, and deleted values remain distinct. Imported IDs never overwrite local identities without an approved mapping. Re-import uses source IDs/checksums and idempotency rules.

## Export pipeline

The user selects scope, format, time range, attachments, privacy redaction, and encryption. Exports include schema/version manifests, checksums, provenance where allowed, and clear exclusions. Secrets, credentials, and prohibited derivatives are never exported by default.

## Acceptance criteria

- Round-trip tests preserve supported meaning, IDs, revisions, and timestamps.
- Malformed or hostile input cannot partially corrupt canonical data.
- Export remains available without a cloud provider.
