## Product / UX Intent

Connect project progress, skill progress, knowledge and actions without collapsing them into one measure. Technical capability should distinguish knowledge, practice and evidence.

## Implementation Guidance

Implement projects, skills, knowledge links and actions as separate linked models. Progress claims should cite evidence. AI-assisted output may contribute to a project but must not automatically count as independent skill mastery; preserve provenance and the user’s actual contribution.

## What Is Locked

- Separation of project progress, skill progress, knowledge and actions.
- Capability distinction between knowledge, practice and evidence.
- Approved references and locked Design System tokens guide V1.

## What Is NOT Permanently Locked

Exact roadmap visualization, sample metrics, layout, labels, icons and decorative styling may evolve in final redesign.

## Source-of-Truth Rules

Documentation defines development entities and evidence rules; the Design System defines global tokens; these assets provide visual/UX reference; source code implements. Generated screenshots cannot override requirements.

## Naming / Versioning

Preserve current filenames. New work follows `Working → Review → Approved → Implementation`; superseded approved assets move to `Archive`. Prefer `PBOS-Development-[Screen]-v#-REFERENCE.png` or `...-PRIMARY.png`.

## Notes for Future Design

Test evidence clarity, assisted-work attribution, project/skill navigation and roadmap scalability using realistic development histories.
